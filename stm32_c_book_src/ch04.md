## 4.1 What a Hardware Timer Does

A timer is a counter driven by a clock that runs **independently of the CPU**. Software configures it, then the hardware counts, compares and generates events with exact timing - no jitter from the code running elsewhere.

The F446RE has general-purpose timers (TIM2-TIM5, TIM9-14), basic timers (TIM6, TIM7), and advanced timers (TIM1, TIM8). Capabilities vary:

| Timer | Counter | Typical use |
|---|---|---|
| TIM6, TIM7 | 16-bit | Pure time base, DAC trigger |
| TIM2, TIM5 | **32-bit** | Long intervals, microsecond timestamps, input capture |
| TIM3, TIM4 | 16-bit | PWM, encoder, input capture |
| TIM1, TIM8 | 16-bit, advanced | Complementary PWM with dead-time for motor bridges |

The heart of every timer is three registers:

- **PSC** - prescaler: divides the timer clock. The counter clock is `f_timer / (PSC + 1)`.
- **ARR** - auto-reload: the counter counts 0 → ARR then overflows (the **update event**).
- **CNT** - the live counter value.

```text Update frequency formula
f_update = f_timer_clock / ((PSC + 1) * (ARR + 1))

Example: f_timer_clock = 90 MHz, want 1 kHz
         PSC = 8999 -> counter clock 10 kHz
         ARR = 9    -> 10 kHz / 10 = 1 kHz
```

> [hw] Timer clock on APB1 | With HCLK = 180 MHz, APB1 = 45 MHz. When an APB prescaler is not 1 the timers get **2×** the bus clock, so TIM2-TIM7 run at **90 MHz** and APB2 timers (TIM1, TIM8, TIM9-11) at **180 MHz**. Always read the real value from the CubeMX clock tree instead of assuming.

## 4.2 Periodic Interrupts and Accurate Delays

```c 1 kHz timer interrupt with TIM6 (CubeMX: Activated, PSC=8999, ARR=9)
/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim6);
/* USER CODE END 2 */

/* USER CODE BEGIN 4 */
volatile uint32_t ms_ticks;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM6) {
    ms_ticks++;
  }
  /* HAL's own tick (TIM-based time base) also arrives here - keep the check */
}
/* USER CODE END 4 */
```

### Microsecond delays with a free-running timer

```c 32-bit TIM5 as a microsecond clock (PSC = 89 -> 1 MHz, ARR = 0xFFFFFFFF)
HAL_TIM_Base_Start(&htim5);

static inline uint32_t micros(void) { return __HAL_TIM_GET_COUNTER(&htim5); }

void delay_us(uint32_t us)
{
  uint32_t start = micros();
  while ((micros() - start) < us) { }        /* wrap-safe subtraction */
}
```

## 4.3 PWM: Analog Control from a Digital Pin

**Pulse Width Modulation** switches a pin on and off quickly; the **duty cycle** (fraction of time high) sets the average power. The timer does it in hardware: the output is high while `CNT < CCR` and low afterwards.

| Parameter | Register | Formula |
|---|---|---|
| Frequency | PSC, ARR | `f_pwm = f_timer / ((PSC+1)(ARR+1))` |
| Duty cycle | CCRx | `duty = CCR / (ARR + 1)` |
| Resolution | ARR | `ARR + 1` steps |

Design example: LED dimming at 1 kHz with 0.1 % resolution. With `f_timer = 90 MHz`, choose `PSC = 89` (1 MHz counter) and `ARR = 999` → 1 kHz, 1000 steps. Setting `CCR = 250` yields 25 % duty.

```c PWM on TIM3 channel 1 (PA6, AF2) - CubeMX: PWM Generation CH1
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
/* USER CODE END 2 */

void set_brightness_percent(uint8_t pct)
{
  uint32_t arr = __HAL_TIM_GET_AUTORELOAD(&htim3);
  __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, (arr + 1) * pct / 100);
}
```

> [tip] Choose the PWM frequency for the load | LEDs: 500 Hz-20 kHz (no visible flicker). Small DC motors: 10-25 kHz (above hearing). Hobby servos: **exactly 50 Hz** with a 1-2 ms pulse. Mismatching frequency and load causes whine, heating or jitter.

### Servo example: 50 Hz, 1-2 ms pulse

```c Servo pulse width with 1 MHz counter (PSC = 89, ARR = 19999)
/* 1 count = 1 microsecond, period = 20 ms */
void servo_set_us(uint16_t us)                     /* 1000..2000 */
{
  if (us < 1000) us = 1000;
  if (us > 2000) us = 2000;
  __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, us); /* TIM3_CH2 on PA7 */
}
```

## 4.4 Input Capture: Measuring Time and Frequency

In input capture mode the timer latches `CNT` into `CCRx` on a pin edge. The difference between two captures is the period.

```c Frequency measurement with input capture (TIM2 CH1, PA0, 1 MHz counter)
volatile uint32_t period_us;

void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
  static uint32_t prev;
  if (htim->Instance == TIM2 && htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1) {
    uint32_t cur = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1);
    period_us = cur - prev;          /* unsigned subtraction handles wrap */
    prev = cur;
  }
}
/* start with: HAL_TIM_IC_Start_IT(&htim2, TIM_CHANNEL_1); */
```

The same technique reads the echo pulse of an HC-SR04 ultrasonic sensor (distance in cm = pulse µs / 58) or a tachometer.

## 4.5 The ADC: Measuring Voltage

The F446 has three 12-bit successive-approximation ADCs. A conversion maps the input voltage between 0 and **VREF+** (3.3 V on the Nucleo) onto a count from 0 to 4095.

```text Converting counts to voltage
V_in = raw * V_ref / 4095         (12-bit)
LSB  = 3.3 V / 4096 = 0.806 mV

raw = 2048  ->  V_in = 1.65 V
```

Key settings:

| Setting | Meaning |
|---|---|
| Resolution | 12, 10, 8 or 6 bits - fewer bits convert faster |
| **Sampling time** | Cycles the sample capacitor charges. Longer for high-impedance sources (> 10 kΩ) |
| Scan mode | Convert several channels in sequence |
| Continuous mode | Restart automatically after each conversion |
| Trigger | Software, or external (timer) for precise sample spacing |
| Data alignment | Right (default) or left |

> [warn] Source impedance | A 100 kΩ sensor driving the ADC directly with a short sampling time reads low and cross-talks between channels. Use a buffer (op-amp) or choose the longest sampling time (480 cycles) and add a 100 nF capacitor at the pin.

```c Polling a single ADC channel (PA0 = ADC1_IN0)
uint16_t adc_read(void)
{
  HAL_ADC_Start(&hadc1);
  if (HAL_ADC_PollForConversion(&hadc1, 10) == HAL_OK) {
    return (uint16_t)HAL_ADC_GetValue(&hadc1);
  }
  return 0xFFFF;                          /* error marker */
}

float adc_to_volts(uint16_t raw) { return raw * 3.3f / 4095.0f; }
```

### Averaging and filtering

Noise of a few counts is normal. Average several samples or use an exponential filter:

```c Moving average and exponential filter
/* exponential moving average, alpha = 1/8, integer-only */
static uint32_t filt;
filt += ((int32_t)raw - (int32_t)filt) / 8;

/* oversample 16x for roughly +2 effective bits */
uint32_t acc = 0;
for (int i = 0; i < 16; i++) acc += adc_read();
uint16_t avg = acc / 16;
```

### Internal temperature sensor and VREFINT

Channel 18 (temperature) and channel 17 (VREFINT, ≈ 1.21 V) are inside the chip. On the F4: `T(°C) = ((V_sense − 0.76 V) / 0.0025 V/°C) + 25`. The temperature sensor is only accurate to a few degrees - good for self-monitoring, not for measurements. Measuring VREFINT lets you compute the real supply voltage when running from a battery.

## 4.6 Triggering the ADC with a Timer

For signal sampling you need **evenly spaced** samples. Software polling jitters; instead have a timer's update event start each conversion. Set *ADC → External Trigger Source = Timer 3 Trigger Out*, TIM3 *Trigger Event Selection = Update Event*, and run the ADC with DMA (next chapter) so results land in a buffer without CPU involvement.

```c Fixed 10 kHz sampling using a timer trigger
/* TIM3: PSC = 89, ARR = 99 -> 10 kHz TRGO on update */
HAL_TIM_Base_Start(&htim3);
HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, ADC_BUF_LEN);   /* see Chapter 5 */
```

## 4.7 Hands-On Lab 4: Potentiometer-Controlled PWM

Wire a 10 kΩ potentiometer: ends to 3V3 and GND, wiper to **PA0**. Connect an LED with 330 Ω in series to **PA6** (TIM3_CH1). Rotating the knob must smoothly dim the LED, and UART should print the voltage twice a second.

```c Lab 4 - ADC to PWM with filtering
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
/* USER CODE END 2 */

/* USER CODE BEGIN 3 */
static uint32_t filt = 0, last_print = 0;

filt += ((int32_t)adc_read() - (int32_t)filt) / 8;           /* smooth */

uint32_t arr = __HAL_TIM_GET_AUTORELOAD(&htim3);
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, (arr + 1) * filt / 4096);

if (HAL_GetTick() - last_print >= 500) {
  last_print = HAL_GetTick();
  printf("raw=%lu  V=%.3f\r\n", (unsigned long)filt, filt * 3.3f / 4095.0f);
}
/* USER CODE END 3 */
```

> [tip] Printing floats | Newlib-nano excludes float support from `printf` by default. Enable *Project → Properties → C/C++ Build → Settings → MCU Settings → Use float with printf from newlib-nano*, or print integers (millivolts) instead. Retargeting `printf` is explained in Chapter 5.
