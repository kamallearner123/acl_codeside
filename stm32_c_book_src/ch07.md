## 7.1 Interfacing Sensors: A Method

Whatever the sensor, the workflow is the same, and following it saves hours:

1. **Read the datasheet's interface section** - bus, address, voltage, maximum clock.
2. **Check the chip ID** register first. A correct ID proves wiring, address and bus timing in one step.
3. **Configure** (sample rate, resolution, power mode) and verify by reading the register back.
4. **Read raw values**, then convert using the datasheet formulas and calibration data.
5. **Validate** against a reference (a second thermometer, gravity on the accelerometer) and handle errors.

| Sensor type | Examples | Interface | Notes |
|---|---|---|---|
| Environment | BME280, SHT31 | I2C / SPI | Temperature, humidity, pressure; factory calibration constants |
| Motion | MPU6050, LSM6DS3 | I2C / SPI | Accelerometer + gyro, need orientation maths and filtering |
| Analog | NTC thermistor, LDR, current shunt | ADC | You supply the signal conditioning |
| Distance | HC-SR04, VL53L0X | Timer capture / I2C | Ultrasonic uses input capture (Chapter 4) |
| Digital 1-wire | DS18B20 | GPIO + timer | Needs microsecond timing |

## 7.2 BME280 over I2C

The Bosch BME280 reports temperature, pressure and humidity. Its raw values are meaningless without the **calibration coefficients** stored in the chip; Bosch publishes the compensation formulas. The temperature path shows the whole technique:

```c BME280 temperature in 0.01 degC (datasheet integer compensation)
static uint16_t T1;  static int16_t T2, T3;
static int32_t  t_fine;

int bme_init(void)
{
  uint8_t id, cal[6];
  if (reg_read(0xD0, &id, 1) != HAL_OK || id != 0x60) return -1;   /* chip id */

  reg_read(0x88, cal, 6);                                          /* calibration */
  T1 = (uint16_t)(cal[1] << 8 | cal[0]);
  T2 = (int16_t) (cal[3] << 8 | cal[2]);
  T3 = (int16_t) (cal[5] << 8 | cal[4]);

  reg_write(0xF2, 0x01);          /* humidity oversampling x1  */
  reg_write(0xF4, 0x27);          /* temp x1, press x1, normal mode */
  reg_write(0xF5, 0xA0);          /* standby 1000 ms, filter off    */
  return 0;
}

int32_t bme_read_temp_centi(void)
{
  uint8_t d[8];
  reg_read(0xF7, d, 8);                                    /* press, temp, hum */
  int32_t adc_T = (int32_t)d[3] << 12 | (int32_t)d[4] << 4 | d[5] >> 4;

  int32_t v1 = (((adc_T >> 3) - ((int32_t)T1 << 1)) * T2) >> 11;
  int32_t v2 = (((((adc_T >> 4) - (int32_t)T1) * ((adc_T >> 4) - (int32_t)T1)) >> 12) * T3) >> 14;
  t_fine = v1 + v2;
  return (t_fine * 5 + 128) >> 8;                          /* 2534 = 25.34 degC */
}
```

For pressure and humidity, use the compensation code from Bosch's open-source **BME280 sensor API** (BSD-3 licence) rather than retyping long formulas - plug in your `reg_read`/`reg_write` as its platform functions.

> [tip] Integers beat floats | Returning centi-degrees as `int32_t` avoids float `printf` and keeps results deterministic. Convert to a string only at the display or console edge: `printf("%ld.%02ld C", t / 100, t % 100)`.

## 7.3 MPU6050 Accelerometer and Gyroscope

The MPU6050 (I2C address `0x68`, or `0x69` if AD0 is high) starts in sleep mode. Write 0 to `PWR_MGMT_1` (0x6B) to wake it, then burst-read 14 bytes from `0x3B`: accel X/Y/Z, temperature, gyro X/Y/Z (each 16-bit big-endian, signed).

```c Read acceleration in milli-g
#define MPU_ADDR (0x68 << 1)

int mpu_init(void)
{
  uint8_t who, zero = 0;
  HAL_I2C_Mem_Read(&hi2c1, MPU_ADDR, 0x75, 1, &who, 1, 50);        /* WHO_AM_I */
  if (who != 0x68) return -1;
  HAL_I2C_Mem_Write(&hi2c1, MPU_ADDR, 0x6B, 1, &zero, 1, 50);      /* wake up  */
  return 0;
}

void mpu_read_mg(int32_t *ax, int32_t *ay, int32_t *az)
{
  uint8_t d[14];
  HAL_I2C_Mem_Read(&hi2c1, MPU_ADDR, 0x3B, 1, d, 14, 50);
  int16_t x = (int16_t)(d[0] << 8 | d[1]);
  int16_t y = (int16_t)(d[2] << 8 | d[3]);
  int16_t z = (int16_t)(d[4] << 8 | d[5]);
  /* default range +/-2 g -> 16384 LSB per g */
  *ax = x * 1000L / 16384;  *ay = y * 1000L / 16384;  *az = z * 1000L / 16384;
}
```

A board lying flat should read about (0, 0, +1000) mg. If not, check the axis orientation and the range setting. Raw gyro/accel data is noisy and drifts; **fuse** them (complementary or Madgwick filter) to estimate tilt.

```c Tilt angle with a complementary filter (call at fixed dt)
/* angle_deg: previous estimate; gyro_dps: rate; acc_angle: from atan2f(ax, az) */
angle_deg = 0.98f * (angle_deg + gyro_dps * dt) + 0.02f * acc_angle;
```

## 7.4 Analog Sensors: NTC Thermistor

An NTC in a divider with a 10 kΩ resistor gives a voltage that falls as temperature rises. Convert voltage → resistance → temperature with the beta equation:

```c Thermistor temperature (10k NTC, beta 3950, divider to 3.3 V)
#include <math.h>

float ntc_temp_c(uint16_t raw)
{
  float r = 10000.0f * raw / (4095.0f - raw);            /* thermistor on low side */
  float inv_t = 1.0f / 298.15f + logf(r / 10000.0f) / 3950.0f;
  return 1.0f / inv_t - 273.15f;
}
```

## 7.5 Displays

| Display | Interface | Resolution | Remarks |
|---|---|---|---|
| 16×2 HD44780 character LCD | 4/8-bit parallel (or I2C backpack) | 16 chars × 2 | Simple text; needs 5 V on many modules |
| **SSD1306 OLED** | I2C or SPI | 128×64 / 128×32 mono | Cheap, sharp, low power - our choice |
| ST7735 / ILI9341 TFT | SPI | 128×160 … 320×240 colour | Needs DMA for smooth refresh |
| 7-segment (TM1637, MAX7219) | 2-wire / SPI | digits | Counters and clocks |

### SSD1306 over I2C (address 0x3C)

The controller keeps a 128×64 bit image: 8 "pages" of 128 bytes; each byte is a vertical strip of 8 pixels. The usual technique is a **frame buffer** in RAM (1024 bytes): draw into it with simple functions, then send the whole buffer in one I2C transfer.

```c SSD1306 minimal driver
#define OLED_ADDR (0x3C << 1)
static uint8_t fb[128 * 8];

static void oled_cmd(uint8_t c) { HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x00, 1, &c, 1, 50); }  /* 0x00 = command */

void oled_init(void)
{
  static const uint8_t seq[] = {
    0xAE, 0xD5, 0x80, 0xA8, 0x3F, 0xD3, 0x00, 0x40, 0x8D, 0x14, 0x20, 0x00,
    0xA1, 0xC8, 0xDA, 0x12, 0x81, 0xCF, 0xD9, 0xF1, 0xDB, 0x40, 0xA4, 0xA6, 0xAF };
  for (unsigned i = 0; i < sizeof seq; i++) oled_cmd(seq[i]);
}

void oled_pixel(int x, int y, int on)
{
  if ((unsigned)x >= 128 || (unsigned)y >= 64) return;       /* clip */
  if (on) fb[x + (y / 8) * 128] |=  (1u << (y % 8));
  else    fb[x + (y / 8) * 128] &= ~(1u << (y % 8));
}

void oled_update(void)
{
  oled_cmd(0x21); oled_cmd(0); oled_cmd(127);                 /* column range */
  oled_cmd(0x22); oled_cmd(0); oled_cmd(7);                   /* page range   */
  HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x40, 1, fb, sizeof fb, 100);   /* 0x40 = data */
}
```

Text needs a font table (5×7 or 8×8 bitmap, 1 KB of `const` data in Flash). Open-source drivers such as *stm32-ssd1306* provide fonts, lines and bitmaps - reading one after writing the minimal driver above is an excellent exercise.

> [tip] Update only when needed | At 400 kHz a full 1024-byte transfer takes roughly 25 ms. Refresh when data changes (or at 5-10 Hz), not on every loop iteration, and use `HAL_I2C_Mem_Write_DMA` if the CPU must stay free.

## 7.6 Actuators: Servos

A hobby servo contains a motor, gearbox, position sensor and controller. You give it a **50 Hz PWM signal**; the pulse width sets the angle: about 1.0 ms = 0°, 1.5 ms = 90°, 2.0 ms = 180° (ranges vary, calibrate yours). Wiring: brown/black = GND, red = **external 5 V**, orange/yellow = signal from the STM32 (PA7, TIM3_CH2).

> [warn] Never power motors from the board's 3V3 pin | A servo can draw an ampere when it starts or stalls, which resets the MCU. Use a separate 5 V supply and **connect its ground to the Nucleo's ground**.

```c Smooth servo motion
void servo_move(uint16_t from_us, uint16_t to_us, uint16_t step_us, uint16_t delay_ms)
{
  if (from_us < to_us) for (uint16_t p = from_us; p <= to_us; p += step_us) { servo_set_us(p); HAL_Delay(delay_ms); }
  else                 for (int32_t p = from_us; p >= to_us; p -= step_us) { servo_set_us(p); HAL_Delay(delay_ms); }
}
```

## 7.7 Actuators: DC Motors with an H-Bridge

A GPIO pin can supply about 20 mA; a small motor needs hundreds of mA. Use a **motor driver** (TB6612FNG, DRV8833, L298N) - an H-bridge that takes logic inputs and switches motor power. Two direction inputs plus a PWM input control one motor:

| IN1 | IN2 | PWM | Motor |
|---|---|---|---|
| 1 | 0 | duty | Forward at duty speed |
| 0 | 1 | duty | Reverse |
| 0 | 0 | any | Coast (free-spin) |
| 1 | 1 | any | Brake |

```c TB6612 motor channel A: PWM on TIM4_CH1 (PB6), IN1 = PC0, IN2 = PC1
void motor_set(int8_t speed_pct)                    /* -100 .. +100 */
{
  if (speed_pct > 100)  speed_pct = 100;
  if (speed_pct < -100) speed_pct = -100;

  HAL_GPIO_WritePin(IN1_GPIO_Port, IN1_Pin, speed_pct > 0 ? GPIO_PIN_SET : GPIO_PIN_RESET);
  HAL_GPIO_WritePin(IN2_GPIO_Port, IN2_Pin, speed_pct < 0 ? GPIO_PIN_SET : GPIO_PIN_RESET);

  uint32_t mag = speed_pct < 0 ? -speed_pct : speed_pct;
  uint32_t arr = __HAL_TIM_GET_AUTORELOAD(&htim4);
  __HAL_TIM_SET_COMPARE(&htim4, TIM_CHANNEL_1, (arr + 1) * mag / 100);
}
```

Good-practice checklist for motors:

- Separate motor supply (VM), **common ground** with the MCU, and a bulk capacitor (100-470 µF) near the driver.
- PWM at **10-25 kHz** to stay above audible range.
- **Ramp** speed changes - sudden reversals draw large currents and stress gears.
- Never reverse direction without first braking/coasting for a few milliseconds (avoid shoot-through on discrete bridges).
- For closed-loop speed or position control, add an **encoder** (timer in encoder mode) and a PI controller.

## 7.8 Actuators: Stepper Motors

A stepper moves in fixed angular increments by energising coils in sequence. The common 28BYJ-48 with a ULN2003 board (5 V) needs four GPIOs and an 8-state half-step sequence:

```c Half-step sequence for 28BYJ-48 (pins PC4..PC7 -> IN1..IN4)
static const uint8_t seq[8] = { 0x1, 0x3, 0x2, 0x6, 0x4, 0xC, 0x8, 0x9 };
static uint8_t idx;

void stepper_step(int dir)                          /* +1 or -1 */
{
  idx = (idx + 8 + dir) & 7;
  GPIOC->ODR = (GPIOC->ODR & ~(0xFUL << 4)) | ((uint32_t)seq[idx] << 4);
}
/* call from a timer interrupt every 2 ms -> about 1 rev per 8 s at 4096 half-steps/rev */
```

For stronger NEMA motors use a **step/direction driver** (A4988, DRV8825, TMC2209): one GPIO for DIR and a timer generating STEP pulses. Pulse rate = speed, so smooth acceleration ramps are just changing ARR over time.

> [warn] Step pulses belong to a timer | Generating steps with `HAL_Delay()` makes motors stutter and lose steps. Use a timer interrupt or PWM output so timing does not depend on other code.
