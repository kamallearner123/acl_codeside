SVC and PendSV

A vendor-neutral look at SVC/PendSV, with the STM32F446 as a worked example.

⏱️ Reading Time: 30 minutes
🛠️ Lab: Lab 20
🎯 Topics: SVC and PendSV

20.1 Two Exceptions for the OS

SVC and PendSV are exceptions designed for operating systems. Together they allow safe system calls and context switching without race conditions.

20.2 SVC: Supervisor Call

The SVC #n instruction deliberately raises the SVCall exception. Unprivileged code uses it to request privileged services, such as starting the scheduler or calling a kernel function.

C Reading the SVC number 
__attribute__((naked)) void SVC_Handler(void) {
    __asm volatile(
        "TST  LR, #4        \n"   /* which stack was in use? */
        "ITE  EQ            \n"
        "MRSEQ R0, MSP      \n"
        "MRSNE R0, PSP      \n"
        "B    svc_c          \n");
}
void svc_c(uint32_t *frame) {
    uint8_t *pc = (uint8_t *)frame[6];      /* stacked PC */
    uint8_t num = pc[-2];                   /* immediate in the SVC instruction */
    /* dispatch on num, put result in frame[0] (R0) */
}

The stacked R0-R3 are the arguments and the return value is written back into the frame.

20.3 PendSV: Pended Supervisor Call

PendSV is software-triggered, set by writing SCB->ICSR |= SCB_ICSR_PENDSVSET_Msk. It runs only when no higher-priority exception is active, so it is configured at the lowest priority. An RTOS pends it whenever a context switch is needed and the actual switch is performed when all other work has finished.

20.4 A Context Switch in Outline

ASM PendSV_Handler (simplified) 
    MRS   R0, PSP
    STMDB R0!, {R4-R11}        @ save software-saved registers
    LDR   R1, =current_tcb
    LDR   R2, [R1]
    STR   R0, [R2]             @ save SP into the old task's control block
    BL    pick_next_task       @ select next
    LDR   R2, [R1]
    LDR   R0, [R2]
    LDMIA R0!, {R4-R11}        @ restore the new task's registers
    MSR   PSP, R0
    BX    LR                   @ hardware restores R0-R3, R12, LR, PC, xPSR

The hardware already saved R0-R3, R12, LR, PC, xPSR at exception entry; the handler saves the remaining R4-R11.

20.5 Why a Separate PendSV?

Switching directly inside SysTick could preempt a real interrupt handler and return to a task while an ISR is still pending. PendSV at lowest priority guarantees that all ISRs finish first.

Timer tick SysTick increments the tick
Decide to switch Scheduler pends PendSV
Perform switch PendSV handler
