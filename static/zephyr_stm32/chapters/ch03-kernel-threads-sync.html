Module 03 • Real-Time Core

Zephyr Kernel Architecture & Synchronization

Dive into the heart of Zephyr's real-time engine: cooperative vs preemptive thread scheduling, priority math, synchronization with Semaphores and Mutexes (priority inheritance), inter-thread data communication via Message Queues (k_msgq), and offloading interrupt routines to workqueues.

⏱️ Reading Time: 40 minutes
🛠️ Lab Project: samples/03_kernel_threads_queues
🎯 Core APIs: k_thread, k_sem, k_mutex, k_msgq

3.1 Thread Scheduling & Priority Hierarchy

Zephyr supports a dual-priority scheduling scheme. Priorities in Zephyr are signed integer values ranging from negative to positive numbers:

⚡ Cooperative Threads (Priority < 0)

Values from -CONFIG_NUM_COOP_PRIORITIES up to -1.

Once a cooperative thread starts running, it cannot be preempted by any other thread (even another cooperative thread with higher priority!). It continues running until it voluntarily relinquishes the CPU by calling k_yield(), k_sleep(), or blocking on an IPC object. Used for time-critical, atomic driver routines.

⏳ Preemptive Threads (Priority >= 0)

Values from 0 up to CONFIG_NUM_PREEMPT_PRIORITIES - 1.

Lower numerical values represent higher priority (e.g., priority 2 preempts priority 7). If a higher-priority preemptive thread becomes ready, the Zephyr scheduler immediately context-switches and suspends the lower-priority thread.

3.2 Defining Threads: Static vs Dynamic

Zephyr provides both compile-time static definition macros and runtime dynamic creation:

C Static Thread Definition (Zero Runtime Overhead) 
#include <zephyr/kernel.h>

#define SENSOR_STACK_SIZE 2048
#define SENSOR_PRIORITY   5

/* Forward declaration of thread entry function */
void sensor_thread_entry(void *arg1, void *arg2, void *arg3);

/* Statically allocate stack and initialize thread control block */
K_THREAD_DEFINE(sensor_tid, SENSOR_STACK_SIZE,
                sensor_thread_entry, NULL, NULL, NULL,
                SENSOR_PRIORITY, 0, 0);

void sensor_thread_entry(void *arg1, void *arg2, void *arg3)
{
    while (1) {
        /* Thread logic executed every 500 ms */
        k_msleep(500);
    }
}

3.3 Synchronization: Semaphores vs Mutexes

A common pitfall is treating a binary semaphore as a mutex. In real-time embedded systems on STM32, they serve fundamentally different purposes:

Primitive Primary Purpose Priority Inheritance? Callable from ISR?
k_sem (Semaphore) Signaling / Notification ("Event occurred") ❌ No ✅ Yes (k_sem_give)
k_mutex (Mutex) Mutual Exclusion ("Protect shared resource") ✅ Yes (Prevents Inversion) ❌ No (Cannot block in ISR)
⚠️ The Priority Inversion Disaster

If low-priority thread L holds a shared bus resource, and high-priority thread H needs it, H must wait for L. If medium-priority thread M preempts L, thread H is starved indefinitely by M! Zephyr's k_mutex implements Priority Inheritance: it temporarily elevates L's priority to H's priority until L releases the mutex, ensuring M cannot cause starvation.

3.4 Hands-On Lab 3: Multi-Threaded Sensor Pipeline

In this laboratory exercise (located in samples/03_kernel_threads_queues/), we implement a multi-threaded data pipeline with thread synchronization and safe data exchange.

3.4.1 Architecture Overview & Priority Matrix

In this project, two threads communicate via a lock-free Zephyr Message Queue (k_msgq):

Thread Priority Stack Size Role in Pipeline
Producer Thread 6 (Preemptive) 2048 bytes Gathers telemetry every 1000ms and puts into k_msgq
Consumer Thread 4 (Higher Priority!) 2048 bytes Blocks on k_msgq_get; preempts producer immediately when packet arrives

3.4.3 Application Source Code: src/main.c

Complete source code featuring static thread definitions and message queues:

C samples/03_kernel_threads_queues/src/main.c 
/*
 * Copyright (c) 2026 Apt Computing Labs
 * "Where Knowledge Meets Innovation"
 *
 * Mastering Zephyr RTOS on STM32 - Lab 3: Kernel Multithreading
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/sys/printk.h>

#define STACK_SIZE 2048
#define PRODUCER_PRIORITY 6
#define CONSUMER_PRIORITY 4

/* Structured Telemetry Packet */
struct sensor_data {
    uint32_t timestamp_ms;
    int32_t temperature_c_x10; /* e.g. 245 = 24.5 C */
    int32_t humidity_pct;
    uint32_t sequence_id;
};

/* Define Message Queue: 10 items deep, aligned to 4 bytes */
K_MSGQ_DEFINE(sensor_msgq, sizeof(struct sensor_data), 10, 4);

/* Onboard LED for status indication */
static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

/* Producer Thread Entry */
void producer_thread_entry(void *arg1, void *arg2, void *arg3)
{
    ARG_UNUSED(arg1); ARG_UNUSED(arg2); ARG_UNUSED(arg3);
    uint32_t seq = 0;
    int32_t base_temp = 220; // 22.0 C

    while (1) {
        struct sensor_data reading;
        reading.timestamp_ms = k_uptime_get_32();
        reading.temperature_c_x10 = base_temp + (seq % 15);
        reading.humidity_pct = 45 + (seq % 10);
        reading.sequence_id = ++seq;

        printk("[Producer] Publishing reading #%u (Temp: %d.%d C, Hum: %d%%)\n",
               reading.sequence_id,
               reading.temperature_c_x10 / 10,
               reading.temperature_c_x10 % 10,
               reading.humidity_pct);

        /* Push to queue (wait up to 50ms if full) */
        if (k_msgq_put(&sensor_msgq, &reading, K_MSEC(50)) != 0) {
            printk("[Producer] Warning: Message queue full! Dropping packet.\n");
        }

        k_msleep(1000);
    }
}

/* Consumer Thread Entry */
void consumer_thread_entry(void *arg1, void *arg2, void *arg3)
{
    ARG_UNUSED(arg1); ARG_UNUSED(arg2); ARG_UNUSED(arg3);
    struct sensor_data item;
    int32_t temp_sum = 0;
    uint32_t count = 0;

    while (1) {
        /* Wait forever until a new packet arrives */
        if (k_msgq_get(&sensor_msgq, &item, K_FOREVER) == 0) {
            count++;
            temp_sum += item.temperature_c_x10;
            int32_t avg = temp_sum / count;

            printk("[Consumer] Processed #%u @ %u ms | Avg Temp: %d.%d C\n",
                   item.sequence_id, item.timestamp_ms, avg / 10, avg % 10);

            /* Flash LED to indicate successful consumption */
            gpio_pin_set_dt(&led, 1);
            k_busy_wait(15000); // 15 us pulse
            gpio_pin_set_dt(&led, 0);
        }
    }
}

/* Statically define threads with zero runtime malloc overhead */
K_THREAD_DEFINE(producer_tid, STACK_SIZE, producer_thread_entry,
                NULL, NULL, NULL, PRODUCER_PRIORITY, 0, 0);

K_THREAD_DEFINE(consumer_tid, STACK_SIZE, consumer_thread_entry,
                NULL, NULL, NULL, CONSUMER_PRIORITY, 0, 0);

int main(void)
{
    printk("\n=== Zephyr Kernel Lab 3: Multithreading & Message Queues ===\n");
    gpio_is_ready_dt(&led);
    gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);

    /* Main thread can either perform work or exit into sleep */
    while (1) {
        k_sleep(K_FOREVER);
    }
    return 0;
}
