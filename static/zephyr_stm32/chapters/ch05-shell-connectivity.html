Module 05 • Interactive Systems

Subsystems, Shell & Industrial Protocols

Turn your firmware into a professional interactive diagnostic platform: implement a dynamic Command Line Interface (CLI) using the Zephyr Shell, decouple high-throughput debugging using the Deferred Logging Subsystem, master CAN bus communications (bxCAN / FDCAN), and understand BLE architecture.

⏱️ Reading Time: 30 minutes
🛠️ Lab Project: samples/05_shell_telemetry
🎯 Key Subsystems: Shell, Logging, CAN, BLE

5.1 The Zephyr Shell Subsystem

In embedded engineering, hardcoding print statements and re-flashing to test every tweak is painfully slow. Zephyr includes a powerful UNIX-like Shell subsystem running directly over your UART ST-Link console:

  • Tab Autocompletion: Type ke<TAB> to expand to kernel.
  • Command History: Up/Down arrow keys recall previous commands.
  • Built-in Kernel Commands: kernel threads displays all active thread stacks, CPU utilization, and state. device list inspects every initialized hardware driver.
  • ANSI Color Support: Colored error banners and interactive prompts.
C Registering Custom Shell Commands 
#include <zephyr/shell/shell.h>

/* Handler function for: 'system status' */
static int cmd_status_handler(const struct shell *sh, size_t argc, char **argv)
{
    ARG_UNUSED(argc);
    ARG_UNUSED(argv);

    shell_print(sh, "=== System Telemetry Status ===");
    shell_print(sh, "Uptime: %u ms", k_uptime_get_32());
    shell_print(sh, "Target Board: %s", CONFIG_BOARD);
    return 0;
}

/* Register root command 'system' with subcommand 'status' */
SHELL_STATIC_SUBCMD_SET_CREATE(sub_system,
    SHELL_CMD(status, NULL, "Print system telemetry status.", cmd_status_handler),
    SHELL_SUBCMD_SET_END
);

SHELL_CMD_REGISTER(system, &sub_system, "System diagnostic commands", NULL);

5.2 High-Throughput Deferred Logging

Calling raw printk() inside an interrupt or a fast control loop blocks CPU execution and alters timing (Heisenbugs). Zephyr's Logging Subsystem (CONFIG_LOG=y) operates in Deferred Mode by default:

  1. When you call LOG_INF("Pressure: %d", val);, Zephyr packs the format pointer and arguments into a lightweight lock-free ring buffer in just a few CPU cycles.
  2. The background idle thread or log processing thread formats and transmits the ASCII string to the UART only when the MCU is otherwise idle!

5.3 Industrial CAN Bus (Controller Area Network) on STM32

CAN is the de-facto standard in automotive, robotics, and industrial automation due to its differential noise immunity and hardware collision arbitration.

  • STM32F4 / L4: Feature bxCAN (Basic Extended CAN, up to 1 Mbps, 8-byte payload).
  • STM32G0 / G4 / H7: Feature FDCAN (CAN with Flexible Data-Rate, up to 8 Mbps, 64-byte payload).
C Transmitting a CAN Frame in Zephyr 
#include <zephyr/drivers/can.h>

const struct device *const can_dev = DEVICE_DT_GET(DT_CHOSEN(zephyr_canbus));

struct can_frame frame = {
    .id = 0x123,            /* Standard 11-bit CAN Identifier */
    .dlc = 4,               /* 4 bytes of data */
    .flags = 0,
    .data = { 0xAA, 0xBB, 0xCC, 0xDD }
};

/* Transmit frame onto physical bus (timeout 100ms) */
int ret = can_send(can_dev, &frame, K_MSEC(100), NULL, NULL);
if (ret != 0) {
    LOG_ERR("CAN transmission failed: %d", ret);
}

5.4 Hands-On Lab 5: Interactive Diagnostic Console

In this laboratory exercise (provided in samples/05_shell_telemetry/), we integrate the Zephyr Shell to allow runtime control of board LEDs, query memory statistics, and stream live sensor telemetry on demand.

5.4.1 Project Configuration: prj.conf

KCONFIG samples/05_shell_telemetry/prj.conf 
# Enable Shell subsystem
CONFIG_SHELL=y
CONFIG_SHELL_BACKENDS=y
CONFIG_SHELL_BACKEND_SERIAL=y
CONFIG_SHELL_PROMPT_UART="nucleo:~$ "

# Enable built-in kernel diagnostics
CONFIG_THREAD_NAME=y
CONFIG_THREAD_ANALYZER=y
CONFIG_DEVICE_SHELL=y

# Enable Deferred Logging with Shell backend
CONFIG_LOG=y
CONFIG_LOG_MODE_DEFERRED=y
CONFIG_LOG_BACKEND_SHELL=y
CONFIG_GPIO=y

5.4.2 Application Code: samples/05_shell_telemetry/src/main.c

C samples/05_shell_telemetry/src/main.c 
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/shell/shell.h>
#include <zephyr/logging/log.h>

LOG_MODULE_REGISTER(main_app, LOG_LEVEL_INF);

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

/* Shell Command: 'led on' and 'led off' */
static int cmd_led_on(const struct shell *sh, size_t argc, char **argv)
{
    ARG_UNUSED(argc);
    ARG_UNUSED(argv);
    gpio_pin_set_dt(&led, 1);
    shell_print(sh, "Onboard LED turned ON.");
    return 0;
}

static int cmd_led_off(const struct shell *sh, size_t argc, char **argv)
{
    ARG_UNUSED(argc);
    ARG_UNUSED(argv);
    gpio_pin_set_dt(&led, 0);
    shell_print(sh, "Onboard LED turned OFF.");
    return 0;
}

SHELL_STATIC_SUBCMD_SET_CREATE(sub_led,
    SHELL_CMD(on, NULL, "Turn onboard LED on", cmd_led_on),
    SHELL_CMD(off, NULL, "Turn onboard LED off", cmd_led_off),
    SHELL_SUBCMD_SET_END
);

SHELL_CMD_REGISTER(led, &sub_led, "Control onboard LED state", NULL);

int main(void)
{
    if (!gpio_is_ready_dt(&led)) {
        LOG_ERR("LED port not ready");
        return 0;
    }
    gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);

    LOG_INF("Zephyr Diagnostic Shell ready. Type 'help' or press TAB.");

    while (1) {
        k_sleep(K_FOREVER);
    }
    return 0;
}

5.4.3 Building & Flashing via ST-Link

Compile and flash the interactive shell diagnostic console:

BASH Build and Flash Commands 
# 1. Navigate to directory
cd samples/05_shell_telemetry

# 2. Build for target board:
west build -b nucleo_f401re -p always

# 3. Flash to STM32:
west flash

# 4. Open serial terminal monitor (115200 baud, 8N1):
minicom -D /dev/tty.usbmodem* -b 115200
