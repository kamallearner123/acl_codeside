Module 02 • Hardware Abstraction

DeviceTree (DTS) & Kconfig Deep Dive

Master the two most critical configuration pillars in Zephyr. Learn how the DeviceTree completely decouples hardware pin layouts and register offsets from application code, how to write non-destructive board overlays (.overlay), and how Kconfig selects drivers and kernel capabilities at build time.

⏱️ Reading Time: 35 minutes
🛠️ Lab Project: samples/02_devicetree_overlay
🎯 Key Mastery: DTS Overlays, Aliases & Kconfig

2.1 The Two Pillars: DeviceTree vs Kconfig

A frequent point of confusion for engineers starting with Zephyr is knowing whether a setting belongs in the DeviceTree or in Kconfig. Here is the definitive distinction:

🌿 DeviceTree (DTS)

Describes Hardware Topology

  • What peripherals exist on the SoC (USART1, I2C1, GPIOA)?
  • What base memory addresses and IRQ numbers are they assigned?
  • Which physical pins are routed to external LEDs, buttons, or sensors?
  • What is the default I2C clock speed (100kHz, 400kHz)?

⚙️ Kconfig

Selects Software Features

  • Should the I2C driver be compiled into the binary?
  • What is the main thread stack size (CONFIG_MAIN_STACK_SIZE)?
  • Is the Shell subsystem enabled (CONFIG_SHELL=y)?
  • Should floating-point printing support be included?

2.2 Anatomy of a DeviceTree Source (DTS)

A DeviceTree is a hierarchical tree of nodes. Every node can have properties (key-value pairs) and child nodes. Let's look at the anatomical structure:

DTS Anatomy of a DeviceTree Node 
/dts-v1/;

/ {
    /* Root node properties */
    #address-cells = <1>;
    #size-cells = <1>;
    model = "STMicroelectronics STM32 Nucleo Board";
    compatible = "st,stm32f401re-nucleo";

    /* Aliases provide stable, generic names for application C code */
    aliases {
        led0 = &green_user_led;
        sw0 = &user_button;
    };

    /* Node label for convenient referencing: 'leds' */
    leds {
        compatible = "gpio-leds";
        
        green_user_led: led_0 {
            gpios = <&gpioa 5 GPIO_ACTIVE_HIGH>;
            label = "User LD2";
        };
    };

    soc {
        #address-cells = <1>;
        #size-cells = <1>;
        compatible = "simple-bus";

        /* Label 'usart2' on unit-address 40004400 */
        usart2: serial@40004400 {
            compatible = "st,stm32-usart", "st,stm32-uart";
            reg = <0x40004400 0x400>;
            interrupts = <38 0>;
            status = "okay";
        };
    };
};

Key DeviceTree Elements Explained:

  • Labels (e.g. usart2:, &gpioa): Shorthands used to refer to a node from elsewhere in the tree (called a phandle).
  • compatible: The most crucial property. It links the DeviceTree node to the exact C driver in Zephyr using YAML bindings (e.g. "st,stm32-uart" matches dts/bindings/serial/st,stm32-uart.yaml).
  • reg = <base_address length>: Defines the physical register memory block of the hardware peripheral on the Cortex-M bus.
  • status = "okay" / "disabled": Enables or disables the device. If status is "disabled", Zephyr does not generate driver instances for it, saving Flash and RAM.

2.3 Working with Board Overlays (.overlay)

Never edit the core board files in the Zephyr installation tree! When you attach external hardware to your STM32 Nucleo board (such as an external LED on PB0, a relay on PC1, or a sensor on I2C1), you create an overlay file in your application repository.

Zephyr automatically looks for overlay files in the following order during west build:

  1. app.overlay (applied regardless of target board)
  2. boards/<board_name>.overlay (e.g. boards/nucleo_f401re.overlay)
💡 Non-Destructive Hardware Expansion

An overlay does not rewrite the entire tree; it simply patches or appends to existing nodes. By referencing a node label like &i2c1 { status = "okay"; ... };, you re-open that node and add new sensor child nodes or change pin alternate functions!

2.4.2 The Board Overlay: boards/nucleo_f401re.overlay

DTS samples/02_devicetree_overlay/boards/nucleo_f401re.overlay 
/ {
    aliases {
        ext-led = &ext_led_node;
        ext-button = &ext_btn_node;
    };

    external_io {
        compatible = "gpio-leds";
        
        ext_led_node: ext_led_0 {
            gpios = <&gpiob 0 GPIO_ACTIVE_HIGH>;
            label = "External Warning LED";
        };
    };

    external_keys {
        compatible = "gpio-keys";
        
        ext_btn_node: ext_btn_0 {
            /* Active low with internal pullup: pressed = 0V (logic 1) */
            gpios = <&gpiob 1 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>;
            label = "External Push Button";
        };
    };
};

2.4.4 Application C Code: src/main.c

Complete source code with EXTI edge-triggered interrupt callback registration:

C samples/02_devicetree_overlay/src/main.c 
/*
 * Copyright (c) 2026 Apt Computing Labs
 * "Where Knowledge Meets Innovation"
 *
 * Mastering Zephyr RTOS on STM32 - Lab 2: DTS Overlays
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/sys/printk.h>

/* Retrieve hardware specs from our DTS aliases */
#define EXT_LED_NODE    DT_ALIAS(ext_led)
#define EXT_BTN_NODE    DT_ALIAS(ext_button)

static const struct gpio_dt_spec ext_led = GPIO_DT_SPEC_GET(EXT_LED_NODE, gpios);
static const struct gpio_dt_spec ext_btn = GPIO_DT_SPEC_GET(EXT_BTN_NODE, gpios);

/* Interrupt callback structure */
static struct gpio_callback button_cb_data;

/* Interrupt Service Routine executed when button is pressed */
void button_pressed_handler(const struct device *dev, struct gpio_callback *cb,
                            uint32_t pins)
{
    /* Toggle external LED on button event */
    gpio_pin_toggle_dt(&ext_led);
    printk("[ISR] Button pressed on pin %d! External LED toggled.\n", ext_btn.pin);
}

int main(void)
{
    int ret;

    printk("\n=== Zephyr RTOS Lab 2: DTS Overlays & GPIO Interrupts ===\n");

    /* Validate both GPIO controllers */
    if (!gpio_is_ready_dt(&ext_led) || !gpio_is_ready_dt(&ext_btn)) {
        printk("Error: One or more GPIO peripheral ports not ready!\n");
        return 0;
    }

    /* Configure external LED */
    ret = gpio_pin_configure_dt(&ext_led, GPIO_OUTPUT_INACTIVE);
    if (ret < 0) {
        printk("Failed to configure ext LED: %d\n", ret);
        return 0;
    }

    /* Configure external Button with pullup */
    ret = gpio_pin_configure_dt(&ext_btn, GPIO_INPUT);
    if (ret < 0) {
        printk("Failed to configure ext Button: %d\n", ret);
        return 0;
    }

    /* Configure edge interrupt on falling edge (button pressed) */
    ret = gpio_pin_interrupt_configure_dt(&ext_btn, GPIO_INT_EDGE_TO_ACTIVE);
    if (ret < 0) {
        printk("Failed to configure button interrupt: %d\n", ret);
        return 0;
    }

    /* Register the callback handler */
    gpio_init_callback(&button_cb_data, button_pressed_handler, BIT(ext_btn.pin));
    gpio_add_callback(ext_btn.port, &button_cb_data);

    printk("DeviceTree Overlay configured successfully!\n");
    printk("LED on Port: %s Pin: %d | Button on Port: %s Pin: %d\n",
           ext_led.port->name, ext_led.pin, ext_btn.port->name, ext_btn.pin);
    printk("Press external button to trigger interrupt...\n");

    while (1) {
        k_sleep(K_FOREVER);
    }

    return 0;
}

cd samples/02_devicetree_overlay

west build -b nucleo_f401re -p always

# 3. Flash to STM32:
west flash

minicom -D /dev/tty.usbmodem* -b 115200
