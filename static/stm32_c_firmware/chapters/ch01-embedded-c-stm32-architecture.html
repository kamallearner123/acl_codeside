Chapter 01 • Foundations

Embedded C & STM32 Architecture

Build the C skills that firmware demands - fixed-width types, bit manipulation, volatile, memory-mapped registers - and learn the parts of the STM32 architecture you actually need: Cortex-M core, memory map, buses, clocks and the boot sequence.

⏱️ Reading Time: 40 minutes
🛠️ Lab: Register-level LED blink
🎯 Topics: Embedded C, Memory map, Clocks

1.1 Why C, and Why "Embedded" C Is Different

C is the language of microcontrollers because it maps almost one-to-one onto hardware: you control memory layout, word size and exactly when a register is read or written. A desktop programmer asks "is my algorithm correct?". A firmware engineer also asks "how many bytes does it use, who else touches this variable, and what happens if an interrupt arrives right here?".

The constraints that shape every decision on an STM32F446RE:

Resource Typical value Consequence
Flash 512 KB Code and constants must fit; avoid large libraries and unnecessary printf float support
SRAM 128 KB No unbounded malloc; prefer static buffers sized at compile time
CPU Cortex-M4F @ up to 180 MHz Fast, but not infinite - busy-wait loops waste power and block other work
No OS by default Bare metal You own the main loop, the interrupts and every failure mode
Rule of thumb
If a value can be known at compile time (buffer sizes, pin numbers, baud rates), make it a #define or enum constant. The compiler can then optimise and you avoid run-time surprises.

1.2 Fixed-Width Types and Integer Behaviour

int is 32 bits on Cortex-M but 16 bits on small 8/16-bit parts. Firmware that talks to hardware must say exactly how wide a value is. Always use <stdint.h>.

C Fixed-width types 
#include <stdint.h>
#include <stdbool.h>

uint8_t  byte   = 0xFF;          /* 8-bit  unsigned: 0..255            */
int16_t  temp   = -1234;         /* 16-bit signed: -32768..32767       */
uint32_t ticks  = 0;             /* 32-bit unsigned: wraps after 2^32  */
bool     ready  = false;

uint8_t a = 200, b = 100;
uint8_t sum = a + b;             /* 300 truncated to 8 bits -> 44!     */
uint16_t wide = (uint16_t)a + b; /* promote first -> 300 is correct    */

Three classic traps:

  • Overflow wrap-around: unsigned arithmetic wraps silently. A uint32_t millisecond counter wraps after about 49.7 days - compare times with subtraction (now - start >= timeout), never with >.
  • Signed overflow is undefined behaviour: the compiler may assume it never happens and delete your checks.
  • Integer promotion: uint8_t operands are promoted to int before arithmetic, then truncated on assignment.

1.3 Bit Manipulation - The Everyday Tool

Peripheral registers are bit fields. Setting, clearing, toggling and testing bits is the single most common operation in firmware.

C Bit operations cheat sheet 
#define BIT(n)            (1UL << (n))

reg |=  BIT(5);               /* set bit 5                       */
reg &= ~BIT(5);               /* clear bit 5                     */
reg ^=  BIT(5);               /* toggle bit 5                    */
if (reg & BIT(5)) { }         /* test bit 5                      */

/* Write a multi-bit field: clear it, then set the new value */
#define FIELD_MASK   (0x3UL << 10)          /* bits 11:10 */
reg = (reg & ~FIELD_MASK) | (2UL << 10);    /* field = 0b10 */
Always use 1UL
1 << 31 shifts into the sign bit of a 32-bit int - undefined behaviour. Use 1UL << n (or BIT(n) above) so the shift happens on an unsigned type.

1.4 volatile, const and static

The compiler assumes memory only changes when your code changes it. Hardware and interrupts break that assumption, so you must tell it.

C Why volatile matters 
volatile uint32_t tick;              /* modified in an ISR              */

void SysTick_Handler(void) { tick++; }

void wait_ms(uint32_t ms)
{
    uint32_t start = tick;
    while ((tick - start) < ms) { }  /* without volatile the compiler may
                                        read 'tick' once and loop forever */
}
  • volatile - "this may change behind your back; do not cache or remove accesses". Required for hardware registers and variables shared between an ISR and main.
  • const - read-only data; globals marked const are placed in Flash, saving precious RAM (lookup tables, strings, sine tables).
  • static at file scope - private to the file. static inside a function - keeps its value between calls and lives in RAM, not on the stack.
volatile is not atomic
volatile uint32_t on Cortex-M is read atomically, but tick++ is a read-modify-write and an ISR can fire between the steps. Protect multi-step updates by disabling interrupts briefly or using a single writer.

1.5 Pointers and Memory-Mapped Registers

On the STM32 every peripheral register lives at a fixed address. Writing C that touches them is simply dereferencing a volatile pointer. Below is how GPIOA's output data register is reached without any library:

C Register access with raw pointers 
#define PERIPH_BASE   0x40000000UL
#define AHB1_BASE     (PERIPH_BASE + 0x20000UL)
#define GPIOA_BASE    (AHB1_BASE + 0x0000UL)      /* 0x40020000 */
#define RCC_BASE      (AHB1_BASE + 0x3800UL)      /* 0x40023800 */

#define GPIOA_MODER   (*(volatile uint32_t *)(GPIOA_BASE + 0x00))
#define GPIOA_ODR     (*(volatile uint32_t *)(GPIOA_BASE + 0x14))
#define RCC_AHB1ENR   (*(volatile uint32_t *)(RCC_BASE   + 0x30))

RCC_AHB1ENR |= BIT(0);                 /* enable GPIOA clock            */
GPIOA_MODER &= ~(3UL << (5 * 2));      /* PA5: clear mode bits          */
GPIOA_MODER |=  (1UL << (5 * 2));      /* PA5: 01 = general purpose out */
GPIOA_ODR   ^=  BIT(5);                /* toggle PA5 (LD2)              */

Real projects use the structures from the CMSIS device header (GPIOA->ODR, RCC->AHB1ENR) - the same idea with named fields. Vendor libraries and HAL are just layers over these registers.

Struct overlays

C How CMSIS models a peripheral 
typedef struct {
    volatile uint32_t MODER;    /* 0x00 */
    volatile uint32_t OTYPER;   /* 0x04 */
    volatile uint32_t OSPEEDR;  /* 0x08 */
    volatile uint32_t PUPDR;    /* 0x0C */
    volatile uint32_t IDR;      /* 0x10 */
    volatile uint32_t ODR;      /* 0x14 */
    volatile uint32_t BSRR;     /* 0x18 */
    /* ... */
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)0x40020000UL)
GPIOA->BSRR = BIT(5);           /* set PA5 atomically */
Prefer BSRR over ODR
Writing BSRR bit n sets pin n, writing bit n+16 resets it. It is a single atomic write, so an interrupt cannot corrupt other pins, unlike ODR |= x (read-modify-write).

1.6 STM32 Family and the Cortex-M4 Core

STM32 is a family of ARM Cortex-M microcontrollers from STMicroelectronics. The part number tells you what you have: STM32 F4 46 R E T6 - family F4 (Cortex-M4, high performance), line 46, 64 pins (R), 512 KB Flash (E), LQFP package (T), industrial temperature (6).

Family Core Typical use
STM32F0 / G0 Cortex-M0 / M0+ Low cost, simple control
STM32F1 / G4 Cortex-M3 / M4 General purpose, motor control (G4)
STM32F4 Cortex-M4F (FPU, DSP) Performance, audio, our reference family
STM32L4 / L5 Cortex-M4 / M33 Ultra-low power
STM32H7 Cortex-M7 Very high performance, graphics

The Cortex-M4F core provides a 3-stage pipeline, a hardware FPU for single-precision float, DSP instructions, the NVIC (interrupt controller), SysTick (system timer) and the debug unit used by SWD. Everything outside the core - GPIO, timers, USARTs - is added by ST as peripherals.

1.7 Memory Map and Bus Matrix

The 4 GB address space is shared by Flash, RAM, peripherals and the core itself:

Region Start address What lives there
Flash 0x0800 0000 Your program, vector table, constants (aliased to 0x0000 0000 at boot)
SRAM1 / SRAM2 0x2000 0000 / 0x2001 C000 .data, .bss, heap, stack (112 KB + 16 KB)
APB1 peripherals 0x4000 0000 TIM2-7, USART2/3, I2C, SPI2/3, CAN, DAC
APB2 peripherals 0x4001 0000 TIM1/8, USART1/6, SPI1, ADCs
AHB1 peripherals 0x4002 0000 GPIOA-H, RCC, DMA1/2
Cortex-M private 0xE000 0000 SysTick, NVIC, SCB, debug (DWT/ITM)

Peripherals hang off buses with different maximum clocks. On the F446 at 180 MHz: AHB 180 MHz, APB2 up to 90 MHz, APB1 up to 45 MHz. Timers on a bus whose prescaler is not 1 receive twice the bus clock - a detail we exploit in Chapter 4.

Clock-gating
Every peripheral is off at reset and its clock must be enabled in RCC before its registers respond. "My GPIO does nothing" is very often "I forgot __HAL_RCC_GPIOA_CLK_ENABLE()".

1.8 Clocks, Reset and the Boot Sequence

After reset the MCU runs from the 16 MHz internal oscillator (HSI). Typical firmware then configures the PLL to reach full speed, using either HSI or an external crystal (HSE). On Nucleo boards the ST-LINK supplies an 8 MHz clock on HSE in bypass mode.

What happens between power-on and main():

  1. The core reads the initial stack pointer from address 0x08000000 and the reset vector from 0x08000004.
  2. It jumps to Reset_Handler in startup_stm32f446xx.s.
  3. The startup code copies .data initial values from Flash to RAM and zeroes .bss.
  4. It calls SystemInit() (FPU enable, vector table offset) and then the C runtime init.
  5. Finally it calls main().
C What static initialisation really means 
int counter = 5;        /* .data : value stored in Flash, copied to RAM at boot */
int zeroed;             /* .bss  : zero-filled by the startup code              */
const int table[] = {1,2,3};  /* .rodata : stays in Flash                       */

int main(void)
{
    int local = 7;      /* stack: gone when function returns */
    ...
}

The linker script (STM32F446RETX_FLASH.ld) tells the linker the Flash and RAM sizes and where to place each section. Open it once and read it; many mysterious "region overflowed" and stack problems become obvious afterwards.

Check memory usage
After every build, the CubeIDE Build Analyzer (or arm-none-eabi-size firmware.elf) shows Flash (text + data) and RAM (data + bss) usage. Watch it grow as you add features.

1.9 Hands-On Lab 1: Register-Level LED Blink

Blink LD2 (PA5) with no HAL: only the register definitions above and a software delay. This lab proves you understand what the HAL will later hide for you.

C Lab 1 - bare register blink (main.c) 
#include "stm32f4xx.h"          /* CMSIS device header, comes with CubeIDE */

static void delay(volatile uint32_t n) { while (n--) { } }

int main(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;           /* clock for GPIOA      */
    GPIOA->MODER &= ~GPIO_MODER_MODER5;            /* clear mode bits      */
    GPIOA->MODER |=  GPIO_MODER_MODER5_0;          /* PA5 output           */

    for (;;) {
        GPIOA->BSRR = GPIO_BSRR_BS5;               /* LED on  */
        delay(2000000);
        GPIOA->BSRR = GPIO_BSRR_BR5;               /* LED off */
        delay(2000000);
    }
}
Compiler optimisation
A delay loop with a non-volatile counter may be removed entirely at -O2. That is why n is volatile above. Real delays use a hardware timer (Chapter 4).
