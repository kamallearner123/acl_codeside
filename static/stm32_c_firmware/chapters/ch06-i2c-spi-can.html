Chapter 06 • Buses

I2C, SPI & CAN Communication

Three buses, three philosophies. Learn addressing and pull-ups on I2C, clock modes and chip-select on SPI, and frames, filters and bit timing on CAN - with working HAL code for each.

⏱️ Reading Time: 60 minutes
🛠️ Lab: Three-bus bring-up
🎯 Topics: I2C, SPI, CAN

6.1 Choosing a Bus

Property I2C SPI CAN
Wires 2 (SDA, SCL) + GND 4+ (SCK, MOSI, MISO, CS per device) 2 (CAN_H, CAN_L) + transceiver
Topology Multi-master/slave, address-based One master, chip-select per slave Multi-master broadcast
Speed 100 kHz, 400 kHz, 1 MHz Up to tens of MHz Up to 1 Mbit/s (classic CAN)
Distance Board level (< 1 m) Board level Up to 40 m at 1 Mbit/s, 1 km at low speed
Typical devices Sensors, EEPROM, RTC, OLED Flash, displays, ADCs, SD cards Vehicles, industrial networks
Robustness Moderate Low (no framing, no error check) Very high (CRC, ACK, arbitration, fault confinement)

6.2 I2C Fundamentals

I2C uses two open-drain lines, SDA (data) and SCL (clock), both pulled up by resistors. A master starts a transaction (START), sends a 7-bit address and a R/W bit, the addressed slave pulls SDA low for an ACK, then bytes follow, each ACKed, until STOP.

  • Pull-ups: typically 4.7 kΩ to 3.3 V at 100/400 kHz. Many breakout boards already carry them - two boards in parallel are fine, but do not stack many.
  • Addresses: the 7-bit address is what datasheets quote (e.g. BME280 = 0x76). HAL wants it shifted left by one: 0x76 << 1 = 0xEC.
  • Speed: Standard 100 kHz, Fast 400 kHz. The slowest device on the bus sets the safe speed.
  • Clock stretching: a slave may hold SCL low to ask the master to wait.
I2C1 on the Nucleo
CubeMX: I2C1 with PB8 = SCL, PB9 = SDA (Arduino connector D15/D14), Fast mode 400 kHz. Add external 4.7 kΩ pull-ups if your sensor board has none. Power sensors from 3V3, not 5 V, unless the board has level shifting.
C Scan the bus for devices 
void i2c_scan(void)
{
  printf("Scanning I2C1...\r\n");
  for (uint8_t addr = 1; addr < 128; addr++) {
    if (HAL_I2C_IsDeviceReady(&hi2c1, addr << 1, 2, 10) == HAL_OK) {
      printf("  found 0x%02X\r\n", addr);
    }
  }
}

Register read/write

Most I2C devices expose registers: write the register address, then read or write data. HAL's Mem functions do exactly this in one call.

C Register access helpers 
#define BME_ADDR  (0x76 << 1)

HAL_StatusTypeDef reg_read(uint8_t reg, uint8_t *buf, uint16_t n)
{
  return HAL_I2C_Mem_Read(&hi2c1, BME_ADDR, reg, I2C_MEMADD_SIZE_8BIT, buf, n, 50);
}

HAL_StatusTypeDef reg_write(uint8_t reg, uint8_t value)
{
  return HAL_I2C_Mem_Write(&hi2c1, BME_ADDR, reg, I2C_MEMADD_SIZE_8BIT, &value, 1, 50);
}

uint8_t id;
if (reg_read(0xD0, &id, 1) == HAL_OK && id == 0x60) {   /* BME280 chip id */
  printf("BME280 detected\r\n");
}

When the bus hangs

If the MCU resets while a slave is mid-byte, the slave may hold SDA low forever and every transaction fails with HAL_BUSY/HAL_ERROR. Recover by switching SCL to a GPIO output and sending up to 9 clock pulses, then a STOP, then re-initialising the I2C peripheral. Check pull-ups and wiring length first - most intermittent faults are electrical.

6.3 SPI Fundamentals

SPI is a synchronous, full-duplex bus: the master drives SCK, sends on MOSI and receives on MISO simultaneously. Each slave has its own CS (chip-select, active low) line; the master pulls it low to start a transaction.

Clock modes

Two settings, CPOL (idle clock level) and CPHA (which edge samples data), define four modes. A slave's datasheet states which it needs; a mismatch gives garbage, not an error.

Mode CPOL CPHA Idle clock Sample edge
0 0 0 Low Rising (first)
1 0 1 Low Falling (second)
2 1 0 High Falling (first)
3 1 1 High Rising (second)
SPI2 wiring
PB13 = SCK, PB14 = MISO, PB15 = MOSI (AF5), and PB12 as a GPIO output for CS. Do not use SPI1 here: its SCK pin (PA5) is the user LED. Set *NSS = Disable* in CubeMX and control CS yourself - it is clearer and works with several slaves.
C Read the JEDEC ID of a W25Qxx flash chip (SPI mode 0) 
#define CS_LOW()   HAL_GPIO_WritePin(SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_RESET)
#define CS_HIGH()  HAL_GPIO_WritePin(SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_SET)

void flash_read_id(uint8_t id[3])
{
  uint8_t cmd = 0x9F;                         /* JEDEC ID command */
  CS_LOW();
  HAL_SPI_Transmit(&hspi2, &cmd, 1, 10);
  HAL_SPI_Receive(&hspi2, id, 3, 10);
  CS_HIGH();
}
/* W25Q128 returns EF 40 18 : manufacturer Winbond, type 0x40, capacity 0x18 */

Use HAL_SPI_TransmitReceive() when a protocol needs simultaneous transfer, such as many ADCs and SD cards. For large buffers (displays, flash pages) use the _DMA variants.

CS discipline
Always raise CS after a transaction, and never share one CS between devices. Keep CS high at start-up (set the initial level in CubeMX) so slaves are not selected while the MCU boots.

Speed

SPI2 sits on APB1 (45 MHz); the baud-rate prescaler divides it: /2 = 22.5 MHz, /4 = 11.25 MHz, /8 = 5.6 MHz. Start slow (/16) during bring-up with long wires, then speed up. Wires above ~30 cm at high speed need care (series resistors, shorter leads).

6.4 CAN Fundamentals

CAN (Controller Area Network) is a differential, multi-master, message-based bus. There are no device addresses: each frame carries an identifier describing *what the data is* ("engine speed"), and every node decides from its filters whether it cares. The identifier also sets priority - lower ID wins arbitration, non-destructively, with no collisions.

Field Classic CAN frame
Identifier 11-bit (standard) or 29-bit (extended)
DLC Data length code, 0-8 bytes
Data Up to 8 bytes
CRC, ACK Added/checked by hardware

Hardware pieces: the STM32 bxCAN controller (CAN1/CAN2 on the F446) talks logic-level CAN_TX/CAN_RX; an external transceiver (SN65HVD230 for 3.3 V, TJA1050 for 5 V) converts these to the differential CAN_H / CAN_L pair. The bus needs 120 Ω termination at each end (60 Ω measured between H and L with power off).

CAN1 pins
Use PA11 = CAN1_RX and PA12 = CAN1_TX (AF9). PB8/PB9 would collide with I2C1 on the Nucleo. In CubeMX also enable the CAN1 RX0 interrupt. For a first test without any transceiver, use Loopback mode: the controller receives its own frames internally.

Bit timing

Every node must agree on the bit rate and sample point. With APB1 = 45 MHz, 500 kbit/s needs 18 time quanta per bit:

TEXT 500 kbit/s timing derivation 
f_APB1 = 45 MHz,  prescaler = 5  ->  f_tq = 9 MHz  (1 tq = 111 ns)
bit time = 18 tq = Sync(1) + BS1(14) + BS2(3)
bit rate = 9 MHz / 18 = 500 kbit/s
sample point = (1 + 14) / 18 = 83.3 %   (target 80-87.5 %)
SJW = 1 tq

Sending a frame

C Start CAN, configure an accept-all filter and send 
CAN_TxHeaderTypeDef txh = { .StdId = 0x123, .IDE = CAN_ID_STD, .RTR = CAN_RTR_DATA, .DLC = 2 };
uint32_t mailbox;

void can_start(void)
{
  CAN_FilterTypeDef f = {0};
  f.FilterBank           = 0;
  f.FilterMode           = CAN_FILTERMODE_IDMASK;
  f.FilterScale          = CAN_FILTERSCALE_32BIT;
  f.FilterIdHigh         = 0;           /* ID = 0 ...                        */
  f.FilterMaskIdHigh     = 0;           /* ... mask = 0 -> accept every frame */
  f.FilterFIFOAssignment = CAN_RX_FIFO0;
  f.FilterActivation     = ENABLE;
  HAL_CAN_ConfigFilter(&hcan1, &f);

  HAL_CAN_Start(&hcan1);
  HAL_CAN_ActivateNotification(&hcan1, CAN_IT_RX_FIFO0_MSG_PENDING);
}

void can_send_temperature(int16_t centi_c)
{
  uint8_t d[2] = { centi_c >> 8, centi_c & 0xFF };
  if (HAL_CAN_AddTxMessage(&hcan1, &txh, d, &mailbox) != HAL_OK) {
    /* all 3 mailboxes busy or bus-off: count and retry later */
  }
}

Receiving with a filter

Filters let hardware discard irrelevant frames so the CPU only sees what it needs. In ID/mask mode, a frame is accepted when (ID & mask) == (filterID & mask). To accept only standard ID 0x123:

C Accept only standard ID 0x123 
f.FilterIdHigh     = 0x123 << 5;      /* 11-bit std ID sits in the top bits of the 32-bit register */
f.FilterIdLow      = 0;
f.FilterMaskIdHigh = 0x7FF << 5;      /* compare all 11 bits */
f.FilterMaskIdLow  = 0;
C Receive in an interrupt callback 
volatile uint8_t  can_rx_flag;
CAN_RxHeaderTypeDef rxh;
uint8_t rxd[8];

void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
  if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rxh, rxd) == HAL_OK) {
    can_rx_flag = 1;                  /* process in main() */
  }
}
A lonely node errors out
A CAN node needs at least one other node that acknowledges its frames. A single board transmitting on a real bus sees ACK errors, retries forever and eventually goes bus-off. Test alone only in loopback mode.

Designing the message set

Allocate IDs by priority and group related data: 0x100 emergency stop (highest priority), 0x200 motor command, 0x300 sensor telemetry. Document every frame (ID, period, byte layout, scaling, endianness) in a table - it is your protocol specification and the only way two engineers' ECUs will interoperate.
