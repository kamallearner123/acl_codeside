## 2.1 Variables, Mutability and Types

Rust variables are **immutable by default**. You opt in to change with `mut`, so the compiler can tell the reader (and itself) which values never change.

```rust Variables and types
let led_count: u8 = 4;          // like uint8_t, immutable
let mut ticks: u32 = 0;         // like uint32_t, mutable
ticks += 1;

const SAMPLE_RATE_HZ: u32 = 1_000;   // compile-time constant, like #define but typed
static BANNER: &str = "boot";        // lives in flash for the whole program
```

| C type | Rust type | Note |
|---|---|---|
| `uint8_t` ... `uint64_t` | `u8` ... `u64` | Same sizes, always |
| `int8_t` ... `int64_t` | `i8` ... `i64` | |
| `size_t` | `usize` | Pointer-sized: 32 bits on Cortex-M |
| `float` / `double` | `f32` / `f64` | Cortex-M4F has a hardware FPU for `f32` only |
| `bool` | `bool` | Only `true` / `false`; an integer is never a bool |
| `char` | `u8` or `char` | Rust `char` is a 4-byte Unicode scalar - use `u8` for bytes |

## 2.2 No Implicit Conversions

C silently converts between integer types. Rust never does, because those conversions hide bugs.

```rust Explicit casts
let raw: u16 = 3071;
let mv = (raw as u32 * 3300) / 4095;     // widen BEFORE multiplying to avoid overflow
let small = mv as u8;                     // `as` truncates silently - use with care
let safe: Result<u8, _> = u8::try_from(mv);   // checked conversion
```

> [tip] Prefer From / TryFrom | `u32::from(x_u16)` can never lose data and says so. `u8::try_from(x_u32)` returns a `Result`. Reserve bare `as` for cases where truncation is intended.

## 2.3 Integer Overflow

In C, signed overflow is undefined behaviour and unsigned overflow wraps. In Rust the behaviour is defined: **debug builds panic**, release builds wrap - unless you say what you want.

```rust Choose your overflow behaviour
let a: u8 = 250;
let b = a.wrapping_add(10);        // 4      (explicit wrap, e.g. a hash)
let c = a.checked_add(10);         // None   (detect overflow)
let d = a.saturating_add(10);      // 255    (clamp, e.g. a PWM duty)
let (e, overflowed) = a.overflowing_add(10);
```

Use `wrapping_sub` for tick differences: `now.wrapping_sub(start) >= timeout` works across the 49-day roll-over of a 1 kHz `u32` counter.

## 2.4 Functions and Expressions

Almost everything is an expression; the last expression without a semicolon is the return value.

```rust Functions
fn celsius_x10(raw: u16) -> i16 {
    let mv = (raw as i32 * 3300) / 4095;
    (mv - 500) as i16              // TMP36: 500 mV offset, 10 mV per degree = degrees x 10
}

fn clamp_duty(d: u16, max: u16) -> u16 {
    if d > max { max } else { d }  // `if` is an expression
}
```

`match` replaces `switch`, and it is **exhaustive**: forgetting a case is a compile error.

```rust match
fn describe(level: u8) -> &'static str {
    match level {
        0 => "off",
        1..=9 => "low",
        10 | 11 => "mid",
        _ => "high",
    }
}
```

## 2.5 Arrays, Slices and Bounds

```rust Arrays and slices
let mut buf = [0u8; 16];          // fixed size, stack allocated, zeroed
buf[3] = 0x7E;
let header: &[u8] = &buf[0..4];   // a slice: pointer + length together
let sum: u32 = header.iter().map(|&b| b as u32).sum();
// buf[16] = 1;   // panics at run time: index out of bounds (never silent corruption)
```

A **slice** `&[u8]` carries its length with it, fixing the classic C problem of passing `(uint8_t *p, size_t n)` separately and getting them out of sync. Loops with iterators (`for b in buf.iter()`) have no index at all, so no out-of-bounds is possible - and the optimiser removes the checks.

## 2.6 A First Look at `unsafe`

`unsafe` marks a block where **you** promise the compiler's rules are upheld - dereferencing a raw pointer, calling a foreign function, touching `static mut`. Everything else in the language stays checked.

```rust Contained unsafe
// Reading a memory-mapped register: the unsafety is hidden behind a safe function
fn read_idr() -> u32 {
    unsafe { core::ptr::read_volatile(0x4002_0010 as *const u32) }
}
```

> [warn] Keep unsafe small | Put each `unsafe` block behind a safe function with a comment explaining why it is sound. In HAL code that is already done for you - application code usually needs none.
