## 21.1 What DMA Gives You

DMA moves data between memory and peripherals without the CPU. It is the highest-performance tool in the course and the most dangerous in C: the hardware writes into a buffer while your code may still be reading, moving or freeing it.

| Risk in C | How Rust prevents it |
|---|---|
| Buffer freed while DMA still writes | Transfer takes **ownership** of the buffer |
| Reading the buffer mid-transfer | Buffer is inaccessible until `wait()` returns it |
| Stack buffer that goes out of scope | Buffer must be `'static` |
| Two transfers on one stream | Stream is a value, moved into the transfer |

## 21.2 Ownership of the Buffer

```rust Memory-to-memory transfer
use cortex_m::singleton;
use stm32f4xx_hal::dma::{config::DmaConfig, MemoryToMemory, StreamsTuple, Transfer};

let streams = StreamsTuple::new(dp.DMA2);
let src: &'static mut [u32; 64] = singleton!(: [u32; 64] = [0xAA55_AA55; 64]).unwrap();
let dst: &'static mut [u32; 64] = singleton!(: [u32; 64] = [0; 64]).unwrap();

let transfer = Transfer::init_memory_to_memory(streams.0, MemoryToMemory::new(), dst, src, DmaConfig::default().memory_increment(true));
// src and dst are moved - main cannot touch them now
let (stream, _, dst, _) = { let mut t = transfer; t.start(|_| {}); t.wait(); t.release() };
// dst is returned only after completion
```

`singleton!` creates a `'static` buffer **once** and returns `None` if called twice, so two transfers cannot alias the same memory.

## 21.3 UART RX with DMA and Idle Line

```text Receive pattern
1. Start a circular or double-buffered DMA transfer.
2. The UART raises an IDLE interrupt when the line goes quiet.
3. In the ISR read the DMA counter to learn how many bytes arrived.
4. Hand the filled half to main; DMA continues into the other half.
```

This receives frames of **unknown length** with zero CPU load per byte. In Rust the buffer halves are separate values: while hardware owns one half, main owns the other.

> [tip] Cache is not a problem on the F446 | The Cortex-M4 has no data cache. On an M7 (F7/H7) you must clean or invalidate the D-cache around DMA, and place buffers in a non-cacheable region.

## 21.4 Alignment and Placement

- DMA buffer element size must match the peripheral data size (8, 16 or 32 bit).
- Use `#[repr(align(4))]` for 32-bit buffers.
- Place DMA buffers in SRAM that the DMA can reach. On the F446 the main SRAM is reachable; the CCM RAM is **not** reachable by DMA. Check the linker section for your buffer (chapter 11).

```rust Aligned buffer
#[repr(C, align(4))]
struct Aligned<const N: usize>([u8; N]);

#[link_section = ".bss"]                 // normal SRAM, not CCM
static mut RX_BUF: Aligned<64> = Aligned([0; 64]);
```

## 21.5 ADC and Timer-Triggered Sampling

A timer trigger and DMA circular mode give you evenly spaced samples with no CPU involvement: configure the timer TRGO to start each ADC conversion, DMA writes the result to memory, and half/transfer-complete interrupts signal data ready.

## 21.6 Debugging DMA

| Symptom | Check |
|---|---|
| Transfer never completes | Stream or channel mapping wrong (RM0390 DMA request table) |
| Data wrong or zero | Peripheral DMA request not enabled, or wrong data size |
| Hard fault at start | Buffer in unreachable memory or misaligned |
| Overrun | Consumer too slow for circular buffer |
