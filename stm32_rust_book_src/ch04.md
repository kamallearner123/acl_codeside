## 4.1 References Instead of Ownership

A **borrow** gives temporary access without transferring ownership. There are two kinds:

| Kind | Syntax | Rule |
|---|---|---|
| Shared | `&T` | Any number at the same time; read-only |
| Exclusive | `&mut T` | Exactly one; nobody else may read or write meanwhile |

This is the **aliasing XOR mutability** rule: *many readers or one writer, never both*. It is exactly the rule you must follow manually in C when an ISR and `main` touch the same data.

```rust Borrowing in practice
fn average(samples: &[u16]) -> u16 {           // shared borrow: read only
    let sum: u32 = samples.iter().map(|&s| s as u32).sum();
    (sum / samples.len() as u32) as u16        // note: panics if len == 0, see chapter 8
}

fn fill(buf: &mut [u16], value: u16) {            // exclusive borrow: may modify
    for b in buf.iter_mut() { *b = value; }
}

let mut data = [0u16; 8];
let avg = average(&data);        // borrow ends after the call
fill(&mut data, 100);        // new exclusive borrow
```

## 4.2 What the Compiler Rejects

```rust Rejected: reader while writer exists
let mut buf = [0u8; 4];
let first = &buf[0];      // shared borrow
buf[1] = 7;               // ERROR: cannot assign while `first` is borrowed
println!("{}", first);
```

In C that code compiles. If `buf[1] = 7` were an ISR rewriting the buffer while `main` was reading it, you would have a data race. Rust makes the equivalent state unrepresentable.

## 4.3 `&mut` for Hardware Drivers

Driver methods take `&mut self` when they change the peripheral. That means two pieces of code cannot call into the same UART at once:

```rust Method receivers
impl Console {
    fn line_count(&self) -> usize { self.lines }          // read only
    fn write_line(&mut self, s: &str) { /* touches UART */ }
}

let mut con = Console::new(tx);
con.write_line("hello");     // needs `mut con`
```

Passing the driver to a helper function as `&mut Console` lends it exclusively for the call - no global variable, no hidden sharing.

## 4.4 Splitting Borrows

A common frustration: you want two `&mut` into one array. Use the split helpers:

```rust split_at_mut
let mut frame = [0u8; 8];
let (id_part, data_part) = frame.split_at_mut(2);
id_part[0] = 0x01;
data_part[0] = 0xFF;
```

Disjoint pieces are provably non-overlapping, so both mutable borrows are allowed.

## 4.5 The `static mut` Trap

The shortcut from C - a global variable - is `static mut`. Using it requires `unsafe` precisely because the compiler cannot verify exclusive access:

```rust static mut is a red flag
static mut TICKS: u32 = 0;

fn bump() {
    unsafe { TICKS += 1; }     // compiles, but races with any ISR that also touches TICKS
}
```

> [warn] Avoid static mut | Modern Rust (2024 edition) warns about references to `static mut`. For data shared with interrupts use `Mutex<RefCell<..>>`, atomics or RTIC resources - chapter 14 shows each one.

## 4.6 Borrowing and the Embedded Memory Model

- Borrowing costs **nothing at run time**: it compiles to the same pointer passing as C.
- The borrow checker runs only at compile time, so there is no flash or RAM overhead.
- Interior mutability (`Cell`, `RefCell`) moves some checks to run time - use sparingly and know the cost.
