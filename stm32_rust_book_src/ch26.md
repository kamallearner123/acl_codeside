## 26.1 Capstone Overview

Build a **Safe Cooling-Fan and Environment Controller Node** in Rust on the NUCLEO-F446RE. It reads temperature, controls a fan with PWM, offers a serial console, reports telemetry on CAN and fails safe when something goes wrong.

This integrates the whole course: ownership, enums and `Result`, `no_std`, interrupts, timers and PWM, I2C, ADC, UART, CAN, testing, debugging and architecture.

## 26.2 Requirements

| ID | Requirement | Verification |
|---|---|---|
| R1 | Read temperature from a BME280 every 500 ms | Logic analyzer and log |
| R2 | Fan PWM 0-100 percent at 20 kHz proportional between 25 and 45 C | Host test plus scope |
| R3 | Read a potentiometer as manual override on ADC | Hardware test |
| R4 | UART console with `status`, `fan <0-100>` and `auto` commands | Terminal session |
| R5 | Send telemetry on CAN ID 0x100 every second and accept fan set on 0x200 | Two-node test |
| R6 | After 5 consecutive sensor failures go to Fault and run fan at 100 percent | Disconnect test |
| R7 | Watchdog resets if the control task stalls for more than 2 s | Fault injection |
| R8 | No `unsafe` in application, drivers or logic crates | `forbid(unsafe_code)` |
| R9 | All logic has host unit tests | `cargo test` in CI |
| R10 | Flash under 64 KB, release build | `cargo size` |

## 26.3 Architecture

```text Block diagram
BME280 --I2C--> [sensor task] --Reading--> [control task] --Percent--> [fan PWM]
Pot   --ADC---> [adc task]    --Override-> [control task]
                                   |--State--> [CAN task] --> bus
UART console <--commands/--> [console task] --> [control task]
Watchdog fed only when sensor, control and CAN tasks all report alive
```

## 26.5 Core Control Loop

```rust Control step in the logic crate
pub struct Controller { state: State, fails: u8, manual: Option<u8> }

impl Controller {
    pub fn on_temp(&mut self, temp_dc: Result<i16, ()>) -> u8 {
        let ev = match temp_dc { Ok(t) => Event::SensorOk(t), Err(_) => Event::SensorFailed };
        self.state = step(self.state, &ev, &mut self.fails);

        match (self.state, temp_dc, self.manual) {
            (State::Fault, _, _) => 100,                       // fail-safe
            (_, _, Some(m)) => m.min(100),                     // manual override
            (_, Ok(t), None) => fan_percent(t as i32),
            (_, Err(_), None) => 60,                           // degraded: moderate cooling
        }
    }
}
```

The function has no hardware access: it is a plain input-to-output mapping you can test with a table of cases.

## 26.6 Test Plan

1. **Host**: temperature sweep, boundaries (24.9, 25.0, 45.0 C), five consecutive failures to Fault, Reset returns to Init, CAN encode/decode round trips.
2. **Mocked driver**: wrong chip ID, NACK, truncated read.
3. **On target**: PWM frequency, ADC range, timer periods.
4. **System**: unplug the sensor, short the CAN bus, hold the console in reset, stall the control task and confirm the watchdog reset.
5. **Soak**: run 24 hours and log maximum loop time and free stack.

> [tip] Common pitfalls | Reading ADC and I2C inside an ISR, blocking the control loop on a console write, forgetting to terminate CAN, and feeding the watchdog from a timer interrupt that keeps running even when the application is stuck.
