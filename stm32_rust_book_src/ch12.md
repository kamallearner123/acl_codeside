## 12.1 The Toolchain at a Glance

| Task | C tool (Book 1) | Rust tool |
|---|---|---|
| Compiler | `arm-none-eabi-gcc` | `rustc` (LLVM) via `cargo` |
| Build system | Makefile / CubeIDE | `cargo` |
| Package manager | Manual copy of HAL files | `cargo` + crates.io |
| Flash + debug | ST-LINK GDB server, OpenOCD | **`probe-rs`** (also works with OpenOCD + GDB) |
| Logging | `printf` over UART/SWO | **`defmt`** over RTT |
| IDE | STM32CubeIDE | VS Code + `rust-analyzer` (any editor with LSP) |
| Static checks | `-Wall`, cppcheck | `clippy`, the compiler |

## 12.2 Installation

```bash One-time setup on Linux/macOS
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh     # rustup, cargo, rustc
rustup target add thumbv7em-none-eabihf
rustup component add llvm-tools clippy rustfmt rust-src
cargo install probe-rs-tools --locked      # flash, run, GDB server, VS Code debugger backend
cargo install flip-link cargo-binutils cargo-bloat --locked
cargo install cargo-generate               # project templates
```

On Windows install `rustup-init.exe` and the same tools. The Nucleo's ST-LINK is supported out of the box - on Linux add the udev rules from the `probe-rs` documentation so you do not need `sudo`.

```bash Check the probe is visible
probe-rs list
probe-rs info --chip STM32F446RETx
```

## 12.3 Creating a Project

```bash From a template
cargo generate --git https://github.com/knurling-rs/app-template
```

The template asks for a chip name and gives you `Cargo.toml`, `.cargo/config.toml`, `memory.x`, `build.rs` and a `main.rs` already wired for `defmt` and `probe-rs`. You can also copy the manual files from chapter 10.

Resulting layout:

```text Typical project
blinky/
 |-- .cargo/config.toml     target, runner, rustflags
 |-- Cargo.toml             dependencies and profiles
 |-- Cargo.lock             exact versions - commit this
 |-- build.rs               copies memory.x
 |-- memory.x               Flash and RAM
 |-- src/main.rs
 `-- tests/                 on-target tests (chapter 22)
```

## 12.4 The Daily Workflow

```bash Commands you will type constantly
cargo check                 # fastest: type-check only
cargo build --release
cargo run                   # build + flash + run, defmt logs appear in the terminal
cargo clippy -- -D warnings # lint (catches common mistakes)
cargo fmt                   # format
cargo doc --open            # documentation of your dependencies, offline
probe-rs run --chip STM32F446RETx target/thumbv7em-none-eabihf/release/blinky
```

`cargo doc --open` is the most underrated command: the HAL documentation shows every pin type, every constructor and the traits it implements.

## 12.5 Reading Crate Documentation

1. Find the crate on **docs.rs** and select the exact version in your `Cargo.toml`.
2. Look for the **`examples/`** directory in the repository - HALs ship dozens of runnable examples per board family.
3. Check the **feature flags**: `stm32f4xx-hal` needs a chip feature such as `stm32f446`.
4. Read the **CHANGELOG** before upgrading; HAL APIs do change.

## 12.6 VS Code Setup

- Extensions: **rust-analyzer** and **probe-rs-debugger**.
- In `.vscode/settings.json` tell rust-analyzer the target: `"rust-analyzer.cargo.target": "thumbv7em-none-eabihf"` and `"rust-analyzer.check.allTargets": false`.
- Use the generated `launch.json` from `probe-rs` to get breakpoints, variables and registers in the editor.

> [warn] Two toolchains can disagree | If you also have CubeIDE and a separate ST-LINK GDB server running, only one program can own the probe at a time. Close one before starting the other.
