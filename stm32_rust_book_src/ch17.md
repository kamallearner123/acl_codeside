## 17.1 I²C and the `embedded-hal` Trait

I²C uses two open-drain wires (SCL, SDA) with pull-ups. Book 1 covered addressing, ACK and NACK. In Rust the important new idea is that a sensor driver should not know about STM32 at all - it only needs something that implements the `embedded_hal::i2c::I2c` trait.

```rust Create I2C1 on PB8 and PB9
use stm32f4xx_hal::{i2c::I2c, prelude::*};

let gpiob = dp.GPIOB.split();
let scl = gpiob.pb8;
let sda = gpiob.pb9;
let mut i2c = I2c::new(dp.I2C1, (scl, sda), 100.kHz(), &clocks);
```

> [hw] Pull-ups | Most BME280 and MPU6050 breakout boards include pull-ups. If you probe with a logic analyzer and see slow rising edges, add 4.7 kOhm to 3.3 V.

## 17.2 Raw Transactions

```rust Read the BME280 chip ID
use embedded_hal::i2c::I2c as _;

const ADDR: u8 = 0x76;
let mut id = [0u8; 1];
i2c.write_read(ADDR, &[0xD0], &mut id)?;        // register 0xD0 holds the chip ID
assert_eq!(id[0], 0x60);                          // 0x60 = BME280
```

`write_read` performs a repeated-start transaction, as the datasheet requires. The `?` operator forwards a bus error (NACK, arbitration lost) to the caller - you cannot forget to check it.

## 17.3 A Generic Sensor Driver

```rust Driver generic over any I2c implementation
use embedded_hal::i2c::I2c;

pub struct Bme280<I2C> { i2c: I2C, addr: u8 }

#[derive(Debug)]
pub enum Error<E> { Bus(E), WrongChip(u8) }

impl<I2C: I2c> Bme280<I2C> {
    pub fn new(mut i2c: I2C, addr: u8) -> Result<Self, Error<I2C::Error>> {
        let mut id = [0u8];
        i2c.write_read(addr, &[0xD0], &mut id).map_err(Error::Bus)?;
        if id[0] != 0x60 { return Err(Error::WrongChip(id[0])); }
        Ok(Self { i2c, addr })
    }

    pub fn read_raw(&mut self) -> Result<[u8; 8], Error<I2C::Error>> {
        let mut buf = [0u8; 8];
        self.i2c.write_read(self.addr, &[0xF7], &mut buf).map_err(Error::Bus)?;
        Ok(buf)
    }

    pub fn release(self) -> I2C { self.i2c }
}
```

- The driver **owns** the bus handle while in use; `release()` hands it back.
- `Error<E>` wraps the HAL's own error type, so nothing is lost and nothing is hidden behind magic numbers.
- The same driver compiles for STM32, nRF, RP2040 or a host mock.

## 17.4 Sharing One Bus Between Several Drivers

Two sensors on one bus cannot both own the I2C peripheral. Use a bus-sharing crate such as `embedded-hal-bus`:

```rust Shared bus via RefCell
use core::cell::RefCell;
use embedded_hal_bus::i2c::RefCellDevice;

let bus = RefCell::new(i2c);
let mut temp = Bme280::new(RefCellDevice::new(&bus), 0x76)?;
let mut imu  = Mpu6050::new(RefCellDevice::new(&bus), 0x68)?;
```

Each device handle borrows the bus for the duration of one transaction. In an interrupt context use the critical-section variant instead.

## 17.5 Converting Raw Data

Compensation formulas in the BME280 datasheet use integer maths on factory calibration values. Keep that conversion in a **pure function** that takes plain integers:

```rust Pure and host-testable
pub struct Calib { pub t1: u16, pub t2: i16, pub t3: i16 }

pub fn compensate_temp(adc_t: i32, c: &Calib) -> i32 {
    let var1 = (((adc_t >> 3) - ((c.t1 as i32) << 1)) * (c.t2 as i32)) >> 11;
    let d = (adc_t >> 4) - (c.t1 as i32);
    let var2 = (((d * d) >> 12) * (c.t3 as i32)) >> 14;
    ((var1 + var2) * 5 + 128) >> 8      // temperature in 0.01 degrees C
}
```

Test it on your PC with values from the datasheet example. This catches overflow and rounding problems without any hardware.

## 17.6 Error Recovery

| Symptom | Likely cause | Rust-side response |
|---|---|---|
| `Error::Bus(NoAcknowledge)` | Wrong address or wiring | Report and retry later |
| `WrongChip(id)` | Different sensor fitted | Refuse to start - fail loudly |
| Bus stuck low | Slave holding SDA | Toggle SCL 9 times, re-init peripheral |
| Intermittent timeouts | Long wires, weak pull-ups | Lower speed, shorten wires |
