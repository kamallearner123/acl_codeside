## 9.1 Three Layers of the Standard Library

Rust's library comes in layers. On a microcontroller you use the bottom one.

| Layer | Provides | Needs | Embedded? |
|---|---|---|---|
| `core` | Types, `Option`, `Result`, iterators, slices, `fmt`, atomics, `ptr`, `mem` | Nothing | **Always** |
| `alloc` | `Vec`, `String`, `Box`, `Rc` | A global heap allocator | Optional |
| `std` | Files, threads, networking, `println!` | An operating system | No |

`#![no_std]` tells the compiler "link `core` only". You lose nothing that does not need an OS.

## 9.2 The Skeleton of a `no_std` Program

```rust src/main.rs
#![no_std]
#![no_main]

use cortex_m_rt::entry;
use panic_probe as _;        // supplies the #[panic_handler]
use defmt_rtt as _;          // supplies the defmt log transport

#[entry]
fn main() -> ! {
    defmt::info!("boot");
    loop {
        cortex_m::asm::wfi();    // sleep until an interrupt
    }
}
```

- `#![no_main]` - there is no `fn main(args)` called by an OS; the reset handler from `cortex-m-rt` calls your `#[entry]`.
- `-> !` - the function never returns (the "never" type). Firmware has no OS to return to.
- `use panic_probe as _;` - links the crate only to get its `#[panic_handler]`.

## 9.3 No Heap? Use Fixed-Capacity Collections

Dynamic allocation in firmware brings fragmentation and non-deterministic timing. The `heapless` crate offers the same ergonomics with a compile-time capacity:

```rust heapless
use heapless::{Vec, String, spsc::Queue};
use core::fmt::Write;

let mut samples: Vec<u16, 32> = Vec::new();         // capacity 32, lives on the stack
samples.push(1234).ok();                             // Err(value) when full - handle it

let mut line: String<64> = String::new();
write!(line, "adc={} mv={}", raw, mv).ok();         // formatting without allocating

let mut q: Queue<u8, 64> = Queue::new();             // single-producer single-consumer ring buffer (chapter 14)
```

`push` returns a `Result` because the buffer can be full - the type forces you to decide what happens, which a C ring buffer rarely does.

## 9.4 Optional: A Heap with `alloc`

```rust embedded-alloc
extern crate alloc;
use embedded_alloc::LlffHeap as Heap;

#[global_allocator]
static HEAP: Heap = Heap::empty();

fn init_heap() {
    use core::mem::MaybeUninit;
    const SIZE: usize = 8 * 1024;
    static mut ARENA: [MaybeUninit<u8>; SIZE] = [MaybeUninit::uninit(); SIZE];
    unsafe { HEAP.init(core::ptr::addr_of_mut!(ARENA) as usize, SIZE) }
}
```

> [tip] Heap policy | Allocate during start-up only, or not at all. Many safety-oriented teams ban the heap and use `heapless` so RAM use is known at link time.

## 9.5 Formatting and Logging Without `std`

- `core::fmt::Write` + `write!` format into any buffer or UART (`writeln!(tx, "x={}", x)`).
- `defmt` is a logging framework designed for microcontrollers: the format strings stay on the PC and only compact IDs are sent, so logging costs very little flash and time.

```rust defmt vs core::fmt
defmt::info!("temp = {} mC, raw = {=u16:#x}", temp, raw);   // tiny, fast, decoded on the host
writeln!(tx, "temp = {} mC", temp).ok();                    // human-readable text over UART
```

## 9.6 What Changes from C

| In C you used | In `no_std` Rust |
|---|---|
| `startup_stm32f446xx.s` | `cortex-m-rt` (`#[entry]`, vector table, RAM initialisation) |
| `printf` retargeting | `defmt`, `write!` to UART |
| `malloc` | `heapless` collections, optional `embedded-alloc` |
| `assert` | `assert!` / `debug_assert!` (calls the panic handler) |
| `errno` | `Result` |
