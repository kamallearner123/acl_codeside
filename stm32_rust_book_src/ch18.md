## 18.1 SPI Basics Recap

SPI uses SCK, MOSI, MISO and one chip-select per device. The key parameters are the **mode** (CPOL/CPHA), clock speed, bit order and frame size. A wrong mode is the number-one cause of garbage data; confirm it with the logic analyzer.

| Mode | CPOL | CPHA | Clock idle | Sample edge |
|---|---|---|---|---|
| 0 | 0 | 0 | Low | Rising |
| 1 | 0 | 1 | Low | Falling |
| 2 | 1 | 0 | High | Falling |
| 3 | 1 | 1 | High | Rising |

## 18.2 Creating SPI1

```rust SPI1 on PA5, PA6, PA7 with CS on PA4
use stm32f4xx_hal::{spi::{Mode, Phase, Polarity, Spi}, prelude::*};

let gpioa = dp.GPIOA.split();
let sck = gpioa.pa5;
let miso = gpioa.pa6;
let mosi = gpioa.pa7;
let mut cs = gpioa.pa4.into_push_pull_output();
cs.set_high();                                  // deselected

let mut spi = Spi::new(
    dp.SPI1,
    (sck, miso, mosi),
    Mode { polarity: Polarity::IdleLow, phase: Phase::CaptureOnFirstTransition },
    1.MHz(),
    &clocks,
);
```

## 18.3 Chip Select Done Safely

Forgetting to raise CS leaves a device selected for the next transaction. Use the `SpiDevice` abstraction, which owns the CS pin and asserts it **only** for the closure of one transaction:

```rust SpiDevice transaction
use embedded_hal::spi::{SpiDevice, Operation};

fn read_id<S: SpiDevice>(dev: &mut S) -> Result<[u8; 3], S::Error> {
    let mut id = [0u8; 3];
    dev.transaction(&mut [Operation::Write(&[0x9F]), Operation::Read(&mut id)])?;   // JEDEC ID, CS held across both
    Ok(id)
}
```

The driver cannot leave CS low: the device implementation drives it for the transaction and releases it even if an error occurs.

## 18.4 Flash and SD Storage

- **SPI NOR flash** (W25Q): erase before write, page size 256 bytes. Wrap sector erase and page program in functions that check the address range and return an `Error`.
- **SD cards** over SPI: use the `embedded-sdmmc` crate to access a FAT filesystem with typed handles that cannot outlive the volume.

```rust Bounds-checked page write
const PAGE: usize = 256;

fn write_page<S: SpiDevice>(dev: &mut S, addr: u32, data: &[u8]) -> Result<(), FlashError<S::Error>> {
    if data.len() > PAGE || (addr as usize % PAGE) + data.len() > PAGE {
        return Err(FlashError::CrossesPage);        // would wrap inside the page
    }
    let cmd = [0x02, (addr >> 16) as u8, (addr >> 8) as u8, addr as u8];
    dev.transaction(&mut [Operation::Write(&cmd), Operation::Write(data)]).map_err(FlashError::Spi)
}
```

This is exactly the "buffer bounds" bug class from the C course turned into a typed error.

## 18.5 Displays with `embedded-graphics`

`embedded-graphics` draws shapes and text onto anything that implements `DrawTarget`. Display drivers (ST7789, SSD1306, ILI9341) implement that trait, so application code never touches pixels directly.

```rust Drawing text on a display
use embedded_graphics::{
    mono_font::{ascii::FONT_6X10, MonoTextStyle},
    pixelcolor::Rgb565, prelude::*, text::Text,
};

let style = MonoTextStyle::new(&FONT_6X10, Rgb565::WHITE);
display.clear(Rgb565::BLACK).ok();
Text::new("Temp: 24.5 C", Point::new(10, 20), style).draw(&mut display).ok();
```

> [tip] Use DMA for frame transfers | A 240x240 RGB565 frame is 115 KB. Over SPI at 10 MHz that takes 90 ms of CPU time unless DMA moves it for you (chapter 21).

## 18.6 Debugging SPI

| Symptom | Check |
|---|---|
| All 0xFF read | MISO floating, CS not asserted, device unpowered |
| All 0x00 read | MISO shorted low or wrong mode |
| Data shifted by one bit | CPHA wrong |
| Works slowly, fails fast | Wires too long, reduce clock |
