Prepare your workstation

What to install

Follow the steps for your operating system. The visualiser and manuals need only a modern browser; install the C or Rust toolchain when you are ready to build firmware. Commands below are run in Terminal (macOS/Linux) or PowerShell (Windows), unless noted.

macOS

  1. Install Apple's command-line tools. Open Terminal and run: 
    xcode-select --install
xcode-select -p
git --version
    Accept the installer prompt. Git should print a version; the developer directory should be printed by the second command.
  2. Install VS Code. Download it from code.visualstudio.com, move it to Applications, then in VS Code open the Command Palette and run Shell Command: Install 'code' command in PATH. Open a new Terminal and verify: 
    code --version
  3. Install ST's C, configuration, and flash tools. Download and install STM32CubeIDE and STM32CubeProgrammer for your macOS version. STM32CubeIDE includes the STM32CubeMX graphical configuration/code-generation workflow, so a separate CubeMX install is not needed for this course. Create a project in CubeIDE, open its .ioc configuration, generate code, and build; the Console should report Build Finished with no errors. Follow any ST-LINK or macOS security prompts. If you use another IDE/toolchain instead, install standalone STM32CubeMX separately.
  4. Optional: set up Rust. Install Rust with rustup, then add the course target and probe tools: 
    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
rustup default stable
rustup target add thumbv7em-none-eabihf
cargo install probe-rs-tools --locked
rustc --version
rustup target list --installed
probe-rs --version
    The installed-target list must include thumbv7em-none-eabihf.

Linux

  1. Install the common command-line tools (Debian/Ubuntu): 
    sudo apt update
sudo apt install -y git build-essential cmake ninja-build pkg-config libudev-dev usbutils
git --version
gcc --version
    For another distribution, use its package manager to install the equivalent packages. Install VS Code using the official package/instructions for that distribution, then verify with code --version.
  2. Install ST's C, configuration, and flash tools. Download STM32CubeIDE and STM32CubeProgrammer for your distribution and follow ST's installer instructions. CubeIDE includes the STM32CubeMX graphical configuration/code-generation workflow; you do not need to install CubeMX separately when using CubeIDE. Create a project, open its .ioc configuration, generate code, then build and confirm Build Finished with no errors. If you use another IDE/toolchain, install standalone STM32CubeMX.
  3. Allow normal USB access to ST-LINK. Apply ST's udev rules as directed by the installed ST package/documentation, then reload rules and reconnect the board: 
    sudo udevadm control --reload-rules
sudo udevadm trigger
lsusb
    With the board connected, check that it appears in lsusb. Do not run CubeIDE or probe-rs with sudo to bypass permissions.
  4. Optional: set up Rust. Install rustup from rustup.rs, then run: 
    rustup default stable
rustup target add thumbv7em-none-eabihf
cargo install probe-rs-tools --locked
rustc --version
rustup target list --installed
probe-rs --version
probe-rs list
    The target must appear in the installed-target list; with a connected board, probe-rs list should find its probe.

Windows

  1. Install Git and VS Code. Use the official Git for Windows and VS Code installers. Open a new PowerShell window and verify: 
    git --version
code --version
  2. Install ST's C, configuration, and flash tools. Download and install STM32CubeIDE and STM32CubeProgrammer using their Windows installers. CubeIDE includes the STM32CubeMX graphical configuration/code-generation workflow, so a separate CubeMX install is not needed for this course. Create a project, open its .ioc configuration, generate code, and build; confirm Build Finished with no errors. If you use another IDE/toolchain, install standalone STM32CubeMX.
  3. Optional: set up Rust. Install rustup for the MSVC host from rustup.rs. When prompted, install the Visual Studio C++ Build Tools and Windows SDK prerequisites, then open a new PowerShell window and run: 
    rustup default stable
rustup target add thumbv7em-none-eabihf
cargo install probe-rs-tools --locked
rustc --version
rustup target list --installed
probe-rs --version
    The installed-target list must include thumbv7em-none-eabihf.
  4. Check the ST-LINK driver. Connect the board and open Device Manager. Confirm the ST-LINK device appears without a warning icon; install the driver from ST's CubeProgrammer package if Windows does not recognise it.

Bench setup

Hardware list

The manuals use the NUCLEO-F446RE as the main C/Cortex-M/Rust board. Visualise STM32 identifies an STM32L476RG-style target; treat that visualiser as a conceptual architecture guide unless you also have an L476 board.

Required to follow board exercises

  • NUCLEO-F446RE development board with its integrated ST-LINK debugger.
  • USB data cable compatible with the board connector, plus a computer that can run the toolchains.
  • Web browser for the architecture visualiser and course manuals.

Recommended for project work

  • Breadboard, jumper wires and basic LEDs/resistors.
  • 3.3 V-compatible button/sensor modules; check board pin limits before wiring.
  • Optional USB-UART adapter, logic analyser and CAN transceiver for projects that need them.
  • For matching Visualise STM32's target, an STM32L476RG board such as NUCLEO-L476RG is optional; it is not required to use the visualiser.

Do not connect 5 V signals directly to MCU pins unless the specific pin's electrical limits and interface circuit explicitly allow it. Automotive and CAN projects require a separate CAN transceiver; the MCU's CAN controller pins are not a vehicle bus interface.

How we work

Expectations from the group

Build, don't just watch

Follow the course material, run the code, and keep a working repository of your own.

Show engineering evidence

Bring logs, diagrams, commits, test results and short design notes when asking for review.

Collaborate respectfully

Share useful feedback, explain assumptions, and help peers reason through faults without sharing credentials or private data.

Own your setup

Install tools before project sessions, check board connectivity, and report OS/tool versions when debugging.

Think about safety and security

Prototype responsibly. Do not connect experimental firmware to real vehicles, industrial equipment, or safety-critical systems.

Complete a project outcome

Work toward a documented, demonstrated engineering deliverable—not only a collection of isolated lab exercises.

ACL project tracks

Engineering projects, not just lab sessions

Each track is framed around a system, an engineering question and reviewable deliverables. Work with simulated systems or bench prototypes; these are educational prototypes, not production or safety certifications.

Automotive cybersecurity

Secure CAN gateway and intrusion monitor

Design a simulated ECU network, define a threat model, validate message IDs and rates, detect replay/anomalous traffic, and record security events. Exercise diagnostic and update-integrity ideas in a contained simulation.

Deliverables: architecture and threat model, testable gateway firmware, attack/defence test cases, and a measured security report.

Zephyr + industrial automation

Simulated production cell controller

Build a Zephyr-based control node for a simulated conveyor/process. Model sensors and actuators, schedule independent tasks, implement a fault-aware state machine, and exchange telemetry with a host-side simulation.

Deliverables: system model, Zephyr application, simulation interface, timing/fault tests, and an operator-facing demonstration.

Simulation + embedded systems

Virtual ECU network and diagnostics bench

Create multiple simulated nodes and a gateway, exercise startup, timeouts, diagnostics and bus faults, then compare observable traces with the firmware's expected state transitions.

Deliverables: executable simulation, protocol/sequence documentation, automated regression tests, and trace-based fault analysis.

Industrial condition monitoring

Sensor-to-edge monitoring node

Acquire simulated or bench sensor samples using timer-triggered ADC and DMA, calculate health indicators, handle missing/out-of-range data, and publish structured telemetry.

Deliverables: acquisition pipeline, fault-injection plan, repeatable tests, and a dashboard or CLI demonstration.
