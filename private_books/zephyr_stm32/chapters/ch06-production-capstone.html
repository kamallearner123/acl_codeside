6.1 Secure Bootloaders & MCUBoot Dual-Slot DFU

In professional IoT and automotive products, a firmware update must never brick the device. MCUBoot is the industry-standard secure bootloader integrated natively into Zephyr.

A dual-slot STM32 Flash partition layout in DeviceTree:

DTS Flash Partition Table for MCUBoot (512KB STM32 Flash) 
&flash0 {
    partitions {
        compatible = "fixed-partitions";
        #address-cells = <1>;
        #size-cells = <1>;

        /* 0x00000 - 0x10000 (64 KB): MCUBoot Bootloader */
        boot_partition: partition@0 {
            label = "mcuboot";
            reg = <0x00000000 0x00010000>;
            read-only;
        };

        /* 0x10000 - 0x48000 (224 KB): Active Firmware (Slot 0) */
        slot0_partition: partition@10000 {
            label = "image-0";
            reg = <0x00010000 0x00038000>;
        };

        /* 0x48000 - 0x80000 (224 KB): Download Secondary (Slot 1) */
        slot1_partition: partition@48000 {
            label = "image-1";
            reg = <0x00048000 0x00038000>;
        };
    };
};

The Safe Swap Protocol:

  1. New encrypted and signed firmware is downloaded into slot1_partition.
  2. On reboot, MCUBoot validates digital cryptographic signatures (RSA-2048 or ECDSA-P256).
  3. MCUBoot swaps Slot 1 into Slot 0 and boots the new image in test mode.
  4. If the application boots and calls boot_write_img_confirmed(), the update is permanent. If a Watchdog or HardFault triggers before confirmation, MCUBoot automatically rolls back to the previous firmware!

6.2 Automated Testing with Twister & Ztest

Zephyr provides Twister, an automated test runner that builds and executes hundreds of test suites across multiple architectures in parallel, either on physical boards or via simulation (QEMU/Renode).

BASH Running Twister Tests 
# Run tests under QEMU emulation
./scripts/twister -T tests/kernel/sched -p qemu_cortex_m3

# Run tests on hardware connected via ST-Link
./scripts/twister -T tests/drivers/gpio -p nucleo_f401re --device-testing

6.4 Capstone Project: Industrial Fail-Safe Gateway

In our final capstone project (located in samples/06_capstone_industrial_monitor/), we integrate all concepts into an industrial-grade firmware architecture:

  • Hardware Independent Watchdog (IWDG): The STM32 hardware watchdog timer triggers a hard MCU reset if not refreshed every 2000 ms.
  • Supervised Watchdog Feeder Task: Continuously monitors system health metrics (message queue capacity, stack headroom). Only feeds the dog if all subsystems are healthy!
  • Fault Injection CLI Command: Allows an engineer to simulate a deadlocked thread or memory corruption, proving that the hardware watchdog automatically recovers the system.

6.4.1 Architecture: STM32 Independent Watchdog (IWDG)

The IWDG is clocked by its own dedicated 32 kHz internal Low-Speed RC oscillator (LSI), completely isolated from the main PLL clock. Even if the Cortex-M core hangs, crashes into a HardFault loop, or the main crystal oscillator fails, the IWDG continues running down to zero and forces a hardware MCU reset.

6.4.3 Capstone Source Code: src/main.c

Complete implementation with watchdog channel installation, periodic feeding, and CLI fault injection:

C samples/06_capstone_industrial_monitor/src/main.c 
/*
 * Copyright (c) 2026 Apt Computing Labs
 * "Where Knowledge Meets Innovation"
 *
 * Mastering Zephyr RTOS on STM32 - Lab 6: Industrial Watchdog Capstone
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/kernel.h>
#include <zephyr/drivers/watchdog.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/shell/shell.h>
#include <zephyr/logging/log.h>

LOG_MODULE_REGISTER(capstone_app, LOG_LEVEL_INF);

#define WDT_TIMEOUT_MS  2000
#define FEED_INTERVAL_MS 500

static const struct device *const wdt = DEVICE_DT_GET(DT_NODELABEL(iwdg));
static int wdt_channel_id;
static bool fault_injected = false;

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

/* Fault Injection Command */
static int cmd_inject_fault(const struct shell *sh, size_t argc, char **argv)
{
    ARG_UNUSED(argc);
    ARG_UNUSED(argv);
    shell_print(sh, "[CRITICAL] Injecting deadlock fault! Watchdog will bite in 2000ms...");
    fault_injected = true;
    return 0;
}

SHELL_CMD_REGISTER(fault_inject, NULL, "Simulate fatal deadlock to trigger Watchdog", cmd_inject_fault);

int main(void)
{
    int ret;
    struct wdt_timeout_cfg wdt_config;

    LOG_INF("==================================================");
    LOG_INF("  Zephyr RTOS Industrial Capstone Gateway Initialized ");
    LOG_INF("  Reset Reason: Checking hardware flags... ");
    LOG_INF("==================================================");

    if (!gpio_is_ready_dt(&led)) {
        LOG_ERR("LED device not ready");
        return 0;
    }
    gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);

    /* 1. Configure Hardware Watchdog */
    if (!device_is_ready(wdt)) {
        LOG_ERR("Watchdog device %s not ready!", wdt->name);
        return 0;
    }

    wdt_config.flags = WDT_FLAG_RESET_SOC;
    wdt_config.window.min = 0;
    wdt_config.window.max = WDT_TIMEOUT_MS;
    wdt_config.callback = NULL; /* Hardware resets immediately */

    wdt_channel_id = wdt_install_timeout(wdt, &wdt_config);
    if (wdt_channel_id < 0) {
        LOG_ERR("Failed to install watchdog timeout: %d", wdt_channel_id);
        return 0;
    }

    ret = wdt_setup(wdt, WDT_OPT_PAUSE_IN_SLEEP);
    if (ret < 0) {
        LOG_ERR("Failed to start watchdog: %d", ret);
        return 0;
    }

    LOG_INF("Hardware Watchdog active (Timeout: %d ms). System guarded.", WDT_TIMEOUT_MS);

    /* 2. Main Supervisor Loop */
    while (1) {
        if (!fault_injected) {
            /* Feed the hardware watchdog */
            wdt_feed(wdt, wdt_channel_id);
            gpio_pin_toggle_dt(&led);
            LOG_INF("Supervisor heartbeat: Watchdog refreshed.");
        } else {
            LOG_WRN("Fault active! Watchdog starving...");
        }

        k_msleep(FEED_INTERVAL_MS);
    }

    return 0;
}
