Module 04 • Hardware Drivers

STM32 Peripherals & Zephyr Driver APIs

Harness the full power of STM32 on-chip peripherals through Zephyr's standardized device driver model: high-speed Asynchronous DMA UART, I2C Bus sensors (BMP280/SHT3x) using the Zephyr Sensor Subsystem, hardware timer PWM for smooth LED breathing, and energy-saving low-power sleep modes.

⏱️ Reading Time: 45 minutes
🛠️ Lab Project: samples/04_sensor_i2c_pwm
🎯 Peripherals: I2C, PWM, Async UART, Low Power

4.1 The Zephyr Device Driver Model

In bare-metal or standard vendor HALs, reading a sensor requires calling MCU-specific register functions (like HAL_I2C_Master_Transmit()). If you switch to another vendor, your code must be completely rewritten.

Zephyr solves this with a unified Device Model:

C Universal Device Acquisition Pattern 
#include <zephyr/device.h>
#include <zephyr/drivers/i2c.h>

/* 1. Retrieve device pointer from DTS node */
const struct device *const i2c_dev = DEVICE_DT_GET(DT_NODELABEL(i2c1));

/* 2. Validate initialization status */
if (!device_is_ready(i2c_dev)) {
    printk("Error: Device %s failed initialization!\n", i2c_dev->name);
    return -ENODEV;
}

/* 3. Invoke standard, cross-platform driver API */
ret = i2c_write_read(i2c_dev, SENSOR_ADDR, ®, 1, buf, 6);

4.2 Asynchronous DMA UART vs Polled UART

Standard printk() or polled UART burns thousands of CPU cycles waiting for the hardware shift register to transmit byte-by-byte. On STM32, Zephyr supports three distinct UART modes:

1. Polled UART

CPU busy-waits on TXE/RXNE flags. Zero memory overhead, but blocks the RTOS thread during transfers.

2. Interrupt-Driven

Fires an interrupt on each received/transmitted byte into a ring buffer. Excellent for low-data rate consoles.

3. Async DMA UART

Autonomous STM32 DMA streams transfer data directly between RAM and USART registers without CPU intervention!

4.3 The Zephyr Sensor API Subsystem

Zephyr includes a built-in Sensor Subsystem (CONFIG_SENSOR=y) supporting over 150 commercial environmental, inertial, and optical sensors. Instead of parsing raw registers, you interact with standard physical quantities:

C Standard Zephyr Sensor API Usage 
#include <zephyr/drivers/sensor.h>

const struct device *const sensor = DEVICE_DT_GET_ANY(bosch_bmp280);
struct sensor_value temp, press;

/* Trigger sensor conversion and read internal registers */
sensor_sample_fetch(sensor);

/* Extract standardized SI values */
sensor_channel_get(sensor, SENSOR_CHAN_AMBIENT_TEMP, &temp);
sensor_channel_get(sensor, SENSOR_CHAN_PRESS, &press);

printk("Temperature: %d.%06d C | Pressure: %d.%06d kPa\n",
       temp.val1, temp.val2, press.val1, press.val2);

4.4 Hardware PWM Dimming on STM32 Timers

On STM32, hardware Pulse Width Modulation (PWM) is driven by the general-purpose or advanced timer peripherals (TIM1, TIM2, TIM3, etc.). By using Zephyr's pwm_set_dt(), you can smoothly adjust duty cycle with nanosecond or microsecond precision without CPU intervention.

4.5.4 Application Code: samples/04_sensor_i2c_pwm/src/main.c

C samples/04_sensor_i2c_pwm/src/main.c 
/*
 * Copyright (c) 2026 Apt Computing Labs
 * "Where Knowledge Meets Innovation"
 *
 * Mastering Zephyr RTOS on STM32 - Lab 4: Sensor & PWM
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/kernel.h>
#include <zephyr/drivers/sensor.h>
#include <zephyr/drivers/pwm.h>
#include <zephyr/sys/printk.h>

#define PWM_PERIOD_NS   PWM_MSEC(20U) /* 50 Hz PWM period (20ms) */
#define STEP_NS         PWM_USEC(500U)

static const struct pwm_dt_spec pwm_led = PWM_DT_SPEC_GET(DT_ALIAS(pwm_led0));

int main(void)
{
    uint32_t pulse = 0;
    bool dir_up = true;

    printk("\n=== Zephyr Lab 4: I2C Sensor & Hardware PWM Engine ===\n");

    if (!pwm_is_ready_dt(&pwm_led)) {
        printk("Error: PWM device %s not ready!\n", pwm_led.dev->name);
        return 0;
    }

    printk("Starting LED breathing pulse cycle...\n");

    while (1) {
        /* Set PWM pulse width (duty cycle) */
        pwm_set_pulse_dt(&pwm_led, pulse);

        if (dir_up) {
            pulse += STEP_NS;
            if (pulse >= PWM_PERIOD_NS) {
                pulse = PWM_PERIOD_NS;
                dir_up = false;
            }
        } else {
            if (pulse <= STEP_NS) {
                pulse = 0;
                dir_up = true;
            } else {
                pulse -= STEP_NS;
            }
        }

        k_msleep(25);
    }
    return 0;
}
