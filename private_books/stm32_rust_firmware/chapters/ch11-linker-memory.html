Linker Scripts & Memory Layout

How memory.x describes flash and SRAM, what the sections contain and how to check usage.

⏱️ Reading Time: 40 minutes
🛠️ Lab: Read the memory map
🎯 Topics: Linker & Memory

11.1 The STM32F446 Memory Map

You met the memory map in Book 1. The linker needs the same facts, written in a file called memory.x.

Region Start Size Content
Flash 0x0800_0000 512 KB Vector table, code, constants, initial values of variables
SRAM 0x2000_0000 128 KB .data, .bss, stack (and heap if used)
Peripherals 0x4000_0000 - Memory-mapped registers (used through the PAC)
TEXT memory.x 
MEMORY
{
  /* NOTE 1 K = 1 KiBi = 1024 bytes */
  FLASH : ORIGIN = 0x08000000, LENGTH = 512K
  RAM   : ORIGIN = 0x20000000, LENGTH = 128K
}

cortex-m-rt ships a generic linker script link.x that includes your memory.x. That is the Rust counterpart of STM32F446RETx_FLASH.ld.

Where does memory.x go?
In the crate root (next to Cargo.toml), copied to the build directory by a small build.rs. The PAC crates with the rt feature already provide the device.x interrupt names; you only supply memory.x.
RUST build.rs 
use std::{env, fs::File, io::Write, path::PathBuf};

fn main() {
    let out = PathBuf::from(env::var_os("OUT_DIR").unwrap());
    File::create(out.join("memory.x")).unwrap().write_all(include_bytes!("memory.x")).unwrap();
    println!("cargo:rustc-link-search={}", out.display());
    println!("cargo:rerun-if-changed=memory.x");
}

11.2 Sections: Where Your Variables Go

Section Contents Lives in Initialised by
.vector_table Initial SP, reset and exception vectors Flash start Linker
.text Machine code Flash -
.rodata const data, string literals, lookup tables Flash -
.data static with non-zero initial value RAM (copy stored in Flash) cortex-m-rt copies at reset
.bss static initialised to zero RAM cortex-m-rt zeroes at reset
Stack Local variables, call frames Top of RAM, grows down Initial SP in the vector table
RUST Where does each go? 
const LUT: [u16; 4] = [0, 100, 200, 300];   // .rodata (flash) - or inlined as immediates
static BANNER: &str = "boot";               // .rodata
static COUNTER: AtomicU32 = AtomicU32::new(0);   // .bss (zero)
static CALIBRATION: Mutex<Cell<u16>> = Mutex::new(Cell::new(1234));   // .data (non-zero)

fn f() { let local = [0u8; 256]; }          // stack (256 bytes of the 128 KB)

The reset handler in cortex-m-rt does what Reset_Handler in the Book 1 start-up file did: sets the stack pointer, copies .data, zeroes .bss, then calls main.

11.3 Reading the Result

BASH Section sizes and symbols 
cargo size --release -- -A
cargo size --release -- -B
arm-none-eabi-nm -S --size-sort -r target/thumbv7em-none-eabihf/release/app | head
Output Meaning
text Code + read-only data: counts against Flash
data Initialised variables: Flash and RAM
bss Zeroed variables: RAM only
Flash use = text + data RAM use = data + bss + stack

11.4 Stack Overflow: C vs Rust

On Cortex-M the stack grows down toward .bss and .data. Overflowing it silently corrupts your variables - the worst kind of bug.

flip-link is a linker wrapper that swaps the layout: the stack goes at the *bottom* of RAM, so an overflow runs off the end into non-existent memory and raises a HardFault instead of corrupting data.

TOML .cargo/config.toml with flip-link 
[target.thumbv7em-none-eabihf]
linker = "flip-link"
BASH Install 
cargo install flip-link
Stack depth in practice
Avoid large local arrays; make big buffers static. Use defmt or a watermark pattern to measure maximum stack use during testing (fill with 0xDEADBEEF and check how far it was overwritten).

11.5 Placing Data Explicitly

RUST link_section 
#[link_section = ".bss.dma_buf"]
static mut DMA_BUF: [u8; 256] = [0; 256];

On parts with several RAM regions (e.g. CCM, backup SRAM) you add MEMORY entries and SECTIONS in a memory.x extension and use #[link_section] to place data there. Backup SRAM is a good place to keep a panic message across a reset.

11.6 Vector Table and Interrupt Names

cortex-m-rt and the PAC build the vector table. An interrupt handler is just a function with the right name:

RUST Handlers 
use stm32f4xx_hal::pac::interrupt;

#[interrupt]
fn EXTI15_10() { /* button on PC13 */ }

#[cortex_m_rt::exception]
fn SysTick() { /* 1 ms tick */ }

If you forget to define a handler, the default handler loops forever (and DefaultHandler can be overridden to log which interrupt fired).
