Chapter 03 • Digital I/O

GPIO & External Interrupts

Master digital input and output on STM32, then step from polling to interrupt-driven design: EXTI lines, the NVIC, priorities, safe ISR patterns and debouncing.

⏱️ Reading Time: 45 minutes
🛠️ Lab: Interrupt-driven button + LED
🎯 Topics: GPIO, EXTI, NVIC

3.1 Anatomy of a GPIO Pin

Each STM32 port (GPIOA...GPIOH) has up to 16 pins. Every pin can be configured independently:

Mode Use Notes
Input (floating / pull-up / pull-down) Buttons, digital sensors A floating input picks up noise - always pick a pull or have an external one
Output push-pull LEDs, logic signals Drives both high and low
Output open-drain I2C, shared lines, level shifting Only pulls low; needs a pull-up resistor
Alternate function (AF) USART TX, SPI SCK, TIM channels Pin is handed to a peripheral (AF0-AF15)
Analog ADC input, DAC output Digital buffer disconnected, lowest leakage

Output speed (Low, Medium, Fast, High) controls the slew rate. Use the slowest speed that works - fast edges cause EMI and ringing.

NUCLEO-F446RE on-board IO
LD2 user LED is on PA5 (active-high). B1 user button is on PC13 (active-low, external pull-up, pressed = 0). USART2 uses PA2 (TX) / PA3 (RX) routed to the ST-LINK Virtual COM Port.

LED wiring maths

An LED needs about 5-15 mA. With a 3.3 V pin, a red LED (Vf ≈ 2.0 V) and 330 Ω: I = (3.3 − 2.0) / 330 ≈ 3.9 mA - bright enough, and well under the pin's limits. Never exceed 25 mA per pin or the total package limit given in the datasheet.

3.2 Using GPIO with HAL

C GPIO API 
HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_SET);   /* drive high */
HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET); /* drive low  */
HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);

GPIO_PinState s = HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin);  /* GPIO_PIN_RESET when pressed */

In CubeMX, give pins user labels (LD2, B1, MOTOR_EN) - the tool generates LD2_Pin and LD2_GPIO_Port macros so your code never contains GPIOA, GPIO_PIN_5.

What MX_GPIO_Init() does

C Generated GPIO init (abridged) 
__HAL_RCC_GPIOC_CLK_ENABLE();
__HAL_RCC_GPIOA_CLK_ENABLE();

HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);   /* safe initial level */

GPIO_InitTypeDef g = {0};
g.Pin   = LD2_Pin;
g.Mode  = GPIO_MODE_OUTPUT_PP;
g.Pull  = GPIO_NOPULL;
g.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(LD2_GPIO_Port, &g);
Initial output level
Set the output level before switching the pin to output mode (CubeMX has a "GPIO output level" setting). Otherwise motors and relays can glitch for a few microseconds at start-up.

3.3 Polling a Button - and Why It Is Not Enough

C Polling approach 
while (1) {
    if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_RESET) {
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
        HAL_Delay(300);                  /* crude debounce - blocks everything */
    }
}

This works for a demo, but the CPU is stuck inside HAL_Delay and cannot do anything else. Polling wastes cycles, misses short events and cannot sleep. The fix is interrupts.

3.4 Interrupts: The Concept

An interrupt is a hardware event that makes the CPU pause the running code, execute a short interrupt service routine (ISR), then resume exactly where it left off. The CPU hardware saves and restores context for you.

  1. The peripheral raises an interrupt request (e.g. EXTI line 13 detects a falling edge).
  2. The NVIC compares its priority with the running code and, if higher, preempts.
  3. The core pushes registers to the stack, fetches the handler address from the vector table and jumps to it.
  4. The ISR runs and clears the flag.
  5. The core pops registers and resumes.

The vector table lives at the start of Flash. Entry names such as EXTI15_10_IRQHandler are defined in the startup file as weak aliases, so defining a function with that exact name overrides it.

3.5 EXTI and the NVIC

The EXTI (external interrupt/event controller) connects GPIO pins to interrupts. EXTI line *n* can be fed by pin *n* of one port at a time (PA0 or PB0 or PC0, not all at once). Lines 0-4 each have their own handler; lines 5-9 share EXTI9_5_IRQHandler; lines 10-15 share EXTI15_10_IRQHandler. B1 on PC13 therefore uses EXTI15_10_IRQn.

C Enabling EXTI with CubeMX output 
/* CubeMX: PC13 -> GPIO_EXTI13, mode = External Interrupt Mode with Falling edge trigger */

/* generated in gpio.c */
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 5, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);

/* generated in stm32f4xx_it.c */
void EXTI15_10_IRQHandler(void)
{
  HAL_GPIO_EXTI_IRQHandler(B1_Pin);     /* clears flag, calls the callback below */
}

/* your code: override the weak callback (USER CODE 4 in main.c) */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == B1_Pin) {
    button_event = 1;                   /* set a flag, keep the ISR short */
  }
}

Priorities

The F4 implements 4 priority bits. CubeMX uses group 4: all bits are *preemption* priority, 0-15, lower number = more urgent. A higher-priority interrupt can preempt a lower one; equal priority interrupts wait. System exceptions (HardFault, NMI) are always above configurable ones.

SysTick priority and HAL_Delay
HAL_Delay() waits for the SysTick-driven tick counter. If you call it inside an ISR whose priority is the same or *higher* than SysTick, the tick never increments and the firmware hangs forever. Never call HAL_Delay in an ISR - and never use blocking HAL calls there.

3.6 Writing Good ISRs

  1. Keep it short. Do the minimum - read a register, store a value, set a flag - then return.
  2. Defer work. Set a volatile flag, push into a ring buffer, and handle it in main().
  3. No blocking. No HAL_Delay, no long loops, no printf over UART.
  4. Share data safely. Variables shared with main() must be volatile; multi-step updates need a critical section.
  5. Clear the cause. Forgetting to clear the flag makes the ISR re-enter endlessly (HAL does this for you in its IRQHandler).
C Flag-and-process pattern 
static volatile uint8_t button_event = 0;

while (1) {
    if (button_event) {
        button_event = 0;
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    }
    /* other tasks run freely here */
}

/* Critical section for a 32-bit shared counter updated in main and ISR */
uint32_t primask = __get_PRIMASK();
__disable_irq();
shared_counter += 10;
__set_PRIMASK(primask);               /* restore, do not blindly enable */

3.7 Debouncing

Mechanical contacts bounce for 1-20 ms, producing several edges per press. An interrupt on every edge would fire many times. Two solutions:

  • Hardware: RC filter (10 kΩ + 100 nF ≈ 1 ms time constant) with a Schmitt-trigger input.
  • Software: ignore edges for a short time after the first one.
C Time-based software debounce 
#define DEBOUNCE_MS 30U

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  static uint32_t last = 0;
  uint32_t now = HAL_GetTick();

  if (GPIO_Pin == B1_Pin && (now - last) >= DEBOUNCE_MS) {   /* subtraction handles wrap */
    last = now;
    button_event = 1;
  }
}
Press versus release
Trigger on the falling edge for a press (active-low button). For long-press detection, start a timer on the falling edge and measure to the rising edge, or sample the pin periodically in a 1 ms tick.

3.8 Hands-On Lab 3: Interrupt-Driven Button and LED

Build a mode switch: each button press cycles the LED through off → slow blink → fast blink. The blink must run without HAL_Delay, using HAL_GetTick().

C Lab 3 - non-blocking blink with button modes 
typedef enum { MODE_OFF, MODE_SLOW, MODE_FAST, MODE_COUNT } led_mode_t;

static volatile uint8_t button_event;
static led_mode_t mode = MODE_OFF;

/* USER CODE BEGIN 3 (inside while(1)) */
static uint32_t last_toggle;
uint32_t period = (mode == MODE_SLOW) ? 500 : 100;

if (button_event) {
    button_event = 0;
    mode = (led_mode_t)((mode + 1) % MODE_COUNT);
    HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);
}
if (mode != MODE_OFF && (HAL_GetTick() - last_toggle) >= period) {
    last_toggle = HAL_GetTick();
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
}
/* USER CODE END 3 */
