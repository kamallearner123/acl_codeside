Module 23: Hardware Mocking & HAL Emulation

Deep dive into simulating peripheral hardware, link-time function interposition via GNU ld --wrap, memory-mapped I/O (MMIO) register emulation in host RAM, and synthetic asynchronous interrupt injection.

⏱️ Duration: 50m
🎯 Standard: POSIX / GNU ld Linker Interposition
⚡ Target: Linux x86_64 Host Testing

23.1 The Silicon Dependency Dilemma

In embedded C, drivers interact directly with hardware through physical memory addresses: 

#define USART1_BASE  (0x40011000UL)
#define USART1_DR    (*(volatile uint32_t *)(USART1_BASE + 0x04))

void uart_send_char(char c) {
    USART1_DR = (uint32_t)c; /* Crashes on x86 Linux! */
}

If you compile and execute this code on an x86 development PC, the CPU encounters address 0x40011000UL. Because this physical address is not mapped into the user-space process's virtual memory page tables, the MMU triggers an immediate Page Fault, terminating the test suite with SIGSEGV (Segmentation Fault).

23.2 Hardware Emulation Strategies

Three primary design patterns allow hardware drivers to execute flawlessly on host development platforms:

Hardware Mocking Architectures Compared
Strategy 1: Virtual Memory Struct Redirection
  #ifdef HOST_TEST
    static USART_TypeDef virtual_usart;
    #define USART1 (&virtual_usart)
  #else
    #define USART1 ((USART_TypeDef *)0x40011000UL)
  #endif

Strategy 2: Link-Time Interposition (GNU ld --wrap)
  Production Call: HAL_I2C_Transmit(...) ──▶ Linker redirects to ──▶ __wrap_HAL_I2C_Transmit(...)
  Original Call:   Can still invoke __real_HAL_I2C_Transmit(...) if needed.

Strategy 3: Dependency Injection via VTable (OOP Interface)
  Application ──▶ [ i2c_bus_ops_t *bus ] ──▶ Real Driver: stm32_i2c_write()
                                        └──▶ Mock Driver: mock_i2c_write()

23.3 Link-Time Wrapping with GNU ld (--wrap)

The most powerful, non-invasive mocking technique supported by the GNU linker is symbol wrapping (-Wl,--wrap=<symbol>). This requires zero modifications to your production C source code!

When you link with -Wl,--wrap=HAL_I2C_Master_Transmit:

  1. Any call to HAL_I2C_Master_Transmit is resolved to __wrap_HAL_I2C_Master_Transmit.
  2. The original implementation remains accessible via the synthetic symbol __real_HAL_I2C_Master_Transmit.

Production Linker Wrap Example

/* mock_i2c.c */
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

/* Capture structures for assertions */
typedef struct {
    uint16_t dev_addr;
    uint8_t  last_data[64];
    uint16_t last_size;
    uint32_t call_count;
    int      injected_return_code;
} i2c_mock_state_t;

static i2c_mock_state_t g_i2c_mock = {0};

void mock_i2c_reset(void) {
    memset(&g_i2c_mock, 0, sizeof(g_i2c_mock));
}

void mock_i2c_inject_error(int err) {
    g_i2c_mock.injected_return_code = err;
}

/* Intercepted function! */
int __wrap_HAL_I2C_Master_Transmit(void *hi2c, uint16_t DevAddress, uint8_t *pData, uint16_t Size, uint32_t Timeout) {
    (void)hi2c;
    (void)Timeout;
    g_i2c_mock.call_count++;
    g_i2c_mock.dev_addr = DevAddress;
    g_i2c_mock.last_size = Size;
    if (Size <= sizeof(g_i2c_mock.last_data)) {
        memcpy(g_i2c_mock.last_data, pData, Size);
    }
    return g_i2c_mock.injected_return_code;
}

23.4 Simulating Asynchronous Interrupts

Testing interrupt-driven protocols (such as UART DMA ring buffers) requires testing how the driver behaves when an interrupt fires midway through a calculation.

On host platforms, we can simulate interrupts synchronously by directly invoking the ISR function pointer: 

void test_uart_rx_overflow_recovery(void) {
    uart_driver_init();

    /* Simulate 10 rapid UART RX interrupts firing from hardware */
    for (int i = 0; i < 10; i++) {
        /* Inject fake received byte into virtual hardware register */
        VIRTUAL_UART->DR = (uint32_t)('A' + i);
        /* Directly trigger the interrupt service routine */
        USART1_IRQHandler();
    }

    TEST_ASSERT_EQUAL_UINT32(10, uart_get_rx_count());
}

23.5 Industrial Case Study: Implantable Cardiac Defibrillator Simulation

Validating Arrhythmia Detection Algorithms via Synthesized Signals

An implantable cardioverter-defibrillator (ICD) monitors cardiac electrical activity (ECG) and delivers a high-voltage electrical shock to defibrillate the heart during ventricular fibrillation.

The Engineering Challenge: Testing defibrillation algorithms cannot be done on live animal models for every code commit. Furthermore, validating brownout recovery when the battery voltage sags from 3.2V to 2.1V during capacitor charging cannot be done on evaluation boards without permanently damaging micro-batteries.

The Virtual HAL Solution: The engineering team implemented a host-compiled virtual ADC and virtual Power Management IC (PMIC). The host test suite injected recorded human clinical ECG waveforms (from the MIT-BIH Arrhythmia Database) through the virtual ADC at 10,000 samples per second.

The test harness verified:

  • Ventricular fibrillation was detected in under 1.2 seconds across 5,000 distinct patient waveforms.
  • Simulated battery impedance sags never triggered unhandled CPU resets.
  • Zero false-positive shock commands were issued during sinus tachycardia.

23.6 Hands-On Lab: Implementing GNU ld --wrap for an I2C Sensor Driver

In this lab, you will write a complete, standalone C temperature sensor driver, create a mock using GNU linker symbol wrapping, and test both success and bus-error recovery branches.

1. Sensor Driver Header (sensor_i2c.h)

#ifndef SENSOR_I2C_H_
#define SENSOR_I2C_H_

#include <stdint.h>
#include <stdbool.h>

#define TEMP_SENSOR_I2C_ADDR (0x90U)

/* Declared HAL function (to be wrapped during host tests) */
int HAL_I2C_Master_Transmit(uint16_t addr, const uint8_t *data, uint16_t len);
int HAL_I2C_Master_Receive(uint16_t addr, uint8_t *data, uint16_t len);

/* Production Driver API */
int sensor_read_temperature_mC(int32_t *out_mC);

#endif /* SENSOR_I2C_H_ */

2. Production Driver Implementation (sensor_i2c.c)

#include "sensor_i2c.h"

int sensor_read_temperature_mC(int32_t *out_mC) {
    if (!out_mC) return -1;

    uint8_t reg = 0x00; // Temperature register pointer
    if (HAL_I2C_Master_Transmit(TEMP_SENSOR_I2C_ADDR, &reg, 1) != 0) {
        return -2; // I2C Bus Error on write
    }

    uint8_t raw[2] = {0};
    if (HAL_I2C_Master_Receive(TEMP_SENSOR_I2C_ADDR, raw, 2) != 0) {
        return -3; // I2C Bus Error on read
    }

    /* Convert 12-bit raw value to milli-Celsius (0.0625 deg C per LSB) */
    int16_t raw_temp = (int16_t)((raw[0] << 8) | raw[1]) >> 4;
    *out_mC = (int32_t)raw_temp * 625 / 10;
    return 0; // Success
}

3. Host Test Harness with __wrap (test_sensor.c)

#include <stdio.h>
#include <assert.h>
#include <string.h>
#include "sensor_i2c.h"

static int g_injected_tx_error = 0;
static int g_injected_rx_error = 0;
static uint8_t g_fake_rx_bytes[2] = {0x19, 0x00}; // 25.0 deg C

/* Intercepted Transmit */
int __wrap_HAL_I2C_Master_Transmit(uint16_t addr, const uint8_t *data, uint16_t len) {
    (void)addr; (void)data; (void)len;
    return g_injected_tx_error;
}

/* Intercepted Receive */
int __wrap_HAL_I2C_Master_Receive(uint16_t addr, uint8_t *data, uint16_t len) {
    (void)addr;
    if (g_injected_rx_error != 0) return g_injected_rx_error;
    memcpy(data, g_fake_rx_bytes, len);
    return 0;
}

int main(void) {
    int32_t temp_mC = 0;

    /* Test Case 1: Successful read */
    g_injected_tx_error = 0;
    g_injected_rx_error = 0;
    int status = sensor_read_temperature_mC(&temp_mC);
    assert(status == 0);
    assert(temp_mC == 25000); // 25.0 C
    printf("[PASS] Nominal temperature read (25000 mC)
");

    /* Test Case 2: Bus Error on Transmit */
    g_injected_tx_error = -1;
    status = sensor_read_temperature_mC(&temp_mC);
    assert(status == -2);
    printf("[PASS] Handled Transmit Bus Error cleanly
");

    /* Test Case 3: Bus Error on Receive */
    g_injected_tx_error = 0;
    g_injected_rx_error = -1;
    status = sensor_read_temperature_mC(&temp_mC);
    assert(status == -3);
    printf("[PASS] Handled Receive Bus Error cleanly
");

    printf("
All hardware mock assertions passed successfully!
");
    return 0;
}

Build & Execute Commands

# Link with GNU ld --wrap flags
gcc -Wall -Wextra sensor_i2c.c test_sensor.c     -Wl,--wrap=HAL_I2C_Master_Transmit     -Wl,--wrap=HAL_I2C_Master_Receive     -o test_sensor

./test_sensor
# Output:
# [PASS] Nominal temperature read (25000 mC)
# [PASS] Handled Transmit Bus Error cleanly
# [PASS] Handled Receive Bus Error cleanly

23.7 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: What happens when an x86 Linux process attempts to dereference a physical ARM peripheral register address like 0x40011000?

Explanation: On operating systems with virtual memory management (x86/x64 Linux), physical address spaces are not mapped into user space by default; attempting to dereference unmapped addresses triggers an immediate segmentation fault.

Q2: What GNU linker flag instructs the linker to resolve calls to foo() to __wrap_foo()?

Explanation: --wrap=<symbol> is a standard feature of GNU ld that interposes wrapper functions around unresolved symbol references at link time.

Q3: Inside a wrapper function __wrap_read(), how can the code invoke the actual underlying original system implementation of read()?

Explanation: When --wrap=symbol is enabled, GNU ld maps the original symbol definition to __real_symbol, allowing wrappers to forward calls when needed.

Q4: What is the primary benefit of link-time function wrapping over compile-time preprocessor macro replacement?

Explanation: Linker wrapping acts upon compiled object files; production code remains pristine, clean, and free of test-specific preprocessor spaghetti.

Q5: How can an ISR be safely tested in a single-threaded host unit test?

Explanation: In C, an ISR is simply a function with void (*)(void) signature; invoking it synchronously allows deterministic validation of internal buffer mutations.
