Module 7: Pointers & Memory Architecture Fundamentals

Master virtual vs. physical address spaces, hardware word alignment, strict aliasing rules, bus faults, and defensive pointer validation in safety-critical systems.

⏱️ Duration: 60m
🎯 System: Memory Layout, Bus Faults, MISRA C:2012
⚡ Architecture: ARM Cortex-M / Linux x86_64

7.1 Memory Architecture: Virtual vs Physical Address Spaces

To write robust, safe, high-performance C code, an engineer must first understand what a memory address actually represents on target hardware: 

+-------------------------------------------------------------------------+
|                  VIRTUAL MEMORY (Linux POSIX x86_64 / ARM64)            |
|  [0x0000000000000000] - Unmapped (NULL Pointer Trap Page)               |
|  [0x0000000000400000] - .text (Executable Code)                         |
|  [0x0000000000600000] - .rodata, .data, .bss                            |
|  [0x00007FFFF7000000] - mmap / Shared Libraries / Heap                   |
|  [0x00007FFFFFFFE000] - User Stack (Grows Downward)                     |
|  [0xFFFF800000000000] - Linux Kernel Memory Space (Ring 0)              |
+-------------------------------------------------------------------------+
|              FLAT PHYSICAL MEMORY (ARM Cortex-M Bare-Metal MCU)         |
|  0x0000_0000 : Aliased to FLASH / System Memory / Bootloader            |
|  0x0800_0000 : Main Flash ROM (Vector Table, .text, .rodata)            |
|  0x2000_0000 : Main SRAM (Data, BSS, Stack, Heap)                       |
|  0x4000_0000 : Peripherals MMIO (GPIO, UART, SPI, I2C, Timers)         |
|  0xE000_0000 : ARM Cortex-M System Control Space (NVIC, SysTick, MPU)   |
+-------------------------------------------------------------------------+

In a hosted OS like Linux, the Memory Management Unit (MMU) translates virtual addresses to physical pages. Accessing address 0x00000000 generates a Page Fault, triggering a SIGSEGV. In contrast, on a microcontroller like STM32 (ARM Cortex-M), addresses directly map to internal bus interconnects (AHB/APB). Reading an invalid or unclocked peripheral address triggers a hardware BusFault or HardFault exception!

7.2 Pointer Representation, Word Alignment & Bus Faults

A pointer variable holds a memory address. The width of a pointer depends strictly on the target CPU architecture:

  • 32-bit Architecture (ARM Cortex-M3/M4/M7, 32-bit Linux): sizeof(void*) == 4 bytes (32 bits).
  • 64-bit Architecture (x86_64, AArch64): sizeof(void*) == 8 bytes (64 bits).
Hardware Alignment Rule: On ARM Cortex-M0/M0+, accessing a 32-bit integer at an unaligned address (e.g., 0x20000001) causes an immediate hardware UsageFault / HardFault. While Cortex-M3/M4/M7 can be configured to support unaligned access, it takes multiple bus cycles and is non-atomic.
Calignment_fault_demo.c
#include <stdint.h>
#include <stdio.h>

void trigger_unaligned_access(void) {
    uint8_t buffer[8] = { 0x11, 0x22, 0x33, 0x44, 0x55, 0x66, 0x77, 0x88 };

    /* Perfectly aligned access: 4-byte boundary */
    uint32_t *aligned_ptr = (uint32_t *)&buffer[0];
    printf("Aligned read: 0x%08X\n", *aligned_ptr);

    /* Dangerous unaligned access: address ends in 1, 2, or 3 */
    uint32_t *unaligned_ptr = (uint32_t *)&buffer[1];
    
    /* On ARM Cortex-M0 or when UNALIGN_TRP is enabled in CCR register:
     * This next line triggers a fatal Hardware HardFault! */
    printf("Unaligned read: 0x%08X\n", *unaligned_ptr);
}

7.3 Strict Aliasing Rules & Type-Punning

Under the ISO C99/C11 standards (and enforced strictly by GCC/Clang with -O2 / -O3), the Strict Aliasing Rule dictates that two pointers of different types cannot point to the same memory location, except if one is char*, uint8_t*, or void*.

Cstrict_aliasing_violation.c (Dangerous vs Safe)
#include <stdint.h>
#include <string.h>

/* ❌ UNDEFINED BEHAVIOR: Violates strict aliasing rule */
uint32_t bad_float_to_raw_bits(float f) {
    /* The compiler assumes a uint32_t pointer cannot alias a float pointer.
     * With -O2, GCC may reorder or eliminate memory loads, returning garbage! */
    return *(uint32_t *)&f;
}

/* ✅ CORRECT & MISRA-COMPLIANT: Using memcpy */
uint32_t safe_float_to_raw_bits(float f) {
    uint32_t bits;
    /* GCC compiles memcpy of small scalar types into a single register move! */
    memcpy(&bits, &f, sizeof(bits));
    return bits;
}

/* ✅ ALTERNATIVE: Safe Type-Punning using a Union */
typedef union {
    float    f_val;
    uint32_t u_val;
} FloatPunning_t;

uint32_t union_float_to_raw_bits(float f) {
    FloatPunning_t p;
    p.f_val = f;
    return p.u_val; /* Explicitly permitted in C99 TC3 / C11 Annex J */
}

7.4 Real-Time Systems Case: Defensive Pointer Validation

In automotive ECUs (ISO 26262 ASIL-D) and medical devices (IEC 62304 Class C), pointers received from external callers or inter-module boundaries must be validated defensively before dereferencing:

Csafe_sensor_driver.c
#include <stdint.h>
#include <stdbool.h>

#define SENSOR_MAGIC_SIGNATURE 0xCAFEBABEUL
#define RAM_START_ADDR         0x20000000UL
#define RAM_END_ADDR           0x2001FFFFUL  /* 128 KB SRAM */

typedef struct {
    uint32_t signature;       /* Memory canary to detect corruption */
    uint16_t sensor_id;
    float    last_temperature;
    bool     is_calibrated;
} SensorHandle_t;

typedef enum {
    DRIVER_OK                 = 0,
    DRIVER_ERR_NULL_PTR       = -1,
    DRIVER_ERR_UNALIGNED_PTR  = -2,
    DRIVER_ERR_OUT_OF_RANGE   = -3,
    DRIVER_ERR_CORRUPT_OBJECT = -4
} DriverStatus_t;

DriverStatus_t sensor_read_sample(const SensorHandle_t *handle, float *out_temp) {
    /* Step 1: Null check */
    if ((handle == NULL) || (out_temp == NULL)) {
        return DRIVER_ERR_NULL_PTR;
    }

    /* Step 2: Alignment verification (must be 4-byte aligned on 32-bit MCU) */
    if (((uintptr_t)handle & 0x03UL) != 0UL) {
        return DRIVER_ERR_UNALIGNED_PTR;
    }

    /* Step 3: Range check - ensure pointer actually resides in valid SRAM */
    uintptr_t addr = (uintptr_t)handle;
    if ((addr < RAM_START_ADDR) || (addr + sizeof(SensorHandle_t) > RAM_END_ADDR)) {
        return DRIVER_ERR_OUT_OF_RANGE;
    }

    /* Step 4: Canary integrity check */
    if (handle->signature != SENSOR_MAGIC_SIGNATURE) {
        return DRIVER_ERR_CORRUPT_OBJECT;
    }

    *out_temp = handle->last_temperature;
    return DRIVER_OK;
}
