Module 37: RTOS Fundamentals & FreeRTOS Internals

Deep dive into real-time operating system kernel architecture on ARM Cortex-M. Master SysTick, PendSV, and SVC context switching mechanics, dual-stack pointers (MSP vs PSP), task control blocks (TCBs), FreeRTOS queues, semaphores, mutex priority inheritance, and the critical FromISR rules.

⏱️ Duration: 70m
🎯 Standard: FreeRTOS V10.x+ / ARM CMSIS-RTOS2
⚡ Target: Hard Real-Time ARM Cortex-M Firmware

37.1 Hard vs. Soft Real-Time & Determinism

A common misconception is that a Real-Time Operating System (RTOS) makes code execute faster. An RTOS does not guarantee high speed; it guarantees mathematical determinism!

  • Hard Real-Time: Missing a deadline constitutes a total system failure (e.g., deploying an automotive airbag within 15 ms, pacemaker cardiac pacing).
  • Soft Real-Time: Missing a deadline degrades quality of service but does not cause catastrophic damage (e.g., video streaming frame drop).

37.2 Preemptive Context Switching on ARM Cortex-M

How does FreeRTOS switch execution between two tasks without an MMU? Cortex-M silicon provides three dedicated architectural features designed explicitly for RTOS kernels:

Cortex-M Dual Stack & Context Switch Pipeline
1. Dual Stack Pointers:
   MSP (Main Stack Pointer): Used exclusively by OS Kernel & Hardware Interrupt ISRs.
   PSP (Process Stack Pointer): Used exclusively by User RTOS Tasks (Thread Mode).

2. Context Switch Trigger (SysTick -> PendSV):
   [ Running Task A (PSP) ]
             │
             ├──▶ [ SysTick Interrupt (1 kHz) ] ──▶ Decides Task B should run
             │                                       Pends PendSV exception (lowest priority!)
             │                                       Returns to Task A immediately
             ▼
   [ PendSV Exception Executes ] (Runs when NO other ISRs are active!)
     ├── Hardware automatically pushed: R0-R3, R12, LR, PC, xPSR onto Task A's stack
     ├── PendSV software handler pushes: R4-R11 onto Task A's stack
     ├── Saves Task A's SP into Task A's TCB (Task Control Block)
     ├── Loads Task B's SP from Task B's TCB
     ├── Pops: R4-R11 from Task B's stack
     └── Returns from exception (EXC_RETURN) ──▶ Hardware pops R0-R3, R12, LR, PC, xPSR
                                                 Execution resumes seamlessly in Task B!

37.3 The Critical FromISR API Rules

In FreeRTOS, every queue, semaphore, and notification API comes in two distinct variants:

  • Standard API (e.g. xQueueSend(), xSemaphoreGive()): May only be called from Task context. These functions can block and put the calling task to sleep.
  • FromISR API (e.g. xQueueSendFromISR(), xSemaphoreGiveFromISR()): Must be used inside Interrupt Service Routines. These functions can NEVER block!

Immediate Preemption upon ISR Exit

If an ISR wakes up a higher-priority task, the ISR must request a context switch before returning using portYIELD_FROM_ISR(): 

void USART1_IRQHandler(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    uint8_t byte = (uint8_t)USART1->DR;

    /* Push byte to queue; do NOT block! */
    xQueueSendFromISR(g_uart_queue, &byte, &xHigherPriorityTaskWoken);

    /* If consumer task has higher priority, trigger immediate context switch! */
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

37.4 Industrial Case Study: Autonomous AGV Steering Jitter

The 50 ms Mutex Deadlock on Factory Floor Vehicles

An autonomous guided vehicle (AGV) in a distribution warehouse experienced periodic violent steering twitching when navigating optical floor markers.

Investigation: The AGV executed FreeRTOS. The LiDAR obstacle detection task (Priority 2) and the Motor Control task (Priority 5) shared an internal CAN bus transmission mutex.

The developers created the mutex using: 

g_can_lock = xSemaphoreCreateBinary(); /* Missing Priority Inheritance! */

Because a binary semaphore was used instead of a true Mutex (xSemaphoreCreateMutex()), the system suffered classic Priority Inversion. A telemetry WiFi logging task (Priority 3) preempted the LiDAR task while it held the CAN lock, delaying the Motor Control task by 50 ms.

Resolution: Converted the synchronization object to xSemaphoreCreateMutex(), enabling FreeRTOS priority inheritance and eliminating steering jitter.

37.5 Hands-On Lab: FreeRTOS Producer-Consumer Sensor Pipeline

In this laboratory, you will implement a multi-task FreeRTOS architecture featuring a sensor polling task, a thread-safe message queue, and a high-priority telemetry transmitter task.

Complete FreeRTOS Application (freertos_app.c)

#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include <stdio.h>

typedef struct {
    uint32_t sample_id;
    int16_t  temperature;
} sensor_msg_t;

static QueueHandle_t g_sensor_queue = NULL;

void vSensorTask(void *pvParameters) {
    sensor_msg_t msg = {0};
    TickType_t xLastWakeTime = xTaskGetTickCount();
    const TickType_t xFrequency = pdMS_TO_TICKS(100); // 10 Hz exact

    for (;;) {
        vTaskDelayUntil(&xLastWakeTime, xFrequency); // Strict periodic execution
        msg.sample_id++;
        msg.temperature = 245; // 24.5 C

        /* Send to queue, wait up to 10 ms if full */
        xQueueSend(g_sensor_queue, &msg, pdMS_TO_TICKS(10));
    }
}

void vTelemetryTask(void *pvParameters) {
    sensor_msg_t received_msg;
    for (;;) {
        /* Block indefinitely until a sensor reading arrives */
        if (xQueueReceive(g_sensor_queue, &received_msg, portMAX_DELAY) == pdPASS) {
            printf("[TELEMETRY] Transmitted Sample #%u: Temp=%d
",
                   received_msg.sample_id, received_msg.temperature);
        }
    }
}

int main(void) {
    g_sensor_queue = xQueueCreate(8, sizeof(sensor_msg_t));

    xTaskCreate(vSensorTask, "Sensor", configMINIMAL_STACK_SIZE + 128, NULL, 2, NULL);
    xTaskCreate(vTelemetryTask, "Telem", configMINIMAL_STACK_SIZE + 128, NULL, 3, NULL);

    vTaskStartScheduler(); // Starts FreeRTOS Kernel!

    for (;;); // Should never reach here
}

37.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why does FreeRTOS execute context switches inside the PendSV exception handler rather than directly inside the SysTick handler?

Explanation: Deferring context switching to PendSV prevents preempting active interrupt service routines, avoiding nested stack corruption.

Q2: What is the primary functional difference between a FreeRTOS Binary Semaphore and a Mutex?

Explanation: FreeRTOS mutexes implement priority inheritance and strict ownership semantics; binary semaphores are intended for task synchronization and lack priority inheritance.

Q3: What stack pointer register is actively used when a Cortex-M core is executing in Thread mode running a FreeRTOS user task?

Explanation: FreeRTOS configures user tasks to run with PSP; interrupts and OS kernel startup execute with MSP.

Q4: What happens if an engineer calls standard xQueueSend() with a non-zero timeout inside an Interrupt Service Routine?

Explanation: ISRs must never block; only non-blocking FromISR variants may be called from interrupt handlers.

Q5: What function guarantees strict, drift-free periodic execution of an RTOS task?

Explanation: vTaskDelayUntil() calculates delays relative to the previous wake time, avoiding cumulative timing drift caused by task execution duration.
