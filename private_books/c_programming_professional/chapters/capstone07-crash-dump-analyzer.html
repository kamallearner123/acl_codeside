Capstone 7: Post-Mortem Crash Dump Diagnostic Engine

Build an embedded black-box flight recorder for ARM Cortex-M HardFaults. Capture stacked CPU registers in assembly, decode Configurable Fault Status Registers (CFSR/HFSR/BFAR), persist crash dumps to battery-backed SRAM, and resolve faulting source lines using addr2line.

⏱️ Duration: 90m
🎯 Standard: ARMv7-M Fault Architecture / CMSIS SCB
⚡ Target: Field HardFault Diagnostic Automation

1. Anatomy of an ARM Cortex-M HardFault

When an ARM processor encounters an illegal operation (e.g. executing non-Thumb code, unaligned memory access with traps enabled, or dereferencing unmapped memory), the core traps into HardFault_Handler.

Hardware Exception Stack Frame on HardFault
Top of Active Stack (MSP or PSP depending on EXC_RETURN bit 2):
SP + 0x00: [ Stacked R0   ]
SP + 0x04: [ Stacked R1   ]
SP + 0x08: [ Stacked R2   ]
SP + 0x0C: [ Stacked R3   ]
SP + 0x10: [ Stacked R12  ]
SP + 0x14: [ Stacked LR   ] (Link Register: Caller function return address!)
SP + 0x18: [ Stacked PC   ] (Program Counter: Exact faulting instruction address!)
SP + 0x1C: [ Stacked xPSR ] (Program Status Register)

2. HardFault Assembly Extractor & C Decoder

#include <stdint.h>

typedef struct {
    uint32_t r0;
    uint32_t r1;
    uint32_t r2;
    uint32_t r3;
    uint32_t r12;
    uint32_t lr;
    uint32_t pc;
    uint32_t xpsr;
    uint32_t cfsr;
    uint32_t hfsr;
    uint32_t bfar;
} crash_dump_t;

/* Preserved in battery-backed SRAM across resets */
__attribute__((section(".noinit")))
crash_dump_t g_last_crash_dump;

void hard_fault_handler_c(uint32_t *stacked_regs) {
    g_last_crash_dump.r0   = stacked_regs[0];
    g_last_crash_dump.r1   = stacked_regs[1];
    g_last_crash_dump.r2   = stacked_regs[2];
    g_last_crash_dump.r3   = stacked_regs[3];
    g_last_crash_dump.r12  = stacked_regs[4];
    g_last_crash_dump.lr   = stacked_regs[5];
    g_last_crash_dump.pc   = stacked_regs[6];
    g_last_crash_dump.xpsr = stacked_regs[7];

    /* System Control Block Status Registers */
    volatile uint32_t *cfsr = (volatile uint32_t *)0xE000ED28;
    volatile uint32_t *hfsr = (volatile uint32_t *)0xE000ED2C;
    volatile uint32_t *bfar = (volatile uint32_t *)0xE000ED38;

    g_last_crash_dump.cfsr = *cfsr;
    g_last_crash_dump.hfsr = *hfsr;
    g_last_crash_dump.bfar = *bfar;

    /* Issue hardware system reset */
    volatile uint32_t *aircr = (volatile uint32_t *)0xE000ED0C;
    *aircr = (0x5FAUL << 16) | (1UL << 2); // Request SYSRESETREQ
    while (1);
}

/* Assembly entry point to determine MSP vs PSP */
__attribute__((naked))
void HardFault_Handler(void) {
    __asm__ volatile(
        "tst lr, #4
"
        "ite eq
"
        "mrseq r0, msp
"
        "mrsne r0, psp
"
        "b hard_fault_handler_c
"
    );
}

3. Capstone Knowledge Verification Quiz

Self-Assessment Check

Q1: How can an engineer determine whether the fault occurred on MSP or PSP inside HardFault_Handler?

Explanation: In ARM Cortex-M architecture, bit 2 of EXC_RETURN (stored in LR upon entering the handler) encodes the active stack pointer prior to the exception.
