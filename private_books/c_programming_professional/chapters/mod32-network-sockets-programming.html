Module 32: Network Sockets Programming

Master production network programming in C. Deep dive into the TCP state machine, socket options (SO_REUSEADDR, TCP_NODELAY), endianness and binary wire protocols (network byte order), framing over streaming TCP sockets, and struct packing hazards across heterogeneous platforms.

⏱️ Duration: 60m
🎯 Standard: POSIX Sockets / RFC 793 (TCP) / RFC 9293
⚡ Target: Networked Embedded Systems & Servers

32.1 TCP Byte Streams vs. Packet Boundaries

The most prevalent defect in beginner socket programming is assuming that a single write() on the sender corresponds to a single read() on the receiver.

TCP is a Streaming Protocol: TCP has no concept of message boundaries! If a client calls write(sock, buf, 100) three times, the receiver’s read() might return 50 bytes on the first call, 200 bytes on the second, and 50 bytes on the third. Sockets must implement application-level framing!
Length-Prefixed Binary Wire Framing
Binary Stream on the Wire:
┌──────────────────────┬──────────────────────┬──────────────────────┬──────────────────────┐
│ Magic Code (2 Bytes) │ Payload Len (2 Bytes)│ Payload Data (N Bytes│ CRC16 (2 Bytes)      │
│ 0xAA 0x55            │ 0x00 0x08 (8 bytes)  │ [ 8 Bytes of Telemetry ] │ 0x4B 0x12        │
└──────────────────────┴──────────────────────┴──────────────────────┴──────────────────────┘
 Receiver reads EXACTLY 4 bytes first -> Decodes Length -> Loops until N+2 bytes read!

32.2 Endianness & Binary Wire Serialization

Network protocols standardize on Big-Endian (Network Byte Order: most significant byte transmitted first). Modern client processors (x86, ARM Cortex-M) are predominantly Little-Endian.

Never cast raw memory structs directly onto network sockets without endianness conversion:

  • htons() / ntohs(): Host-to-Network / Network-to-Host for 16-bit integers.
  • htonl() / ntohl(): Host-to-Network / Network-to-Host for 32-bit integers.

Struct Packing Hazards

Different compiler ABIs insert padding bytes to align struct members to 4-byte or 8-byte boundaries. If transmitting a struct over the wire, packing must be enforced: 

#pragma pack(push, 1)
typedef struct {
    uint16_t magic;      /* 2 bytes */
    uint16_t length;     /* 2 bytes */
    uint32_t timestamp;  /* 4 bytes (Packed: zero padding bytes!) */
} __attribute__((packed)) wire_header_t;
#pragma pack(pop)

32.3 Socket Options: SO_REUSEADDR & TCP_NODELAY

Two essential socket options are required for production network servers:

  1. SO_REUSEADDR: Bypasses the TIME_WAIT state, allowing immediate re-binding to a local port when a daemon is restarted.
  2. TCP_NODELAY: Disables Nagle’s Algorithm. Nagle’s algorithm buffers small outgoing packets to minimize header overhead; in real-time telemetry or robotics control, Nagle’s delay introduces up to 200 ms of intolerable latency!

32.4 Industrial Case Study: Medical Infusion Pump Packet Fragmentation

The Fragmented Dosage Telemetry Failure

A hospital bedside infusion pump transmitting real-time insulin infusion rates to a central nurses' station displayed sporadic "Corrupt Dosage Rate: 0.0 mg/h" alarms.

Investigation: The pump transmitted a 24-byte telemetry structure every 100 milliseconds. The hospital network switch experienced MTU fragmentation during a backup transfer.

The receiver code executed: 

/* Faulty Assumption: 1 read() == 1 full packet */
ssize_t bytes = read(sock_fd, &telemetry, sizeof(telemetry));
if (bytes > 0) {
    display_dosage(telemetry.dosage_rate); /* Reads half-filled struct! */
}

When network congestion caused TCP to split the 24-byte message into two 12-byte fragments, the receiver parsed the first 12 bytes immediately, reading uninitialized zeroes for the dosage rate!

The Fix: The protocol was refactored with a 4-byte header containing a length field, and the receiver was rewritten with an exact-length framing loop.

32.5 Hands-On Lab: Framing Client & Server in C

In this lab, you will construct a production-grade binary protocol parser that sends and receives length-prefixed binary telemetry frames over a TCP socket.

Robust Framing Helper (wire_protocol.c)

#include <stdio.h>
#include <stdint.h>
#include <unistd.h>
#include <arpa/inet.h>

#define MAGIC_HEADER 0xA55A

#pragma pack(push, 1)
typedef struct {
    uint16_t magic;
    uint16_t length;
} frame_header_t;
#pragma pack(pop)

/* Helper: Read exact number of bytes regardless of TCP fragmentation */
int read_exact(int fd, void *buf, size_t len) {
    char *ptr = (char *)buf;
    size_t remaining = len;
    while (remaining > 0) {
        ssize_t n = read(fd, ptr, remaining);
        if (n <= 0) return -1; // Connection closed or error
        ptr += n;
        remaining -= (size_t)n;
    }
    return 0; // Exactly len bytes read!
}

/* Helper: Send framed binary message */
int send_framed_packet(int fd, const void *payload, uint16_t payload_len) {
    frame_header_t hdr;
    hdr.magic = htons(MAGIC_HEADER);
    hdr.length = htons(payload_len);

    if (write(fd, &hdr, sizeof(hdr)) != sizeof(hdr)) return -1;
    if (write(fd, payload, payload_len) != payload_len) return -1;
    return 0;
}

/* Helper: Receive framed binary message */
int receive_framed_packet(int fd, void *out_buf, uint16_t max_buf_len, uint16_t *out_payload_len) {
    frame_header_t hdr;
    if (read_exact(fd, &hdr, sizeof(hdr)) != 0) return -1;

    uint16_t magic = ntohs(hdr.magic);
    uint16_t len = ntohs(hdr.length);

    if (magic != MAGIC_HEADER || len > max_buf_len) return -2; // Corrupt frame

    if (read_exact(fd, out_buf, len) != 0) return -3;
    *out_payload_len = len;
    return 0; // Success!
}

32.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: What network byte order is standard across internet protocols such as TCP/IP?

Explanation: Internet standards dictate Big-Endian (most significant byte first) as the canonical Network Byte Order.

Q2: What is the primary purpose of disabling Nagle’s algorithm via TCP_NODELAY?

Explanation: Nagle buffers small segments to combine them into single MTUs; disabling it via TCP_NODELAY provides sub-millisecond latency for real-time telemetry.

Q3: Why can a single read() on a TCP stream socket return fewer bytes than were sent in a single write()?

Explanation: TCP guarantees ordered, reliable byte stream delivery, but preserves no delineation of application message boundaries.

Q4: What socket option allows an application to immediately bind to a port that is currently in the TIME_WAIT state?

Explanation: SO_REUSEADDR allows daemons to restart and re-bind their listening port immediately without waiting 60-120 seconds for TIME_WAIT sockets to expire.

Q5: What compiler attribute eliminates automatic padding bytes between struct members?

Explanation: __attribute__((packed)) instructs GCC to pack struct members with minimum byte alignment, preventing architecture-specific padding from altering wire serialization layouts.
