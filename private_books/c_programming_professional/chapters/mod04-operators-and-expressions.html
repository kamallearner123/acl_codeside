Module 4: Operators, Expressions & Bitwise Systems Engineering

Deconstruct operators at the hardware ALU layer: exploit ARM barrel shifters, master register bitmasking idioms (set, clear, toggle, test), eliminate shift undefined behavior, avoid lethal precedence traps, and write atomic GPIO drivers using the BSRR register.

⏱️ Estimated Reading: 60 min
🎯 Standard: C99 / C11 / C17 / MISRA C:2012
🛠️ Environments: Linux POSIX + ARM Cortex-M

4.1 Operators as Hardware ALU Operations & The Barrel Shifter

In higher-level languages, operators are abstract syntactic constructs. In systems C and embedded firmware, every operator maps directly to discrete hardware components within the CPU's Arithmetic Logic Unit (ALU). On modern RISC processors such as the ARM Cortex-M4 / Cortex-M7, mathematical operations are heavily influenced by hardware architectural features such as the Barrel Shifter and hardware single-cycle multipliers.

The ARM Hardware Barrel Shifter in Action

ARM processors incorporate a physical hardware barrel shifter directly on the second operand (Operand 2) of the ALU input path. This enables the CPU to shift or rotate a register value and perform an arithmetic/logic operation in a single clock cycle:

Cbarrel_shifter_idiom.c
/* Multiplying an index by 4 and adding a base address */
uint32_t calc_address(uint32_t base, uint32_t index) {
    return base + (index * 4U);
}

/* Compiles on ARM Cortex-M to a single instruction with ZERO cycle penalty:
 *   ADD R0, R0, R1, LSL #2   ; R0 = R0 + (R1 << 2) in 1 clock cycle!
 */
C Operator ARM Cortex-M Instruction Hardware Cycle Latency Real-Time Architectural Impact
+, - ADD, SUB 1 cycle Deterministic execution; sets carry/overflow flags in APSR.
* MUL, SMULL, UMULL 1 cycle (Cortex-M3/M4/M7) Hardware multiplier present on M3/M4/M7. On Cortex-M0/M0+, can take 1 or 32 cycles depending on silicon option!
/, % SDIV, UDIV 2 to 12 cycles (Non-deterministic) Hardware divide is non-constant time. Cortex-M0/M0+ lacks hardware division entirely; invokes heavy software library routines.
&, |, ^, ~ AND, ORR, EOR, MVN 1 cycle Fundamental bitmask primitives for hardware register manipulation.

4.2 Bitwise Manipulation Primitives: Setting, Clearing, Toggling & Testing

In embedded firmware, microcontrollers interface with hardware through Memory-Mapped I/O (MMIO) registers. A 32-bit register controls GPIO pin modes, peripheral clocks, interrupt enables, and status flags. Firmware engineers must manipulate individual bits or bitfields without disturbing unrelated bits in the register.

1. Setting Bits (OR with Mask)

Forces target bit positions to 1 while preserving all other bits: 

/* Set bit 5 */
reg |= (1U << 5U);

/* Set multiple bits (bits 2, 4, and 7) */
reg |= ((1U << 2U) | (1U << 4U) | (1U << 7U));

2. Clearing Bits (AND with Inverted Mask)

Forces target bit positions to 0 while preserving all other bits: 

/* Clear bit 5 */
reg &= ~(1U << 5U);

/* Clear bitfield (bits [3:0]) */
reg &= ~0x0FU;

3. Toggling Bits (XOR with Mask)

Inverts target bit positions ($0 ightarrow 1$, $1 ightarrow 0$) without branching: 

/* Toggle LED on GPIO Pin 13 */
reg ^= (1U << 13U);

4. Testing & Polling Bits

Tests whether a specific flag is set in a hardware status register: 

/* Check if UART Transmission Complete (TC) */
bool is_tx_complete = (reg & (1U << 6U)) != 0U;

Multi-Bit Bitfield Extraction & Insertion

Microcontroller registers often store configuration values across contiguous multi-bit slices (e.g. 2 bits per GPIO pin in STM32 MODER, or a 4-bit baud rate prescaler). To manipulate bitfields defensively without data corrupting adjacent configuration:

Cbitfield_manipulation.c
#include <stdint.h>

#define UART_BAUD_POS  4U       /* Starts at bit 4 */
#define UART_BAUD_MASK 0x0FU    /* 4-bit wide field (0000 to 1111) */

/* Extract bitfield value: Shift right then mask */
uint32_t extract_baud_prescaler(uint32_t reg_val) {
    return (reg_val >> UART_BAUD_POS) & UART_BAUD_MASK;
}

/* Insert bitfield value: Clear target field first, then OR shifted new value */
uint32_t set_baud_prescaler(uint32_t reg_val, uint32_t new_prescaler) {
    /* 1. Clear existing 4-bit field */
    reg_val &= ~(UART_BAUD_MASK << UART_BAUD_POS);
    /* 2. Mask new value to ensure it fits, shift into position, and OR */
    reg_val |= ((new_prescaler & UART_BAUD_MASK) << UART_BAUD_POS);
    return reg_val;
}

4.3 Shift Operators & Undefined Behavior Hazards

Bit-shifting operations (<<, >>) map to hardware shifts, but C imposes strict rules whose violation triggers dangerous Undefined Behavior (UB):

⚠️ Hazard 1: Shifting by $\ge$ Width of the Type

Shifting a 32-bit integer by 32 or more positions (or by a negative count) is Undefined Behavior in ISO C (§6.5.7/3). On x86 processors, the hardware instruction masks the shift count with 0x1F (shift by 32 becomes shift by 0, leaving the value unchanged!). On ARM processors, shifting by 32 returns 0. The compiler optimizer assumes you will never shift by $\ge 32$ bits and can eliminate surrounding safety checks! 

uint32_t x = 1U;
uint32_t bad_shift = x << 32U; /* UNDEFINED BEHAVIOR! Hardware results diverge! */

⚠️ Hazard 2: Logical Right Shift (LSR) vs. Arithmetic Right Shift (ASR)

When right-shifting a signed negative integer, the C standard designates the result as Implementation-Defined. Most compilers emit ASR (Arithmetic Shift Right), which shifts in sign bits to preserve negative value. For an unsigned integer, the C standard guarantees a logical right shift (LSR), padding upper bits with zeros. 

int16_t  s = -16;   /* 0xFFF0 */
int16_t  s_res = s >> 2; /* 0xFFFC (-4) via Arithmetic Shift Right */

uint16_t u = 0xFFF0U;
uint16_t u_res = u >> 2; /* 0x3FFC (16380) via Logical Shift Right */

4.4 Operator Precedence & Associativity Hazards in Systems Code

C's operator precedence table has notorious historical quirks. Specifically, bitwise operators have lower precedence than relational and equality operators! In 1974, when B evolved into C, Ritchie separated && from &, but maintained backward compatibility by keeping bitwise precedence lower than == and !=.

The Lethal Register Poll Bug

Cprecedence_bug.c
#define STATUS_READY_BIT (1U << 3U)

/* ENGINEER INTENT: Check if the ready bit is non-zero */
if (status_reg & STATUS_READY_BIT != 0U) {
    /* Process data */
}

/* COMPILER EVALUATION (Equality == has HIGHER precedence than Bitwise &):
 *   if (status_reg & (STATUS_READY_BIT != 0U))
 *   ==> if (status_reg & 1U)
 * Checks bit 0 instead of bit 3! The condition executes on WRONG data!
 *
 * DEFENSIVE FIX: Always wrap bitwise expressions in explicit parentheses!
 */
if ((status_reg & STATUS_READY_BIT) != 0U) {
    /* Correctly evaluates bit 3 */
}

4.5 Safety Standards: MISRA C:2012 Rules on Bitwise Operations

In automotive, medical, and aerospace systems, complying with MISRA C:2012 prevents undefined behavior and conversion surprises:

  • MISRA C:2012 Rule 10.1: Operands to bitwise operators (&, |, ^, ~, <<, >>) shall have an essentially unsigned type. Applying bitwise operators to signed integers is strictly forbidden.
  • MISRA C:2012 Rule 10.4: Both operands of an operator shall have the same essential type category. Mixing unsigned and signed integers in bitwise expressions triggers violation.
  • MISRA C:2012 Rule 12.2: The right-hand operand of a shift operator shall be strictly less than the width of the left-hand operand in bits.

4.6 Real-Time Case Study: STM32 GPIO Register Driver with Atomic Bit Set/Reset (BSRR)

A common beginner mistake when toggling GPIO pins is using a Read-Modify-Write operation on the output data register: GPIOA->ODR |= (1U << 5). In a real-time system with concurrent interrupts, an interrupt occurring between the Read and the Write will have its register modifications overwritten and lost!

To prevent race conditions without disabling global interrupts, ARM Cortex-M microcontrollers provide an atomic Bit Set/Reset Register (BSRR):

Cstm32_gpio_atomic_driver.c
#include <stdint.h>
#include <stdbool.h>

/* Mock Memory-Mapped GPIO Register Layout (STM32 Standard) */
typedef struct {
    volatile uint32_t MODER;   /* GPIO port mode register (2 bits per pin) */
    volatile uint32_t OTYPER;  /* Output type register (1 bit per pin) */
    volatile uint32_t OSPEEDR; /* Output speed register (2 bits per pin) */
    volatile uint32_t PUPDR;   /* Pull-up/pull-down register (2 bits per pin) */
    volatile uint32_t IDR;     /* Input data register (read-only) */
    volatile uint32_t ODR;     /* Output data register */
    volatile uint32_t BSRR;    /* Bit set/reset register (write-only, atomic) */
} gpio_port_reg_t;

#define GPIOA_BASE_ADDR 0x40020000U
#define GPIOA           ((gpio_port_reg_t *)GPIOA_BASE_ADDR)

/* Pin Mode Definitions */
typedef enum {
    GPIO_MODE_INPUT     = 0x00U,
    GPIO_MODE_OUTPUT    = 0x01U,
    GPIO_MODE_ALTERNATE = 0x02U,
    GPIO_MODE_ANALOG    = 0x03U
} gpio_mode_t;

/**
 * @brief Configures mode for a specific GPIO pin (0-15).
 */
void gpio_set_pin_mode(gpio_port_reg_t *port, uint8_t pin, gpio_mode_t mode) {
    if (port == NULL || pin > 15U) return;
    
    uint32_t shift = (uint32_t)pin * 2U;
    uint32_t mask = 0x03U << shift;
    
    /* Read-Modify-Write during initialization (interrupts not yet enabled) */
    uint32_t val = port->MODER;
    val &= ~mask;                     /* Clear mode field */
    val |= ((uint32_t)mode << shift); /* Set mode */
    port->MODER = val;
}

/**
 * @brief Atomically drives GPIO pin HIGH.
 * Writing 1 to bit (pin) sets ODR bit. Writing 0 has no effect.
 */
static inline void gpio_write_pin_high(gpio_port_reg_t *port, uint8_t pin) {
    /* Bits 0-15 of BSRR set corresponding ODR bit atomically in 1 cycle */
    port->BSRR = (1U << pin);
}

/**
 * @brief Atomically drives GPIO pin LOW.
 * Writing 1 to bit (pin + 16) resets ODR bit. Writing 0 has no effect.
 */
static inline void gpio_write_pin_low(gpio_port_reg_t *port, uint8_t pin) {
    /* Bits 16-31 of BSRR reset corresponding ODR bit atomically in 1 cycle */
    port->BSRR = (1U << (pin + 16U));
}

4.7 Hands-On Lab: Bit Manipulation & Hardware Register Simulator

Lab Exercise: The Bit Manipulation Engine

In this lab, you will author a standalone utility bit_engine_lab.c that validates bit manipulation idioms, measures bit population algorithms (Brian Kernighan's bit-counting algorithm vs hardware __builtin_popcount), tests atomic register writes, and diagnoses precedence traps.

Complete Source Code: bit_engine_lab.c

Cbit_engine_lab.c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

/* Displays a 32-bit word in binary format with nibble spacing */
static void print_binary_32(const char *label, uint32_t val) {
    printf("%-20s [0x%08X] : ", label, val);
    for (int i = 31; i >= 0; --i) {
        printf("%c", (val & (1U << (uint32_t)i)) ? '1' : '0');
        if (i % 4 == 0 && i != 0) printf(" ");
    }
    printf("\n");
}

/* Brian Kernighan's Algorithm: Counts set bits in O(number of set bits) */
static uint32_t count_set_bits_kernighan(uint32_t n) {
    uint32_t count = 0;
    while (n != 0U) {
        n &= (n - 1U); /* Clears the least significant set bit */
        count++;
    }
    return count;
}

int main(void) {
    printf("========================================================\n");
    printf("    EMBEDDED BITWISE MANIPULATION & REGISTER ENGINE      \n");
    printf("========================================================\n\n");

    uint32_t reg = 0x00000000U;
    print_binary_32("Initial Register", reg);

    /* 1. Set Bits 4, 12, 28 */
    reg |= ((1U << 4U) | (1U << 12U) | (1U << 28U));
    print_binary_32("Set Bits 4,12,28", reg);

    /* 2. Toggle Bit 12 (turn off) and Bit 1 (turn on) */
    reg ^= ((1U << 12U) | (1U << 1U));
    print_binary_32("Toggle Bits 12 & 1", reg);

    /* 3. Insert 4-bit field (0xA) at bits [19:16] */
    uint32_t field_val = 0x0AU;
    uint32_t pos = 16U;
    uint32_t mask = 0x0FU;
    reg = (reg & ~(mask << pos)) | ((field_val & mask) << pos);
    print_binary_32("Insert 0xA at [19:16]", reg);

    /* 4. Bit Counting Verification */
    uint32_t k_count = count_set_bits_kernighan(reg);
    uint32_t hw_count = (uint32_t)__builtin_popcount(reg);
    printf("\nSet Bit Count (Kernighan Algorithm): %u\n", k_count);
    printf("Set Bit Count (Hardware popcount):     %u\n", hw_count);

    if (k_count == hw_count) {
        printf("Verification: BIT COUNT ALGORITHMS MATCH PERFECTLY!\n");
    }

    printf("\n========================================================\n");
    printf("Bit engine diagnostics completed successfully.\n");
    return EXIT_SUCCESS;
}

4.8 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: What is the resulting value of evaluating (reg & 1U << 4U == 0U)?

Explanation: Equality == binds tighter than shifts << and bitwise &. Always parenthesize expressions: ((reg & (1U << 4U)) == 0U).

Q2: Why does Brian Kernighan's algorithm n &= (n - 1) clear the lowest set bit?

Explanation: In binary subtraction, n - 1 flips the lowest 1 bit to 0 and all trailing 0s to 1. Performing bitwise AND with n sets all differing bits to 0, clearing precisely that single lowest set bit.

Q3: Why should hardware GPIO toggling in interrupt-driven systems use BSRR instead of ODR?

Explanation: Writing to BSRR writes directly to the set/reset flip-flops in a single cycle. Modifying ODR requires a load, or, store sequence; if an ISR fires between the load and store, its GPIO updates are overwritten and lost.

Q4: What happens under ISO C when shifting a 32-bit unsigned integer by 35 bits (val << 35U)?

Explanation: ISO C specifies that shifting by $\ge$ the bitwidth of the operand is undefined. Never shift by $\ge 32$ bits on a 32-bit type.

Q5: According to MISRA C:2012 Rule 10.1, why are bitwise operators prohibited on signed integers?

Explanation: Shifting or inverting signed types can flip the sign bit, resulting in negative overflow (UB) or implementation-defined arithmetic shifts.
