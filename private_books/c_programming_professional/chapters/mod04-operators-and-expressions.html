Module 4: Operators, Expressions & Bit Manipulation

Master professional bitwise idioms, register manipulation, sequence points, evaluation order, integer promotion rules, and avoiding Undefined Behavior (UB).

⏱️ Estimated Reading: 45 min
🎯 Standard: C11 / C17 / C23
🛠️ Environments: Linux POSIX + Bare-Metal ARM
⚡ MISRA C:2012 Rule 10.1, 12.1 Aligned

4.1 The Five Essential Bitwise Idioms in Firmware

Microcontroller programming relies entirely on manipulating individual bits within peripheral hardware registers. The five core idioms must be second nature to every systems engineer:

Operation Bitwise Expression Engineering Purpose
Set Bit n REG |= (1U << n) Enables a peripheral clock, triggers an interrupt enable flag, or drives an output high.
Clear Bit n REG &= ~(1U << n) Disables a timer, resets an interrupt pending status, or drives an output low.
Toggle Bit n REG ^= (1U << n) Inverts the state of a GPIO pin (e.g. flashing an LED or square-wave heartbeat).
Check Bit n (REG & (1U << n)) != 0U Tests if a hardware TX buffer is empty or an ADC conversion is complete.
Modify Multi-bit Field REG = (REG & ~MASK) | (VAL << POS) Safely updates multi-bit configuration registers (e.g. baud rate or ADC prescaler) without corrupting adjacent bits.
CSafe Multi-Bit Field Modification Pattern
#define USART_CR1_M_POS       12U
#define USART_CR1_M_MASK      (0x3U << USART_CR1_M_POS)

void usart_set_word_length(volatile uint32_t *cr1, uint32_t mode) {
    /* 1. Read current register value
     * 2. Clear target field bits
     * 3. Mask and OR-in the new setting
     * 4. Write back atomic value */
    uint32_t val = *cr1;
    val &= ~USART_CR1_M_MASK;
    val |= ((mode << USART_CR1_M_POS) & USART_CR1_M_MASK);
    *cr1 = val;
}

4.2 Integer Promotions & The "unsigned int" Trap

In C, operands smaller than int (such as uint8_t and int16_t) undergo integer promotion to signed int before arithmetic or bitwise operations. This frequently introduces security bugs:

CInversion & Comparison Pitfall
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t a = 0xAA;
    
    /* Pitfall: ~a is promoted to signed int (0xFFFFFF55 on 32-bit CPU) */
    if (~a == 0x55) {
        printf("Matches!\n");
    } else {
        printf("FAILED! Evaluated to: 0x%08X\n", (unsigned int)(~a));
    }
    
    /* Correct Idiom: Explicit cast after promotion */
    if ((uint8_t)(~a) == 0x55) {
        printf("Correctly matches 0x55 with explicit cast\n");
    }
    return 0;
}

4.3 Sequence Points & Undefined Behavior (UB)

Between sequence points, an object's value must not be modified more than once, nor may it be read except to determine the value to be stored. Violating this produces compiler-dependent Undefined Behavior:

  • i = i++ + 1; — Undefined behavior.
  • arr[i] = i++; — Undefined behavior.
  • printf("%d %d\n", ++i, ++i); — Undefined parameter evaluation order.
