Module 3: C Data Types, Variables & Memory Alignment

Master low-level integer representations, fixed-width types, IEEE 754 floating-point characteristics, storage classes, pointer sizes, and hardware memory alignment requirements in systems code.

⏱️ Estimated Reading: 50 min
🎯 Standard: C11 / C17 / C23
🛠️ Environments: Linux POSIX + ARM Cortex-M Bare-Metal
⚡ MISRA C:2012 Rule 8.4, 8.7, 8.9 Aligned

3.1 Primitive Types vs. Architecture-Dependent Sizes

In C, primitive types (such as int, long, and pointers) do not have a globally fixed byte width. Their sizes depend on the data model chosen by the compiler target architecture:

Data Model Target Platforms short int long long long Pointer
ILP32 32-bit ARM (Cortex-M0/M3/M4), x86 32-bit 16-bit 32-bit 32-bit 64-bit 32-bit (4 bytes)
LP64 Linux x86_64, macOS, ARM64 (AArch64) 16-bit 32-bit 64-bit 64-bit 64-bit (8 bytes)
LLP64 Microsoft Windows x64 16-bit 32-bit 32-bit 64-bit 64-bit (8 bytes)
Professional Engineering Warning:

Because long is 32 bits on ILP32 (ARM Cortex-M) and 64 bits on LP64 (Linux x86_64), writing data packets using standard types results in silent protocol corruption. Always use exact-width integer types from <stdint.h> in firmware and networking code.

3.2 Exact-Width Integer Types (<stdint.h> & <inttypes.h>)

Introduced in C99, <stdint.h> specifies standard integer types with explicit widths and signedness:

CFixed-Width Declarations & Format Specifiers
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

void display_telemetry(uint32_t timestamp_ms, int16_t temperature_raw) {
    /* Always use PRIu32 and PRId16 for portable printing across 32-bit and 64-bit hosts */
    printf("Time: %" PRIu32 " ms | Temp: %" PRId16 " LSB\n", timestamp_ms, temperature_raw);
}

int main(void) {
    uint8_t  can_id_filter = 0x7F;
    uint16_t packet_crc    = 0xA4F2;
    uint32_t flash_addr    = 0x08004000;
    uint64_t uptime_ns     = 1450209384918ULL;

    display_telemetry(15000, -420);
    return 0;
}

3.3 Type Qualifiers: const, volatile & restrict

Type qualifiers change how compilers reason about memory locations and control optimizations:

1. volatile

Tells the compiler that the variable's value can change outside the program's control (e.g., hardware registers, shared ISR memory). Prevents the compiler from caching the value in a CPU register or eliding successive reads/writes.

2. const

Marks an object as read-only. For embedded targets, global const tables are allocated directly in Flash ROM (.rodata), conserving critical micro-controller SRAM.

3. restrict

Guarantees to the compiler that for the lifetime of the pointer, no other pointer will alias the same memory region. Enables aggressive SIMD vectorization and register unrolling.

CHardware MMIO with volatile vs const volatile
/* Typical ARM Cortex-M Peripheral Register Definitions */
typedef struct {
    volatile uint32_t MODER;   /* Read/Write control register */
    volatile uint32_t OTYPER;  /* Read/Write output type */
    volatile uint32_t OSPEEDR; /* Read/Write output speed */
    const volatile uint32_t IDR;     /* READ-ONLY input data register (Hardware driven) */
    volatile uint32_t ODR;     /* Read/Write output data register */
    volatile uint32_t BSRR;    /* Write-only bit set/reset */
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *) 0x48000000UL)

void poll_pin(void) {
    /* Compiler is forced to read physical bus every iteration */
    while ((GPIOA->IDR & (1 << 0)) == 0) {
        /* Wait for input pin high */
    }
}

3.4 Memory Alignment, Padding & Cache Coherence

CPUs access memory efficiently when data addresses are multiples of the natural word size (e.g. 4-byte integers at 4-byte aligned addresses). Compilers automatically insert padding bytes into structures to ensure alignment:

CStructure Layout & Padding Inspection
#include <stdio.h>
#include <stdint.h>
#include <stddef.h>

/* Sub-optimal ordering: 12 bytes */
struct UnalignedSensor {
    uint8_t  id;       /* 1 byte  - offset 0 */
    /* 3 bytes padding */
    uint32_t timestamp;/* 4 bytes - offset 4 */
    uint16_t reading;  /* 2 bytes - offset 8 */
    /* 2 bytes tail padding to satisfy 4-byte struct alignment */
};

/* Optimized ordering (largest to smallest): 8 bytes */
struct OptimalSensor {
    uint32_t timestamp;/* 4 bytes - offset 0 */
    uint16_t reading;  /* 2 bytes - offset 4 */
    uint8_t  id;       /* 1 byte  - offset 6 */
    /* 1 byte tail padding */
};

int main(void) {
    printf("Unaligned struct size: %zu bytes (lost 5 bytes to padding)\n", sizeof(struct UnalignedSensor));
    printf("Optimal struct size:   %zu bytes\n", sizeof(struct OptimalSensor));
    printf("Offset of timestamp:   %zu\n", offsetof(struct UnalignedSensor, timestamp));
    return 0;
}
