Module 28: Process Lifecycle & Inter-Process Communication (IPC)

Deep dive into Linux process creation, fork() Copy-on-Write (COW) memory mechanics, execve(), zombie process reaping with waitpid(), daemonization (setsid), anonymous pipes, POSIX shared memory (shm_open, mmap), and POSIX message queues.

⏱️ Duration: 60m
🎯 Standard: POSIX.1-2008 / System V & POSIX IPC
⚡ Target: Multi-Process Linux Architectures

28.1 Process Creation: fork() & Copy-on-Write (COW)

When a process calls fork(), the Linux kernel does not make an expensive duplicate copy of the parent process's physical RAM. Instead, it duplicates the parent's page tables and marks all physical memory pages as Read-Only.

Copy-on-Write (COW) Page Fault Architecture
Parent Page Table ──┐
                    ├──▶ [ Shared Physical Page (Read-Only) ]
Child Page Table  ──┘               │
                                    │ (Child or Parent attempts memory WRITE)
                                    ▼
                         [ MMU Write Fault (Page Fault) ]
                                    │
                                    ▼
       [ Kernel Allocates NEW Physical Page & Copies 4 KB Data ]
Parent Page Table ──▶ [ Original Page (Read/Write) ]
Child Page Table  ──▶ [ Private Copy Page (Read/Write) ]

Zombie Processes & Reaping Mechanics

When a child process terminates via exit(), its virtual memory, open files, and address space are immediately deallocated. However, its entry in the kernel process table remains (a Zombie Process, state Z) so the parent can inspect its exit status code.

If the parent fails to call wait() or waitpid(), zombies accumulate, eventually exhausting the kernel PID space (/proc/sys/kernel/pid_max), preventing any new processes from launching!

28.2 Anonymous Pipes & Broken Pipe (SIGPIPE)

Pipes are unidirectional byte streams buffered in kernel memory (typically 64 KB). A pipe possesses a read descriptor (pipefd[0]) and a write descriptor (pipefd[1]).

The Fatal SIGPIPE Default Action: If a process writes to a pipe whose read end has been closed by the peer, the kernel delivers a SIGPIPE signal. The default disposition of SIGPIPE is abnormal process termination! Production daemons must set signal(SIGPIPE, SIG_IGN) so that write() returns -1 with errno == EPIPE instead of crashing.

28.3 POSIX Shared Memory (shm_open & mmap)

Shared memory is the fastest possible IPC mechanism because data does not pass through the kernel. Once mapped into the virtual address spaces of both processes via mmap(), reads and writes occur directly at RAM hardware speeds (zero system call overhead).

Lifecycle of POSIX Shared Memory

  1. shm_open("/telemetry_shm", O_CREAT | O_RDWR, 0660): Creates a named shared memory object in /dev/shm.
  2. ftruncate(shm_fd, sizeof(telemetry_data_t)): Sizes the physical allocation.
  3. mmap(NULL, size, PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd, 0): Maps memory into process address space.
  4. shm_unlink("/telemetry_shm"): Removes the name from the filesystem namespace (memory persists until all processes unmap).

28.4 Industrial Case Study: Robot Arm Supervisor Crash

The SIGPIPE Factory Floor Emergency Shutdown

An industrial articulated robotic arm performing automotive welding suddenly stopped mid-weld and collapsed into emergency limp mode.

Investigation: The robot’s trajectory controller ran as a multi-process architecture. The motion supervisor communicated with a GUI diagnostic display over a local UNIX domain socket pipe.

The GUI tablet battery died, closing the receiving socket. 10 milliseconds later, the motion supervisor attempted to write a telemetry frame: 

write(gui_socket_fd, &coords, sizeof(coords)); /* Unshielded write! */

Because the receiving socket was closed and the application had not ignored SIGPIPE, the Linux kernel terminated the main motion supervisor immediately.

Corrective Action: Enforced signal(SIGPIPE, SIG_IGN) across all daemons, and configured socket writes to use send(..., MSG_NOSIGNAL).

28.5 Hands-On Lab: Zero-Copy Shared Memory IPC with Process-Shared Mutex

In this lab, you will create two independent processes communicating over POSIX Shared Memory synchronized by a process-shared pthread mutex.

Shared Memory IPC Engine (shm_ipc.c)

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <pthread.h>

typedef struct {
    pthread_mutex_t mutex;
    uint32_t counter;
} shared_block_t;

int main(void) {
    const char *shm_name = "/acl_demo_shm";
    int shm_fd = shm_open(shm_name, O_CREAT | O_RDWR | O_TRUNC, 0666);
    ftruncate(shm_fd, sizeof(shared_block_t));

    shared_block_t *block = (shared_block_t *)mmap(
        NULL, sizeof(shared_block_t), PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd, 0);

    /* Initialize process-shared mutex */
    pthread_mutexattr_t attr;
    pthread_mutexattr_init(&attr);
    pthread_mutexattr_setpshared(&attr, PTHREAD_PROCESS_SHARED);
    pthread_mutex_init(&block->mutex, &attr);
    block->counter = 0;

    pid_t pid = fork();
    if (pid == 0) {
        /* Child Process: Producer */
        for (int i = 0; i < 5; i++) {
            pthread_mutex_lock(&block->mutex);
            block->counter += 10;
            printf("[CHILD] Incremented counter to: %u
", block->counter);
            pthread_mutex_unlock(&block->mutex);
            usleep(100000);
        }
        exit(0);
    } else {
        /* Parent Process: Consumer */
        for (int i = 0; i < 5; i++) {
            pthread_mutex_lock(&block->mutex);
            printf("[PARENT] Read counter value: %u
", block->counter);
            pthread_mutex_unlock(&block->mutex);
            usleep(100000);
        }
        wait(NULL); // Reap child
    }

    munmap(block, sizeof(shared_block_t));
    shm_unlink(shm_name);
    return 0;
}

28.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: What physical event occurs during fork() under Copy-on-Write (COW)?

Explanation: Copy-on-Write optimizes process creation by sharing existing physical memory pages until a write triggers a hardware page fault that creates a private copy.

Q2: What signal is delivered by default when writing to a pipe with no active readers, and what is its default action?

Explanation: SIGPIPE is delivered when writing to a broken pipe or disconnected socket; because its default action is termination, production systems must ignore it or handle it.

Q3: What mutex attribute must be enabled to allow a pthread mutex in POSIX shared memory to synchronize two distinct processes?

Explanation: By default, pthread mutexes are PTHREAD_PROCESS_PRIVATE; setting PTHREAD_PROCESS_SHARED instructs the kernel futex subsystem to permit multi-process synchronization.

Q4: What filesystem directory mounts the POSIX shared memory objects created via shm_open() on Linux?

Explanation: On Linux, POSIX shared memory is backed by a tmpfs RAM filesystem mounted at /dev/shm.

Q5: How can a parent process clean up finished child processes without blocking if no children have exited yet?

Explanation: The WNOHANG option instructs waitpid() to return immediately with 0 if no child has exited, preventing the parent from stalling.
