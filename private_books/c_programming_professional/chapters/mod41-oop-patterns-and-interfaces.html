Module 41: OOP Patterns & Interfaces in C

Implement modern object-oriented paradigms in clean ANSI C: opaque handles for strict encapsulation, ISO C single inheritance guarantees, virtual method tables (vtables) in Flash memory, and swappable network interfaces.

⏱️ Estimated Reading: 65 min
🎯 Standard: C99 / C11 / C17 / MISRA C:2012
🛠️ Environments: Linux POSIX + Bare-Metal ARM

41.1 Encapsulation in Pure C: Incomplete Types & Opaque Handles

Object-Oriented Programming (OOP) is not a language feature—it is an architectural design paradigm. Languages like C++ and Java enforce OOP principles at the compiler and grammar level, but seasoned systems engineers routinely implement robust Encapsulation, Inheritance, and Polymorphism in pure ANSI/ISO C.

The bedrock of OOP in C is Encapsulation via the Opaque Pointer (PIMPL) Pattern. By declaring a struct name in the header without defining its internal fields, callers are physically prevented from accessing or modifying internal state:

Copaque_encapsulation.h
#ifndef OPAQUE_ENCAPSULATION_H
#define OPAQUE_ENCAPSULATION_H

#include <stdint.h>
#include <stdbool.h>

/* Incomplete struct declaration (Opaque Handle) */
typedef struct ring_buffer ring_buffer_t;

/* Constructor and Destructor */
ring_buffer_t *ring_buffer_create(size_t capacity);
void           ring_buffer_destroy(ring_buffer_t *rb);

/* Public Member Methods (Encapsulated operations) */
bool   ring_buffer_push(ring_buffer_t *rb, uint8_t byte);
bool   ring_buffer_pop(ring_buffer_t *rb, uint8_t *out_byte);
size_t ring_buffer_get_count(const ring_buffer_t *rb);

#endif /* OPAQUE_ENCAPSULATION_H */

41.2 Inheritance in C: Struct Composition & ISO Memory Guarantees

In C, single inheritance is modeled by Struct Composition, where the base class structure is embedded as the very first member of the derived class structure.

The ISO C Memory Guarantee (§6.7.2.1)

The ISO C standard explicitly guarantees that a pointer to a structure object, suitably converted, points to its initial member. There are zero padding bytes before the first member: 


 struct base_sensor {
     uint32_t sensor_id;       // Offset 0x00
     uint32_t sample_rate_hz;  // Offset 0x04
 };

 struct derived_imu {
     struct base_sensor base;  // Offset 0x00 (EXACTLY MATCHES &derived_imu!)
     int16_t accel_x;          // Offset 0x08
     int16_t accel_y;          // Offset 0x0A
     int16_t accel_z;          // Offset 0x0C
 };

 // UPCASTING IS STRICTLY VALID IN ISO C:
 struct derived_imu imu;
 struct base_sensor *base_ptr = (struct base_sensor *)&imu; // Address identical!

41.3 Polymorphism via Virtual Method Tables (Vtables) in C

Runtime polymorphism allows calling a method on an abstract base pointer without knowing the concrete underlying derived type. In pure C, we achieve this by defining a Vtable struct of function pointers stored in read-only Flash (.rodata):

Cvtable_actuator.c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>

/* Forward declaration */
typedef struct actuator actuator_t;

/* 1. Abstract Interface Vtable */
typedef struct {
    void (*set_speed)(actuator_t *self, int32_t speed);
    void (*emergency_stop)(actuator_t *self);
    int32_t (*get_position)(const actuator_t *self);
} actuator_vtable_t;

/* 2. Abstract Base Class */
struct actuator {
    const actuator_vtable_t *vptr; /* Virtual pointer to .rodata table */
    uint32_t id;
};

/* Virtual Method Dispatch Helper */
static inline void actuator_set_speed(actuator_t *self, int32_t speed) {
    if (self && self->vptr && self->vptr->set_speed) {
        self->vptr->set_speed(self, speed);
    }
}

/* 3. Concrete Derived Class: Stepper Motor */
typedef struct {
    actuator_t base;       /* Base class embedded at offset 0 */
    int32_t    step_angle;
    int32_t    current_steps;
} stepper_motor_t;

static void stepper_set_speed(actuator_t *self, int32_t speed) {
    stepper_motor_t *stepper = (stepper_motor_t *)self;
    printf("[Stepper %u] Speed set to %d RPM (Step angle: %d deg)\n",
           stepper->base.id, speed, stepper->step_angle);
}

static void stepper_emergency_stop(actuator_t *self) {
    printf("[Stepper %u] EMERGENCY STOP: Coil Power Cut!\n", self->id);
}

static int32_t stepper_get_position(const actuator_t *self) {
    const stepper_motor_t *stepper = (const stepper_motor_t *)self;
    return stepper->current_steps;
}

/* Vtable allocated in Flash (.rodata) */
static const actuator_vtable_t STEPPER_VTABLE = {
    .set_speed = stepper_set_speed,
    .emergency_stop = stepper_emergency_stop,
    .get_position = stepper_get_position
};

/* Stepper Constructor */
void stepper_init(stepper_motor_t *motor, uint32_t id, int32_t step_angle) {
    motor->base.vptr = &STEPPER_VTABLE;
    motor->base.id = id;
    motor->step_angle = step_angle;
    motor->current_steps = 0;
}

41.4 Real-Time Industrial Case: Swappable Network Interface Architecture

Consider an IoT gateway that transmits sensor data over Ethernet, Wi-Fi, or 4G LTE depending on physical link availability. By consuming an abstract net_if_t vtable interface, the telemetry client requires zero modifications when the link switches:

Cnetwork_interface_vtable.c
typedef struct net_if net_if_t;

typedef struct {
    bool (*connect)(net_if_t *self, const char *endpoint);
    bool (*send_packet)(net_if_t *self, const uint8_t *data, size_t len);
    bool (*disconnect)(net_if_t *self);
} net_if_vtable_t;

struct net_if {
    const net_if_vtable_t *vptr;
    bool is_up;
};

/* Telemetry loop operates purely on abstract interface */
void broadcast_telemetry(net_if_t *net, const uint8_t *data, size_t len) {
    if (net->is_up) {
        net->vptr->send_packet(net, data, len);
    }
}

41.5 Hands-On Lab: Polymorphic Actuator Engine Simulator

Lab Exercise: The Pure C Polymorphism Testbed

In this lab, you will author vtable_actuator_lab.c to instantiate an array of polymorphic actuators (Stepper Motors and DC Motors) and dispatch control commands through virtual tables.

Complete Source Code: vtable_actuator_lab.c

Cvtable_actuator_lab.c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct device device_t;
typedef struct {
    void (*self_test)(device_t *self);
} device_vtable_t;

struct device {
    const device_vtable_t *vptr;
    const char *name;
};

/* Concrete Device 1: CAN Transceiver */
typedef struct {
    device_t base;
    uint32_t baud;
} can_device_t;

static void can_self_test(device_t *self) {
    can_device_t *can = (can_device_t *)self;
    printf("[CAN] Testing %s at %u baud: Loopback OK\n", can->base.name, can->baud);
}
static const device_vtable_t CAN_VTABLE = { .self_test = can_self_test };

/* Concrete Device 2: SPI Flash */
typedef struct {
    device_t base;
    uint32_t capacity_kb;
} flash_device_t;

static void flash_self_test(device_t *self) {
    flash_device_t *flash = (flash_device_t *)self;
    printf("[FLASH] Testing %s (%u KB): JEDEC ID Verified\n", flash->base.name, flash->capacity_kb);
}
static const device_vtable_t FLASH_VTABLE = { .self_test = flash_self_test };

int main(void) {
    printf("========================================================\n");
    printf("        PURE C POLYMORPHIC VTABLE ENGINE LAB            \n");
    printf("========================================================\n\n");

    can_device_t can = { .base = { .vptr = &CAN_VTABLE, .name = "CAN_BUS_PRIMARY" }, .baud = 500000 };
    flash_device_t flash = { .base = { .vptr = &FLASH_VTABLE, .name = "NOR_FLASH_W25Q" }, .capacity_kb = 8192 };

    /* Heterogeneous array of base class pointers */
    device_t *fleet[] = { (device_t *)&can, (device_t *)&flash };

    for (size_t i = 0; i < 2; ++i) {
        fleet[i]->vptr->self_test(fleet[i]);
    }

    printf("\n========================================================\n");
    printf("Polymorphic testbed executed successfully.\n");
    return EXIT_SUCCESS;
}

41.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why does ISO C guarantee that casting a derived struct pointer to its base struct pointer is safe when the base struct is the first member?

Explanation: Under ISO C, there is never leading padding before the first member of a structure, guaranteeing identical memory addresses.

Q2: What is the primary performance penalty of invoking methods through a pure C virtual method table (vtable)?

Explanation: Indirect branch calls prevent function inlining and may cause a branch target buffer misprediction.
