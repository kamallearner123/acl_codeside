Module 29: POSIX Threads & Multithreading

Deep dive into Linux Native POSIX Thread Library (NPTL) internals, clone() system calls, thread creation lifecycle, custom stack sizing and MPU guard pages, thread cancellation, thread-local storage (_Thread_local), and safe worker thread pools.

⏱️ Duration: 55m
🎯 Standard: POSIX.1c (pthreads) / ISO C11 / Linux NPTL
⚡ Target: Multithreaded Linux & RT-Preempt

29.1 Linux NPTL & The clone() Syscall

In the Linux kernel, there is strictly no difference in internal representation between a process and a thread: both are represented by a struct task_struct.

A thread is created via the clone(2) system call passing flags that instruct the child task to share the parent's memory, file descriptors, and signal dispositions: 

clone(child_func, stack_top,
      CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD,
      arg);
  • CLONE_VM: Both tasks share the same virtual memory page tables.
  • CLONE_FILES: Both tasks share the same file descriptor table.
  • CLONE_THREAD: Placed into the same Thread Group (TGID matches PID).

29.2 Thread Stacks & Guard Pages

While threads share the heap and data segments, every thread must have its own independent stack for function calls and local variables.

Thread Stack Memory Layout & Guard Page Protection
High Memory (0x7FFF...)
    │ ┌────────────────────────────────────────────────────────┐
    │ │ Thread Stack Top (Stack Pointer %rsp starts here)      │
    │ │ Local variables, return addresses, AAPCS stack frames   │
    │ │               │ (Stack grows downward)                 │
    │ │               ▼                                        │
    │ ├────────────────────────────────────────────────────────┤
    │ │ Guard Page (4 KB, mprotect(PROT_NONE))                 │ <-- Stack Overflow Traps Here!
    ▼ └────────────────────────────────────────────────────────┘
Low Memory

On desktop Linux, the default thread stack is 8 MB. In memory-constrained embedded Linux gateways (e.g. 64 MB total RAM), spawning 20 threads with default stacks would consume 160 MB of virtual address space!

Configuring Custom Stack Sizes

pthread_attr_t attr;
pthread_attr_init(&attr);
/* Restrict stack size to 128 KB for embedded tasks */
pthread_attr_setstacksize(&attr, 128 * 1024);
pthread_create(&thread_id, &attr, worker_task, NULL);
pthread_attr_destroy(&attr);

29.3 Thread Cancellation & Cleanup Handlers

Terminating a thread from the outside using pthread_cancel() is dangerous: if the thread holds an open mutex or malloc buffer, terminating it asynchronously causes resource leaks or deadlocks.

Deferred Cancellation: By default, cancellation occurs only when the thread reaches a defined POSIX cancellation point (such as read(), sleep(), or pthread_testcancel()).

To ensure resources are cleanly released when cancelled, register cleanup handlers: 

void cleanup_handler(void *arg) {
    int *fd = (int *)arg;
    if (fd && *fd >= 0) close(*fd);
}

void *worker(void *arg) {
    int fd = open("log.txt", O_WRONLY);
    pthread_cleanup_push(cleanup_handler, &fd);

    while (1) {
        pthread_testcancel(); /* Explicit cancellation checkpoint */
        usleep(10000);
    }

    pthread_cleanup_pop(1); /* Executes cleanup if cancelled or returned */
    return NULL;
}

29.4 Industrial Case Study: Drone Embedded Gateway Stack Exhaustion

The 64 MB RAM Out-Of-Memory Reboot

An autonomous agricultural survey drone running embedded Linux crashed and rebooted every time it engaged all 12 multi-spectral camera channels.

Investigation: The video capture software spawned a dedicated thread for each camera channel. The developers used default pthread_create() attributes.

With 12 camera threads + 6 networking threads + 4 sensor fusion threads = 22 threads. 22 threads × 8 MB default stack = 176 MB of virtual memory requested on a drone board with only 64 MB of physical RAM! The Linux OOM (Out-Of-Memory) killer was triggered, terminating the flight navigation service.

Resolution: Explicit stack sizes were configured: 256 KB for camera ingestion, 64 KB for sensor telemetry. Total stack footprint dropped from 176 MB to 3.5 MB, resolving the issue completely.

29.5 Hands-On Lab: Implementing a Worker Thread Pool in C

In this lab, you will write a complete multi-threaded worker pool in C that distributes computational tasks across worker threads using a task queue.

Worker Thread Pool (thread_pool.c)

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <stdbool.h>
#include <unistd.h>

#define POOL_SIZE 4
#define QUEUE_MAX 16

typedef void (*task_fn)(void *arg);

typedef struct {
    task_fn function;
    void *argument;
} task_t;

typedef struct {
    pthread_mutex_t lock;
    pthread_cond_t notify;
    pthread_t threads[POOL_SIZE];
    task_t queue[QUEUE_MAX];
    int head;
    int tail;
    int count;
    bool shutdown;
} thread_pool_t;

static void *worker_thread(void *arg) {
    thread_pool_t *pool = (thread_pool_t *)arg;
    while (1) {
        pthread_mutex_lock(&pool->lock);
        while (pool->count == 0 && !pool->shutdown) {
            pthread_cond_wait(&pool->notify, &pool->lock);
        }
        if (pool->shutdown && pool->count == 0) {
            pthread_mutex_unlock(&pool->lock);
            break;
        }

        task_t task = pool->queue[pool->tail];
        pool->tail = (pool->tail + 1) % QUEUE_MAX;
        pool->count--;
        pthread_mutex_unlock(&pool->lock);

        /* Execute task */
        task.function(task.argument);
    }
    return NULL;
}

void print_task(void *arg) {
    int id = (int)(intptr_t)arg;
    printf("[THREAD %lu] Executed Task ID #%d
", pthread_self(), id);
    usleep(50000);
}

int main(void) {
    thread_pool_t pool = {0};
    pthread_mutex_init(&pool.lock, NULL);
    pthread_cond_init(&pool.notify, NULL);

    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setstacksize(&attr, 128 * 1024); /* 128 KB custom stack */

    for (int i = 0; i < POOL_SIZE; i++) {
        pthread_create(&pool.threads[i], &attr, worker_thread, &pool);
    }
    pthread_attr_destroy(&attr);

    /* Enqueue 8 tasks */
    pthread_mutex_lock(&pool.lock);
    for (intptr_t i = 1; i <= 8; i++) {
        pool.queue[pool.head] = (task_t){print_task, (void *)i};
        pool.head = (pool.head + 1) % QUEUE_MAX;
        pool.count++;
    }
    pthread_cond_broadcast(&pool.notify);
    pthread_mutex_unlock(&pool.lock);

    sleep(1);

    /* Clean shutdown */
    pthread_mutex_lock(&pool.lock);
    pool.shutdown = true;
    pthread_cond_broadcast(&pool.notify);
    pthread_mutex_unlock(&pool.lock);

    for (int i = 0; i < POOL_SIZE; i++) {
        pthread_join(pool.threads[i], NULL);
    }
    printf("Thread pool shut down cleanly.
");
    return 0;
}

29.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: What underlying Linux system call creates POSIX threads in the Native POSIX Thread Library (NPTL)?

Explanation: pthread_create() invokes clone() passing flags that share virtual memory, file descriptors, and signal handlers with the calling process.

Q2: What is the typical default thread stack size allocated on 64-bit Linux distributions?

Explanation: The standard Linux pthreads default stack is 8 megabytes, which must be configured lower in embedded systems with limited RAM.

Q3: What ISO C11 keyword defines a variable that is instantiated uniquely per thread?

Explanation: _Thread_local (or thread_local in <threads.h>) gives the variable thread-local storage duration.

Q4: What happens if a detached thread (pthread_detach()) terminates?

Explanation: Detached threads automatically clean up their own resources upon termination without requiring another thread to join them.

Q5: Why should thread cancellation cleanup handlers be registered via pthread_cleanup_push()?

Explanation: Cleanup handlers act like finally blocks in C, guaranteeing that held locks or allocated memory are not leaked if cancellation occurs.
