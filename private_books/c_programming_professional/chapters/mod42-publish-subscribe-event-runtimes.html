Module 42: Event-Driven & Pub/Sub Runtimes

Eliminate mutex deadlocks and priority inversion in real-time embedded systems: master the Active Object design pattern, zero-lock immutable event queues, and pure C publish-subscribe message brokers.

⏱️ Estimated Reading: 65 min
🎯 Standard: C99 / C11 / C17 / Active Objects
🛠️ Environments: Linux POSIX + FreeRTOS + Bare-Metal ARM

42.1 The Active Object (Actor) Design Pattern in Embedded Systems

Traditional embedded firmware multi-threading relies on shared data structures protected by blocking mutexes, binary semaphores, and critical sections. In complex systems, this paradigm inevitably triggers catastrophic runtime defects: Deadlocks, Priority Inversion, Race Conditions, and Non-Deterministic Jitter.

The Active Object (AO) Pattern (standardized by Dr. Miro Samek in Quantum Platform QP/C and based on Hewitt's Actor Model) solves concurrency by replacing shared state with Asynchronous Message Passing. An Active Object is an autonomous, encapsulated software entity consisting of three components:

The 3 Pillars of an Active Object

  • 1. Dedicated Event Queue: A private FIFO message queue receiving event signals and payloads from other AOs or ISRs.
  • 2. Private Execution Thread (RTOS Task): An RTOS thread blocking on the event queue, processing incoming events one at a time.
  • 3. Internal State Machine (FSM / HSM): Encapsulated private state variables modified strictly within the AO's own thread context. ZERO external mutex locks required!

42.2 Zero-Lock Immutable Event Passing Architecture

To achieve deterministic real-time performance without dynamic heap allocation (malloc), events are passed as lightweight immutable structures containing a signal ID and an optional payload:

Cactive_object_event.h
#ifndef ACTIVE_OBJECT_EVENT_H
#define ACTIVE_OBJECT_EVENT_H

#include <stdint.h>
#include <stdbool.h>

/* Event Signals */
typedef enum {
    SIG_TIMER_TICK = 0,
    SIG_SENSOR_DATA_READY,
    SIG_BUTTON_PRESSED,
    SIG_CAN_FRAME_RECEIVED,
    SIG_ALARM_TRIGGERED,
    SIG_USER_MAX
} event_signal_t;

/* Base Event Structure */
typedef struct event {
    event_signal_t sig;
    uint32_t       sender_id;
} event_t;

/* Concrete Event with Payload */
typedef struct {
    event_t super;
    float   temperature_celsius;
    float   pressure_hpa;
} sensor_event_t;

#endif /* ACTIVE_OBJECT_EVENT_H */

42.3 The Publish-Subscribe Event Broker in Pure C

In a publish-subscribe architecture, components do not send messages directly to specific receivers. Instead, an Active Object subscribes to a topic/signal on a centralized Event Broker. When an event is published, the Broker dispatches copies to all registered subscribers:

Cevent_broker.c
#define MAX_SUBSCRIBERS_PER_SIG 8U

typedef struct {
    void (*post_fifo)(void *ao_ctx, const event_t *evt);
    void *ao_ctx;
} subscriber_t;

typedef struct {
    subscriber_t subscribers[SIG_USER_MAX][MAX_SUBSCRIBERS_PER_SIG];
    uint8_t      sub_count[SIG_USER_MAX];
} event_broker_t;

static event_broker_t g_broker;

void broker_subscribe(event_signal_t sig, void *ao_ctx, void (*post_fifo)(void *, const event_t *)) {
    if (sig >= SIG_USER_MAX) return;
    uint8_t idx = g_broker.sub_count[sig];
    if (idx < MAX_SUBSCRIBERS_PER_SIG) {
        g_broker.subscribers[sig][idx].ao_ctx = ao_ctx;
        g_broker.subscribers[sig][idx].post_fifo = post_fifo;
        g_broker.sub_count[sig]++;
    }
}

void broker_publish(const event_t *evt) {
    if (evt == NULL || evt->sig >= SIG_USER_MAX) return;
    uint8_t count = g_broker.sub_count[evt->sig];
    for (uint8_t i = 0; i < count; ++i) {
        g_broker.subscribers[evt->sig][i].post_fifo(
            g_broker.subscribers[evt->sig][i].ao_ctx, evt);
    }
}

42.4 Real-Time Industrial Case: Avionics / Drone Flight Controller Active Object Mesh

A production UAV flight controller decomposes into four concurrent Active Objects:

  1. Sensor IMU AO (1000 Hz): Reads gyroscope and accelerometer over SPI, runs complementary Madgwick filter, and publishes SIG_ATTITUDE_ESTIMATE.
  2. Flight Control PID AO (500 Hz): Subscribes to SIG_ATTITUDE_ESTIMATE and SIG_PILOT_COMMAND, computes motor PWM outputs.
  3. Telemetry Radiomodem AO (50 Hz): Serializes flight metrics and transmits over MAVLink RF bus.
  4. Black-Box Flash Logger AO (10 Hz): Writes telemetry packets to SPI NOR Flash without blocking the high-rate flight loop!

42.5 Hands-On Lab: Standalone Active Object & Pub/Sub Event Bus

Lab Exercise: The Active Object Event Engine

In this lab, you will compile and execute active_object_lab.c, running an event broker with mock telemetry and alarm subscriber objects.

Complete Source Code: active_object_lab.c

Cactive_object_lab.c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    EVENT_TICK = 0,
    EVENT_OVERHEAT_ALARM,
    EVENT_COUNT
} signal_t;

typedef struct {
    signal_t sig;
    int32_t  payload;
} event_t;

/* Active Object Consumer 1: Display Logger */
static void logger_on_event(void *ctx, const event_t *evt) {
    (void)ctx;
    if (evt->sig == EVENT_TICK) {
        printf("[LOGGER AO] Heartbeat Tick: %d\n", evt->payload);
    } else if (evt->sig == EVENT_OVERHEAT_ALARM) {
        printf("[LOGGER AO] 🚨 ALARM DETECTED! Temperature: %d C\n", evt->payload);
    }
}

/* Active Object Consumer 2: Safety Interlock */
static void safety_on_event(void *ctx, const event_t *evt) {
    (void)ctx;
    if (evt->sig == EVENT_OVERHEAT_ALARM) {
        printf("[SAFETY AO] ⚠️ TRIPPING RELAY: Cooling Fan Activated at Max RPM!\n");
    }
}

int main(void) {
    printf("========================================================\n");
    printf("      ACTIVE OBJECT & EVENT-DRIVEN RUNTIME LAB          \n");
    printf("========================================================\n\n");

    /* Simulating Event Dispatching */
    event_t normal_tick = { .sig = EVENT_TICK, .payload = 1001 };
    event_t alarm_event = { .sig = EVENT_OVERHEAT_ALARM, .payload = 98 };

    printf("Dispatching Normal Tick Event:\n");
    logger_on_event(NULL, &normal_tick);

    printf("\nPublishing Overheat Alarm Event to Multi-Subscribers:\n");
    logger_on_event(NULL, &alarm_event);
    safety_on_event(NULL, &alarm_event);

    printf("\n========================================================\n");
    printf("Active Object event dispatching verified with zero defects.\n");
    return EXIT_SUCCESS;
}

42.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: How does the Active Object design pattern eliminate multi-threading deadlocks and race conditions?

Explanation: Because an Active Object accesses its private state strictly within its single designated task, mutual exclusion locks are completely eliminated.

Q2: What is the primary benefit of a Publish-Subscribe broker over point-to-point task queues?

Explanation: Pub/Sub decouples event producers from consumers, allowing modular extension without modifying producer code.
