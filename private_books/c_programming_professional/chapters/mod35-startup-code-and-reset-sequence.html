Module 35: Startup Code & Reset Sequence (crt0)

Deep dive into the silicon reset lifecycle of ARM Cortex-M microcontrollers. Master the hardware reset sequence, writing the pure C Reset_Handler, copying .data from Flash to RAM, zero-filling .bss, hardware FPU coprocessor initialization, and calling main().

⏱️ Duration: 55m
🎯 Standard: ARMv7-M Architecture / C11 Runtime Init
⚡ Target: Bare-Metal ARM Cortex-M4F / STM32F4

35.1 The Hardware Reset Sequence

When power is applied to an ARM Cortex-M processor (or when the hardware NRST pin is released), the core executes a strict, unalterable hardware sequence hardwired into the silicon:

Cortex-M Hardware Power-On Execution Sequence
Power On / Reset Pin Released
          │
          ▼
Hardware samples BOOT pins (determines whether vector table alias is Flash, System ROM, or SRAM)
          │
          ▼
Step 1: Hardware reads 32-bit word from address 0x00000000 ──▶ Loads into MSP (Main Stack Pointer %sp)
          │
          ▼
Step 2: Hardware reads 32-bit word from address 0x00000004 ──▶ Loads into PC (Program Counter %pc)
          │                                                    (LSB must be 1 to indicate Thumb mode!)
          ▼
Step 3: CPU begins executing machine instructions at Reset_Handler()

35.2 The 4 Mandatory Steps of Reset_Handler (crt0)

Before any high-level C code (like main()) can execute, the C runtime environment (crt0) must establish memory invariants guaranteed by the ISO C standard:

  1. Copy .data from Flash to RAM: Initialized global and static variables have their initial values stored in Flash ROM. The startup code copies them word-by-word into SRAM.
  2. Zero-Fill .bss in RAM: The ISO C standard guarantees that all uninitialized global/static variables start with value zero. The startup code loops through the .bss memory region and fills it with 0x00000000.
  3. Enable the Hardware Floating-Point Unit (FPU): On Cortex-M4F, the hardware FPU coprocessor is powered down by default on reset. Any floating-point instruction executed before enabling CP10/CP11 triggers an immediate NOCP (No Coprocessor) UsageFault!
  4. Branch to main(): With stacks initialized and global memory established, execution branches to main().

35.3 Writing a Pure C startup_stm32f4.c from Scratch

#include <stdint.h>

/* Symbols defined in Linker Script */
extern uint32_t _estack;
extern uint32_t _sidata;
extern uint32_t _sdata;
extern uint32_t _edata;
extern uint32_t _sbss;
extern uint32_t _ebss;

/* Function prototypes */
int main(void);
void Reset_Handler(void);
void Default_Handler(void);

/* Weak aliases for Exception Handlers */
void NMI_Handler(void)        __attribute__((weak, alias("Default_Handler")));
void HardFault_Handler(void)  __attribute__((weak, alias("Default_Handler")));
void MemManage_Handler(void)  __attribute__((weak, alias("Default_Handler")));
void BusFault_Handler(void)   __attribute__((weak, alias("Default_Handler")));
void UsageFault_Handler(void) __attribute__((weak, alias("Default_Handler")));
void SVC_Handler(void)        __attribute__((weak, alias("Default_Handler")));
void PendSV_Handler(void)     __attribute__((weak, alias("Default_Handler")));
void SysTick_Handler(void)    __attribute__((weak, alias("Default_Handler")));

/* Vector Table placed into .isr_vector section */
__attribute__((section(".isr_vector"), used))
uint32_t * const g_pfnVectors[] = {
    (uint32_t *)&_estack,            /* 0x00: Initial Main Stack Pointer */
    (uint32_t *)Reset_Handler,        /* 0x04: Reset Handler */
    (uint32_t *)NMI_Handler,          /* 0x08: Non-Maskable Interrupt */
    (uint32_t *)HardFault_Handler,    /* 0x0C: HardFault Handler */
    (uint32_t *)MemManage_Handler,    /* 0x10: Memory Management Fault */
    (uint32_t *)BusFault_Handler,     /* 0x14: Bus Fault */
    (uint32_t *)UsageFault_Handler,   /* 0x18: Usage Fault */
    0, 0, 0, 0,                       /* Reserved */
    (uint32_t *)SVC_Handler,          /* 0x2C: SVCall */
    0, 0,                             /* Reserved */
    (uint32_t *)PendSV_Handler,       /* 0x38: PendSV */
    (uint32_t *)SysTick_Handler       /* 0x3C: SysTick */
};

/* The C Runtime Reset Entry Point */
void Reset_Handler(void) {
    /* Step 1: Copy .data from Flash ROM to SRAM */
    uint32_t *src = &_sidata;
    uint32_t *dst = &_sdata;
    while (dst < &_edata) {
        *dst++ = *src++;
    }

    /* Step 2: Zero-fill .bss section in SRAM */
    dst = &_sbss;
    while (dst < &_ebss) {
        *dst++ = 0U;
    }

    /* Step 3: Enable Hardware FPU Coprocessor (CP10 and CP11) */
    /* System Control Space: CPACR register at 0xE000ED88 */
    volatile uint32_t *cpacr = (volatile uint32_t *)0xE000ED88;
    *cpacr |= ((3UL << (10 * 2)) | (3UL << (11 * 2))); /* Full access */
    __asm__ volatile("dsb
isb" ::: "memory");

    /* Step 4: Branch to Application Entry Point */
    main();

    /* Trap if main ever returns */
    while (1) {
        __asm__ volatile("wfi");
    }
}

void Default_Handler(void) {
    while (1) {
        /* Infinite loop for unhandled interrupts */
    }
}

35.4 Industrial Case Study: Sub-Zero Smart Meter Reset Failure

The Uninitialized Pointer Winter Blackout Incident

An electrical utility deployed 100,000 smart grid electricity meters. During a severe polar vortex (-30°C), thousands of meters experienced power glitches and rebooted into a corrupted state with spinning fans and disabled metering.

Investigation: The developers optimized boot time by commenting out the .bss zeroing loop in the startup file to shave 3 milliseconds off reset!

They reasoned: "We explicitly initialize all critical variables in C anyway."

However, a secondary flash write lock flag was declared as a global: 

static bool g_flash_write_in_progress; /* Depended on ISO C zero-init! */

During a cold power glitch, unpowered SRAM cells decayed to arbitrary random patterns (often 0xFF or 0xAA). When the meter rebooted without .bss zeroing, g_flash_write_in_progress woke up with value true! The metering task assumed an ongoing write and refused to log power readings forever.

Corrective Action: Strict compliance with the ISO C crt0 specification was mandated. Zeroing .bss was permanently re-enabled across all firmware projects.

35.5 Hands-On Lab: Verifying BSS and DATA Initialization via GDB

In this lab, you will compile the custom startup file, set a breakpoint at the entry of Reset_Handler in GDB, inspect SRAM before and after the copy/zero loops, and prove that main() receives pristine memory.

Verification Script

# Connect GDB to running QEMU or OpenOCD target
arm-none-eabi-gdb -q build/firmware.elf

# Set breakpoint at Reset_Handler
(gdb) target remote localhost:3333
(gdb) break Reset_Handler
(gdb) continue

# Inspect uninitialized SRAM at _sdata before copy loop
(gdb) print &_sdata
$1 = (uint32_t *) 0x20000000
(gdb) x/4xw 0x20000000
0x20000000: 0x00000000 0x00000000 0x00000000 0x00000000

# Step past copy loop
(gdb) until main
(gdb) x/4xw 0x20000000
# Displays populated initialized data copied faithfully from Flash!

35.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why must the least-significant bit (LSB) of function pointers in the ARM Cortex-M vector table be set to 1?

Explanation: Cortex-M processors exclusively support Thumb-2 instructions; setting LSB=1 signals Thumb mode to the processor core.

Q2: What happens if an application executes a hardware floating-point instruction on Cortex-M4F without first enabling CP10/CP11 in the CPACR register?

Explanation: The FPU coprocessor is powered down on reset; executing FPU opcodes without enabling access triggers a No Coprocessor UsageFault.

Q3: What memory operations are performed by the Reset_Handler loop handling the .data section?

Explanation: Initialized variables must be copied from non-volatile flash into writeable SRAM before main() executes.

Q4: What attribute is used to provide default fallback implementations for interrupt service routines that can be overridden by user drivers?

Explanation: Weak symbols allow the linker to bind to Default_Handler unless a strong definition (such as a custom USART1_IRQHandler) is supplied elsewhere.

Q5: What instruction should be placed in an infinite loop after main() in bare-metal startup code to conserve electrical power?

Explanation: WFI suspends CPU core clocks until an interrupt arrives, drastically reducing power consumption compared to a busy spin loop.
