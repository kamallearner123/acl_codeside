Module 36: Interrupts, NVIC & Concurrency

Master real-time interrupt handling on the ARM Cortex-M NVIC: vector table mechanics, priority grouping, tail-chaining in 6 cycles, elimination of torn-read race conditions, PRIMASK critical sections, and lock-free SPSC ring buffers.

⏱️ Estimated Reading: 75 min
🎯 Standard: C99 / C11 / Cortex-M NVIC
🛠️ Environments: Bare-Metal ARM + FreeRTOS

36.1 Hardware Interrupt Architecture & The ARM Nested Vectored Interrupt Controller (NVIC)

In embedded real-time systems, asynchronous events (ADC conversions, timer expirations, CAN frame arrivals, sensor fault pins) cannot be serviced via CPU polling without wasting massive compute cycles and violating latency deadlines. The processor must respond deterministically to external hardware stimuli via Hardware Interrupts.

On the ARM Cortex-M architecture (Cortex-M0/M3/M4/M7), interrupt handling is governed by a dedicated hardware peripheral tightly integrated into the processor core: the Nested Vectored Interrupt Controller (NVIC). Unlike legacy processors that vector all interrupts to a single dispatcher routine, the NVIC supports up to 240 physical external interrupt lines (IRQs), each with a direct vector address mapped in hardware.

The Cortex-M Physical Vector Table Layout in Flash

The vector table begins at memory address 0x00000000 (aliased to 0x08000000 on STM32 Flash). The first entry contains the initial Main Stack Pointer (MSP), followed by 15 system exceptions, and up to 240 vendor-defined peripheral IRQs: 


 Address      Vector Index   Exception Type          Description
 --------------------------------------------------------------------------------------
 0x0000_0000  0              Initial MSP Value       Top of Main Stack in RAM
 0x0000_0004  1              Reset Handler           First instruction executed on boot
 0x0000_0008  2              NMI Handler             Non-Maskable Interrupt (Clock security)
 0x0000_000C  3              HardFault Handler       Unrecoverable bus or execution fault
 0x0000_0010  4              MemManage Handler       MPU memory permission violation
 0x0000_0014  5              BusFault Handler        AHB/APB bus error or invalid address
 0x0000_0018  6              UsageFault Handler      Undefined instruction or divide-by-zero
 0x0000_001C-0x0000_002B    7-10 Reserved
 0x0000_002C  11             SVCall Handler          Supervisor Call (OS system calls)
 0x0000_0038  14             PendSV Handler          Pended Service Call (RTOS context switch)
 0x0000_003C  15             SysTick Handler         System Tick Timer (RTOS scheduler tick)
 --------------------------------------------------------------------------------------
 0x0000_0040  16 (IRQ 0)     WWDG                    Window Watchdog Interrupt
 0x0000_0044  17 (IRQ 1)     PVD                     Power Voltage Detector
 ...          ...            ...                     ...
 0x0000_00E4  56 (IRQ 40)    TIM2_IRQHandler         General Purpose Timer 2
 0x0000_0128  73 (IRQ 57)    USART2_IRQHandler       Serial Port 2 Transmit/Receive

The Core NVIC Register Interface

Firmware interfaces with the NVIC through memory-mapped control registers located in the System Control Space (SCS, base address 0xE000E100). To avoid Read-Modify-Write race conditions, the NVIC uses separate Set and Clear registers:

Register Group Full Name Access Type Hardware Operation
NVIC->ISER[8] Interrupt Set-Enable Registers Read / Write-1-to-Set Writing 1 enables the corresponding IRQ line. Writing 0 has no effect. Eliminates read-modify-write hazards!
NVIC->ICER[8] Interrupt Clear-Enable Registers Read / Write-1-to-Clear Writing 1 disables the corresponding IRQ line atomically. Writing 0 has no effect.
NVIC->ISPR[8] Interrupt Set-Pending Registers Read / Write-1-to-Set Allows software to artificially trigger an interrupt line (software interrupts).
NVIC->ICPR[8] Interrupt Clear-Pending Registers Read / Write-1-to-Clear Clears a pending interrupt latch before it executes.
NVIC->IPR[60] Interrupt Priority Registers Byte-accessible Read/Write Configures the priority level (0-255) for each peripheral IRQ.

36.2 Interrupt Priority Grouping & Preemption Mechanics

In ARM Cortex-M architecture, interrupt priority is governed by a fundamental mathematical rule:

LOWER NUMERICAL VALUE = HIGHER LOGICAL PRIORITY!
Priority 0 is the most urgent, critical interrupt. Priority 15 (or 255) is the lowest urgency background interrupt.

Preemption Priority vs. Subpriority

Each priority byte is partitioned into two fields by the Priority Grouping setting in the Application Interrupt and Reset Control Register (SCB->AIRCR):

  • Preemption Priority (Group Priority): Determines whether an incoming interrupt can preempt (nest inside) an already executing Interrupt Service Routine. If an incoming IRQ has a lower numerical preemption priority than the currently running ISR, the processor immediately suspends the current ISR and executes the higher-priority IRQ!
  • Subpriority (Subgroup Priority): Used purely as a tie-breaker when two interrupts with the identical preemption priority are pended at the same time. Subpriority does NOT cause preemption; it only decides which one executes first!
Cnvic_priority_configuration.c
#include <stdint.h>

/* CMSIS Standard Definitions for STM32 / Cortex-M4 */
#define NVIC_PRIORITYGROUP_4  0x00000003U /* 4 bits for preemption priority, 0 bits for subpriority */

void configure_nvic_subsystems(void) {
    /* 1. Set Priority Grouping: 4 bits of preemption priority (Levels 0 to 15) */
    NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);

    /* 2. Configure High-Priority Motor Control Current Loop (Preemption Priority 1) */
    NVIC_SetPriority(TIM1_UP_TIM10_IRQn, NVIC_EncodePriority(NVIC_PRIORITYGROUP_4, 1, 0));
    NVIC_EnableIRQ(TIM1_UP_TIM10_IRQn);

    /* 3. Configure Medium-Priority Telemetry UART Receiver (Preemption Priority 5) */
    NVIC_SetPriority(USART2_IRQn, NVIC_EncodePriority(NVIC_PRIORITYGROUP_4, 5, 0));
    NVIC_EnableIRQ(USART2_IRQn);

    /* 4. Configure Low-Priority Debug Console (Preemption Priority 14) */
    NVIC_SetPriority(USART3_IRQn, NVIC_EncodePriority(NVIC_PRIORITYGROUP_4, 14, 0));
    NVIC_EnableIRQ(USART3_IRQn);

    /* Concurrency Rule: TIM1 (Priority 1) can PREEMPT USART2 (Priority 5)!
     * USART3 (Priority 14) can NEVER preempt USART2 or TIM1. */
}

36.3 Hardware Exception Entry, Stacking & Tail-Chaining Mechanics

When an enabled interrupt triggers and is accepted by the NVIC, the Cortex-M processor executes an autonomous hardware sequence before the first instruction of your C ISR executes:

The 12-Cycle Hardware Stacking Sequence

The CPU automatically pushes 8 words (32 bytes) onto the active stack (usually the Process Stack Pointer PSP for threads, or Main Stack Pointer MSP): 


 [Cortex-M Hardware Stacking Frame (32 Bytes)]
 SP + 0x1C: xPSR (Program Status Register with execution flags)
 SP + 0x18: PC   (Return address: instruction to resume after ISR)
 SP + 0x14: LR   (Link Register value prior to interrupt)
 SP + 0x10: R12  (Intra-procedure scratchpad register)
 SP + 0x0C: R3   (Argument / Scratch register 3)
 SP + 0x08: R2   (Argument / Scratch register 2)
 SP + 0x04: R1   (Argument / Scratch register 1)
 SP + 0x00: R0   (Argument / Scratch register 0) <-- Stack Pointer after Entry

EXC_RETURN: While pushing the caller context, the CPU loads a special magic value into the Link Register (LR) known as EXC_RETURN (e.g. 0xFFFFFFF9 or 0xFFFFFFFD). When the C function returns via BX LR, the processor detects this magic value and triggers the hardware unstacking sequence!

Hardware Tail-Chaining Optimization (6 Clock Cycles!)

In traditional architectures, exiting one ISR and entering another requires popping all 8 registers off the stack and immediately pushing them back on.

Cortex-M introduces hardware Tail-Chaining: if an interrupt of equal or higher priority is pending when an ISR finishes, the processor skips unstacking and re-stacking entirely! It simply redirects the Program Counter to the new ISR vector in just 6 clock cycles, achieving exceptional real-time throughput.

36.4 Concurrency, Race Conditions & Critical Sections

A software bug that plagues embedded development is the Interrupt Race Condition. When a thread in the main loop reads a 16-bit or 32-bit variable in multiple CPU instructions, an ISR can fire halfway through the read, producing corrupted data:

The 64-Bit Variable Torn Read Hazard

Ctorn_read_hazard.c
/* 64-bit millisecond system uptime counter */
volatile uint64_t g_system_uptime_ms = 0;

/* Executed inside SysTick_Handler every 1 ms */
void SysTick_Handler(void) {
    g_system_uptime_ms++;
}

/* Executed in main thread */
uint64_t get_uptime_ms_UNSAFE(void) {
    /* ON A 32-BIT ARM CPU, READING A 64-BIT INTEGER REQUIRES TWO INSTRUCTIONS:
     *   LDR  R0, [g_system_uptime_ms]      ; Read lower 32 bits
     *   --- >>> SYSTICK FIRES HERE! g_system_uptime_ms rolls from 0x00000000FFFFFFFF to 0x0000000100000000 <<< ---
     *   LDR  R1, [g_system_uptime_ms + 4]  ; Read upper 32 bits
     *
     * Result in R0:R1 is 0x00000001FFFFFFFF (Time jumped into the future by 49 days!)
     */
    return g_system_uptime_ms;
}

Defensive Critical Sections: PRIMASK Save and Restore

A common mistake is wrapping critical sections with naive __disable_irq() and __enable_irq() calls. If function A calls function B, and function B calls __enable_irq(), interrupts are prematurely re-enabled inside function A, destroying protection!

The correct, robust pattern saves the current PRIMASK state and restores it upon exit:

Ccritical_section_primask.c
#include <stdint.h>

/* Safe Reentrant Critical Section Pattern */
static inline uint32_t enter_critical_section(void) {
    uint32_t primask_state;
    /* Read current PRIMASK interrupt mask state into register */
    __asm__ volatile ("MRS %0, PRIMASK" : "=r" (primask_state) :: "memory");
    /* Disable interrupts with priority >= 0 */
    __asm__ volatile ("CPSID I" ::: "memory");
    return primask_state;
}

static inline void exit_critical_section(uint32_t primask_state) {
    /* Restore previous PRIMASK state (only enables interrupts if they were already enabled!) */
    __asm__ volatile ("MSR PRIMASK, %0" :: "r" (primask_state) : "memory");
}

/* Safe Atomic Read of 64-bit Variable */
uint64_t get_uptime_ms_SAFE(void) {
    uint32_t state = enter_critical_section();
    uint64_t safe_uptime = g_system_uptime_ms;
    exit_critical_section(state);
    return safe_uptime;
}

36.5 Lock-Free Single-Producer Single-Consumer (SPSC) Ring Buffers

Disabling interrupts introduces jitter and latency into high-speed control loops. For streaming data between an ISR (Producer) and the main thread (Consumer), we can eliminate locks completely using a Single-Producer Single-Consumer (SPSC) Lock-Free Circular Buffer:

Clockfree_spsc_ringbuf.h
#ifndef LOCKFREE_SPSC_RINGBUF_H
#define LOCKFREE_SPSC_RINGBUF_H

#include <stdint.h>
#include <stdbool.h>

/* Power-of-two capacity for fast bitwise wrapping */
#define RINGBUF_CAPACITY 256U
#define RINGBUF_MASK     (RINGBUF_CAPACITY - 1U)

typedef struct {
    uint8_t  buffer[RINGBUF_CAPACITY];
    volatile uint32_t head; /* Modified ONLY by Producer (ISR) */
    volatile uint32_t tail; /* Modified ONLY by Consumer (Main Thread) */
} spsc_ringbuf_t;

static inline void spsc_ringbuf_init(spsc_ringbuf_t *rb) {
    rb->head = 0U;
    rb->tail = 0U;
}

/* Push Byte from ISR (Producer) - NO LOCKS NEEDED! */
static inline bool spsc_ringbuf_push_isr(spsc_ringbuf_t *rb, uint8_t byte) {
    uint32_t next_head = (rb->head + 1U) & RINGBUF_MASK;
    if (next_head == rb->tail) {
        return false; /* Buffer Full! */
    }
    rb->buffer[rb->head] = byte;
    
    /* Memory barrier ensures byte is written to memory before head index updates */
    __asm__ volatile ("DMB" ::: "memory");
    rb->head = next_head;
    return true;
}

/* Pop Byte from Main Thread (Consumer) - NO LOCKS NEEDED! */
static inline bool spsc_ringbuf_pop_thread(spsc_ringbuf_t *rb, uint8_t *out_byte) {
    if (rb->tail == rb->head) {
        return false; /* Buffer Empty! */
    }
    *out_byte = rb->buffer[rb->tail];
    
    /* Memory barrier ensures byte read completes before tail index advances */
    __asm__ volatile ("DMB" ::: "memory");
    rb->tail = (rb->tail + 1U) & RINGBUF_MASK;
    return true;
}

#endif /* LOCKFREE_SPSC_RINGBUF_H */

36.6 Real-Time Case Study: STM32 DMA UART Receiver with IDLE-Line Interrupt

Processing serial data byte-by-byte in an interrupt routine wastes significant CPU headroom at 921,600 baud (92,160 interrupts/sec!). The gold-standard industrial architecture combines DMA Circular Buffer Reception with the UART IDLE Line Interrupt:

  1. Hardware Direct Memory Access (DMA) transfers incoming UART bytes directly into SRAM with 0% CPU utilization.
  2. When the sender finishes transmitting a frame, the serial line goes idle for 1 full byte duration. The UART peripheral hardware detects this and asserts the IDLE Interrupt.
  3. The ISR fires only once per complete message packet, reads the DMA counter (DMA_CNDTR), and signals the processing task!

36.7 Hands-On Lab: Software Interrupt Dispatcher & Priority Preemption Benchmark

Lab Exercise: The NVIC Priority & Race Condition Simulator

In this lab, you will author nvic_concurrency_lab.c to simulate NVIC priority preemption, measure latency penalties from torn reads, and test the lock-free SPSC circular ring buffer.

Complete Source Code: nvic_concurrency_lab.c

Cnvic_concurrency_lab.c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define RING_SIZE 8U
#define RING_MASK (RING_SIZE - 1U)

typedef struct {
    uint8_t buffer[RING_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} mock_ringbuf_t;

static mock_ringbuf_t g_ring;

int main(void) {
    printf("========================================================\n");
    printf("     NVIC CONCURRENCY & LOCK-FREE RING BUFFER BENCHMARK   \n");
    printf("========================================================\n\n");

    g_ring.head = 0;
    g_ring.tail = 0;

    printf("[1] Simulating High-Frequency ISR Pushing 6 Bytes...\n");
    for (uint8_t i = 0xAA; i <= 0xAF; ++i) {
        uint32_t next = (g_ring.head + 1U) & RING_MASK;
        if (next != g_ring.tail) {
            g_ring.buffer[g_ring.head] = i;
            g_ring.head = next;
            printf("  ISR Pushed: 0x%02X (Head: %u, Tail: %u)\n", i, g_ring.head, g_ring.tail);
        }
    }

    printf("\n[2] Simulating Main Thread Consumer Popping Data...\n");
    while (g_ring.tail != g_ring.head) {
        uint8_t val = g_ring.buffer[g_ring.tail];
        g_ring.tail = (g_ring.tail + 1U) & RING_MASK;
        printf("  Thread Popped: 0x%02X (Head: %u, Tail: %u)\n", val, g_ring.head, g_ring.tail);
    }

    printf("\n[3] Testing Buffer Full Condition...\n");
    for (uint8_t i = 1; i <= 10; ++i) {
        uint32_t next = (g_ring.head + 1U) & RING_MASK;
        if (next == g_ring.tail) {
            printf("  Overflow Caught Defensively! Slot %u Rejected.\n", i);
            break;
        }
        g_ring.buffer[g_ring.head] = i;
        g_ring.head = next;
    }

    printf("\n========================================================\n");
    printf("NVIC Concurrency Lab completed with zero defects.\n");
    return EXIT_SUCCESS;
}

36.8 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: On an ARM Cortex-M processor, if Interrupt A has Priority 2 and Interrupt B has Priority 7, which interrupt will preempt the other?

Explanation: Cortex-M NVIC prioritizes lower numerical values. Priority 0 is the most urgent; Priority 2 has higher priority than Priority 7.

Q2: What is the primary purpose of the Cortex-M hardware Tail-Chaining feature?

Explanation: Tail-chaining avoids wasting 24+ clock cycles popping and re-pushing R0-R3, R12, LR, PC, and xPSR between consecutive interrupts.

Q3: Why is volatile insufficient to prevent race conditions when reading a 64-bit integer on a 32-bit MCU?

Explanation: Reading 64 bits on a 32-bit bus requires two LDR instructions. An interrupt firing between them sees inconsistent state unless protected by a critical section.

Q4: Why does a lock-free Single-Producer Single-Consumer (SPSC) ring buffer require no mutexes or interrupt disabling?

Explanation: Since each index is modified by exactly one execution context, neither context can corrupt the other's state variable, eliminating race conditions.

Q5: What is the role of EXC_RETURN loaded into the Link Register (LR) upon interrupt entry?

Explanation: EXC_RETURN values (starting with 0xFFFFFFF) instruct the CPU on exit whether to unstack from MSP or PSP and whether the returning code was in Thread or Handler mode.
