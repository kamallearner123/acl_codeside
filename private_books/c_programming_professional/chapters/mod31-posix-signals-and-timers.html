Module 31: POSIX Signals & Real-Time Timers

Deep dive into asynchronous signal delivery, the strict POSIX async-signal-safety contract, converting signals to events via signalfd(2), clean shutdown architectures, and POSIX high-resolution real-time timers (timer_create, CLOCK_MONOTONIC).

⏱️ Duration: 50m
🎯 Standard: POSIX.1-2008 / Linux signalfd(2)
⚡ Target: Production Daemons & Real-Time Controllers

31.1 Signal Mechanics & The Async-Signal-Safety Trap

A Signal is an asynchronous software interrupt delivered by the Linux kernel to a process. When a signal arrives, the kernel interrupts whatever instruction the CPU is executing, pushes a synthetic signal frame onto the stack, and jumps to the signal handler function.

The Fatal Async-Signal-Safety Rule: Inside a traditional signal handler, you are STRICTLY FORBIDDEN from calling non-reentrant functions! Functions like printf(), malloc(), free(), and pthread_mutex_lock() acquire internal locks. If a signal interrupts a thread while that thread is already holding the internal malloc lock, calling malloc() inside the signal handler triggers an immediate, unrecoverable deadlock!

Only functions explicitly listed as Async-Signal-Safe in man 7 signal-safety (such as write(), _exit(), sigaction()) may be invoked inside signal handlers.

31.2 Modern Architecture: signalfd(2) Synchronous Consumption

To escape the hazards of asynchronous signal handlers, modern Linux provides signalfd(2). It converts asynchronous signals into a standard readable file descriptor!

signalfd Architecture: Unifying Signals into epoll
Kernel Signals (SIGINT, SIGTERM)
          │
          ▼ Blocked by sigprocmask() (Cannot interrupt threads!)
  [ signalfd File Descriptor ] ──(Readable Event)──▶ [ Unified epoll_wait Loop ]
                                                              │
                                                  Handles shutdown cleanly
                                                  using standard printf/free!

Setting Up signalfd with epoll

sigset_t mask;
sigemptyset(&mask);
sigaddset(&mask, SIGINT);
sigaddset(&mask, SIGTERM);

/* 1. Block signals so they do not invoke default interrupt handlers */
sigprocmask(SIG_BLOCK, &mask, NULL);

/* 2. Create signal file descriptor */
int sfd = signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);

/* 3. Register sfd directly with your epoll event loop! */
struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = sfd;
epoll_ctl(epoll_fd, EPOLL_CTL_ADD, sfd, &ev);

31.3 POSIX Real-Time Periodic Timers

Rather than relying on inaccurate sleep() loops, safety-critical real-time applications configure high-precision kernel timers using timer_create() bound to CLOCK_MONOTONIC: 

timer_t timerid;
struct sigevent sev = {0};
sev.sigev_notify = SIGEV_SIGNAL;
sev.sigev_signo = SIGRTMIN; /* Real-time signal */

timer_create(CLOCK_MONOTONIC, &sev, &timerid);

/* Configure 100 Hz periodic timer (every 10 ms) */
struct itimerspec its;
its.it_interval.tv_sec = 0;
its.it_interval.tv_nsec = 10000000; // 10 ms period
its.it_value = its.it_interval;     // Initial expiration

timer_settime(timerid, 0, &its, NULL);

31.4 Industrial Case Study: Flight Simulator Lockup via syslog() in Signal

The Commercial Flight Simulator Visual Engine Hang

A high-fidelity FAA Level D flight simulator visual projection system randomly locked up during training exercises. The simulation froze completely, requiring a hard reboot.

Investigation: Core dumps showed the rendering thread was deadlocked inside malloc(): 

#0  __lll_lock_wait () at futex.c
#1  __GI___libc_malloc () at malloc.c:2928
#2  syslog () at syslog.c:184
#3  <signal handler called> (SIGALRM)
#4  __GI___libc_malloc () at malloc.c:2910
#5  render_terrain_mesh () at terrain.c:452

Root Cause: The terrain rendering thread was allocating a dynamic vertex buffer when the SIGALRM timer signal fired. The signal handler called syslog() to record periodic telemetry.

Internally, syslog() calls malloc(). Because the thread already held the internal glibc heap arena lock at the moment of interruption, the second malloc() call attempted to acquire the same lock, resulting in an immediate self-deadlock!

Resolution: The async signal handler was completely removed and replaced with timerfd_create() integrated into the main epoll event loop.

31.5 Hands-On Lab: Graceful Daemon Shutdown with signalfd

In this lab, you will write a complete Linux server that handles SIGINT (Ctrl+C) and SIGTERM cleanly using signalfd() and an epoll event loop.

Graceful Shutdown Server (signalfd_daemon.c)

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/signalfd.h>
#include <sys/epoll.h>

int main(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGTERM);

    /* Block signals so they are delivered synchronously through signalfd */
    if (sigprocmask(SIG_BLOCK, &mask, NULL) < 0) {
        perror("sigprocmask");
        return 1;
    }

    int sfd = signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);
    int epfd = epoll_create1(EPOLL_CLOEXEC);

    struct epoll_event ev;
    ev.events = EPOLLIN;
    ev.data.fd = sfd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &ev);

    printf("[DAEMON] Running. Press Ctrl+C (SIGINT) to trigger graceful shutdown...
");

    int running = 1;
    while (running) {
        struct epoll_event events[4];
        int nfds = epoll_wait(epfd, events, 4, -1);
        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == sfd) {
                struct signalfd_siginfo fdsi;
                ssize_t s = read(sfd, &fdsi, sizeof(fdsi));
                if (s == sizeof(fdsi)) {
                    printf("
[SIGNAL] Caught signal %u (sender PID=%d)!
",
                           fdsi.ssi_signo, fdsi.ssi_pid);
                    printf("[CLEANUP] Flushing file buffers and freeing resources safely...
");
                    running = 0; // Terminate loop cleanly!
                }
            }
        }
    }

    close(sfd);
    close(epfd);
    printf("[DAEMON] Shutdown sequence completed cleanly. Exiting with code 0.
");
    return 0;
}

31.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why is calling printf() inside an asynchronous signal handler dangerous?

Explanation: printf is not async-signal-safe because it relies on non-reentrant stdio buffer locks.

Q2: What Linux system call converts incoming signals into readable events on a file descriptor?

Explanation: signalfd() provides a descriptor interface for consuming signals synchronously via read() and epoll.

Q3: What clock source should be used for real-time periodic timers to prevent time jumps when NTP syncs the system clock?

Explanation: CLOCK_MONOTONIC advances strictly monotonically at constant speed and is immune to discontinuous system wall-clock adjustments.

Q4: Before reading signals from signalfd, what must be done with sigprocmask()?

Explanation: Blocking the signals prevents the kernel from executing default actions (e.g. terminating the process on SIGINT) so the signal is queued for signalfd.

Q5: Which of the following data types is guaranteed by the C standard to be read and written atomically in a signal handler?

Explanation: sig_atomic_t is guaranteed by ISO C to be modified as an atomic entity even in the presence of asynchronous signals.
