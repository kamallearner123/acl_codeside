Part 5 • Testing & QA Engineering

Module 22: Unit Testing with Unity & CMock

Master embedded unit testing architectures using the industry-standard Unity test framework and CMock function mocking engine. Learn how to decouple hardware dependencies, execute test suites 1,000x faster on development hosts, and assert memory buffers, struct layouts, and error states.

⏱️ Duration: 55m
🎯 Standard: ISO 26262 Part 6 / DO-178C Level B / Unity 2.5+
⚡ Target: Host x86_64 / Cross-Compiled QEMU

22.1 The Embedded Testing Pyramid & Host-Based Verification

In traditional embedded workflows, engineers write firmware, flash a physical target board over JTAG/SWD, and probe with an oscilloscope or printf. This workflow is painfully slow (15-60 seconds per debug iteration) and fails to scale across complex state machines.

The Embedded Software Testing Pyramid
                 ▲
                ╱ ╲
               ╱ HIL╲          Hardware-In-The-Loop: Real physical silicon, oscilloscopes,
              ╱──────╲         environmental chambers. (~10-50 tests/day)
             ╱ System ╲        Board-level firmware execution, complete peripherals.
            ╱──────────╲       (~100-500 tests/day)
           ╱ Integration╲      Subsystem interaction, simulated buses, RTOS tasks.
          ╱──────────────╲     (~1,000 tests/hour)
         ╱   Unit Tests   ╲    Host-compiled pure C algorithms, Unity/CMock, 100% mocks.
        ╱──────────────────╲   (> 10,000 tests in under 2 seconds!)

By isolating hardware register accesses behind abstract HAL boundaries, 90% of embedded firmware algorithms (parsers, state machines, protocol decoders, PID loops, memory managers) can be compiled with host GCC or Clang and validated in fractions of a second on developer workstations and in CI/CD pipelines.

22.2 The Unity Test Framework Architecture

Unity is an ultra-lightweight, ANSI C-compliant test harness engineered specifically for embedded and resource-constrained environments. It requires zero dynamic memory allocation and outputs standardized ASCII or TAP test reports.

Unity Execution Lifecycle

Each individual test case executes inside a strictly defined lifecycle sandwich:

  1. setUp(void): Invoked automatically prior to every single test function. Resets global state, reinitializes circular buffers, and zeroes mock expectations.
  2. test_FunctionName(void): The unit test body containing assertions.
  3. tearDown(void): Invoked automatically following every single test function. Frees allocated test buffers and validates that no unhandled mock calls remain.

Production Unity Assertions

/* Exact integer comparisons */
TEST_ASSERT_EQUAL_INT32(expected_int, actual_int);
TEST_ASSERT_EQUAL_HEX32(0xDEADBEEF, register_val);

/* Null pointer checks */
TEST_ASSERT_NOT_NULL(sensor_handle);
TEST_ASSERT_NULL(invalid_handle);

/* Float comparisons with delta tolerances */
TEST_ASSERT_FLOAT_WITHIN(0.001f, 3.300f, measured_voltage);

/* Memory and byte-array comparisons */
TEST_ASSERT_EQUAL_MEMORY(expected_packet, received_packet, sizeof(packet_t));
TEST_ASSERT_EQUAL_UINT8_ARRAY(expected_bytes, buffer, 16);

22.3 CMock & Function Mocking Mechanics

Unit testing requires isolating the Unit Under Test (UUT) from its external collaborators. When testing a temperature telemetry module that writes to I2C, you must not invoke physical I2C hardware. Instead, you link against a Mock Object.

CMock parses C header files (such as i2c_driver.h) and automatically generates mock implementations of every declared function.

CMock Expectation Patterns

/* 1. Expect call with exact parameters and return a specific status */
i2c_write_ExpectAndReturn(0x48, expected_payload, 2, I2C_STATUS_OK);

/* 2. Expect call and validate an array parameter */
i2c_write_ExpectWithArray(0x48, 1, expected_data, 1, 1, 4, I2C_STATUS_OK);

/* 3. Ignore arguments and return error (simulating hardware bus failure) */
i2c_read_IgnoreAndReturn(I2C_STATUS_BUS_ERROR);

22.4 Decoupling Time & Interrupts in Unit Tests

Embedded code frequently uses hardware timers or delay loops (such as HAL_Delay(100)). If executed naively on a host machine, unit tests would crawl at real-time speeds, and testing a 10-minute timeout would take 10 minutes.

The Solution: Time Injection. Provide a virtual clock interface: 

/* Virtual Time Interface */
typedef uint32_t (*time_get_ticks_fn)(void);

static uint32_t g_fake_ticks = 0;
uint32_t mock_get_ticks(void) { return g_fake_ticks; }

void test_telemetry_timeout(void) {
    g_fake_ticks = 0;
    telemetry_start();
    
    /* Warp time forward by 5000 milliseconds instantaneously! */
    g_fake_ticks += 5000;
    telemetry_process();
    
    TEST_ASSERT_EQUAL(TELEMETRY_STATE_TIMEOUT, telemetry_get_state());
}

22.5 Industrial Case Study: Therac-25 Medical Radiation Disaster

The Lethal Software Race Condition in Medical Linear Accelerators

Between 1985 and 1987, the Therac-25 medical radiation machine administered massive radiation overdoses (over 100 times the intended therapeutic dose) to multiple oncology patients, causing severe radiation poisoning and deaths.

The Software Defect: The operator console allowed the technician to select "X-Ray Mode" (which uses a high-energy electron beam deflected by a physical tungsten target plate) or "Electron Mode" (which uses a low-energy beam without the target).

If a skilled technician accidentally pressed "X-Ray", quickly hit "Up Arrow", and corrected it to "Electron Mode" within an eight-second window, an unhandled race condition occurred:

  • The software reset the machine state variables indicating Electron Mode.
  • However, the subroutine positioning the heavy mechanical tungsten shield took several seconds to respond and did not move the shield into place!
  • The software fired the raw, unattenuated 25 MeV high-current beam directly into human tissue without the attenuating target in place.

How Unit Testing Prevents This: Therac-25 was tested almost exclusively as a whole integrated machine; developers never unit-tested the keyboard entry parser and motor positioning state transitions independently. Host-based unit testing with randomized input fuzzing would have executed millions of rapid state transitions, instantly uncovering the missing synchronization between user input validation and mechanical actuator interlocks.

22.6 Hands-On Lab: Complete Unity Test Suite for an Embedded Circular Ring Buffer

In this laboratory, you will construct a production FIFO circular ring buffer and develop an exhaustive Unity test harness verifying boundary conditions: initialization, full buffer rejection, FIFO order preservation, and wrap-around mechanics.

1. Production Ring Buffer Header (ring_buf.h)

#ifndef RING_BUF_H_
#define RING_BUF_H_

#include <stdint.h>
#include <stdbool.h>

#define RING_BUF_CAPACITY 8U

typedef struct {
    uint8_t buffer[RING_BUF_CAPACITY];
    uint32_t head;
    uint32_t tail;
    uint32_t count;
} ring_buf_t;

void ring_buf_init(ring_buf_t *rb);
bool ring_buf_push(ring_buf_t *rb, uint8_t byte);
bool ring_buf_pop(ring_buf_t *rb, uint8_t *out_byte);
bool ring_buf_is_empty(const ring_buf_t *rb);
bool ring_buf_is_full(const ring_buf_t *rb);

#endif /* RING_BUF_H_ */

2. Production Implementation (ring_buf.c)

#include "ring_buf.h"

void ring_buf_init(ring_buf_t *rb) {
    if (!rb) return;
    rb->head = 0;
    rb->tail = 0;
    rb->count = 0;
}

bool ring_buf_push(ring_buf_t *rb, uint8_t byte) {
    if (!rb || ring_buf_is_full(rb)) return false;
    rb->buffer[rb->head] = byte;
    rb->head = (rb->head + 1U) % RING_BUF_CAPACITY;
    rb->count++;
    return true;
}

bool ring_buf_pop(ring_buf_t *rb, uint8_t *out_byte) {
    if (!rb || !out_byte || ring_buf_is_empty(rb)) return false;
    *out_byte = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1U) % RING_BUF_CAPACITY;
    rb->count--;
    return true;
}

bool ring_buf_is_empty(const ring_buf_t *rb) {
    return (rb != (void *)0) ? (rb->count == 0U) : true;
}

bool ring_buf_is_full(const ring_buf_t *rb) {
    return (rb != (void *)0) ? (rb->count >= RING_BUF_CAPACITY) : false;
}

3. Exhaustive Unity Test Suite (test_ring_buf.c)

#include "unity.h"
#include "ring_buf.h"

static ring_buf_t g_rb;

void setUp(void) {
    ring_buf_init(&g_rb);
}

void tearDown(void) {
    /* Cleanup after each test */
}

void test_initial_state_is_empty(void) {
    TEST_ASSERT_TRUE(ring_buf_is_empty(&g_rb));
    TEST_ASSERT_FALSE(ring_buf_is_full(&g_rb));
    TEST_ASSERT_EQUAL_UINT32(0, g_rb.count);
}

void test_push_and_pop_single_byte(void) {
    uint8_t popped = 0;
    TEST_ASSERT_TRUE(ring_buf_push(&g_rb, 0x42));
    TEST_ASSERT_EQUAL_UINT32(1, g_rb.count);
    TEST_ASSERT_FALSE(ring_buf_is_empty(&g_rb));

    TEST_ASSERT_TRUE(ring_buf_pop(&g_rb, &popped));
    TEST_ASSERT_EQUAL_HEX8(0x42, popped);
    TEST_ASSERT_TRUE(ring_buf_is_empty(&g_rb));
}

void test_buffer_overflow_rejection(void) {
    for (uint8_t i = 0; i < RING_BUF_CAPACITY; i++) {
        TEST_ASSERT_TRUE(ring_buf_push(&g_rb, i));
    }
    TEST_ASSERT_TRUE(ring_buf_is_full(&g_rb));

    /* Attempting to push past capacity must fail gracefully */
    TEST_ASSERT_FALSE(ring_buf_push(&g_rb, 0xFF));
    TEST_ASSERT_EQUAL_UINT32(RING_BUF_CAPACITY, g_rb.count);
}

void test_fifo_wrap_around_preserves_order(void) {
    uint8_t byte = 0;
    /* Fill 4 bytes, pop 4 bytes to advance tail */
    for (uint8_t i = 1; i <= 4; i++) ring_buf_push(&g_rb, i);
    for (uint8_t i = 1; i <= 4; i++) ring_buf_pop(&g_rb, &byte);

    /* Now push across the array wrap-around boundary */
    for (uint8_t i = 10; i < 18; i++) {
        TEST_ASSERT_TRUE(ring_buf_push(&g_rb, i));
    }
    TEST_ASSERT_TRUE(ring_buf_is_full(&g_rb));

    /* Verify FIFO extraction across wrap-around */
    for (uint8_t expected = 10; expected < 18; expected++) {
        TEST_ASSERT_TRUE(ring_buf_pop(&g_rb, &byte));
        TEST_ASSERT_EQUAL_UINT8(expected, byte);
    }
    TEST_ASSERT_TRUE(ring_buf_is_empty(&g_rb));
}

int main(void) {
    UNITY_BEGIN();
    RUN_TEST(test_initial_state_is_empty);
    RUN_TEST(test_push_and_pop_single_byte);
    RUN_TEST(test_buffer_overflow_rejection);
    RUN_TEST(test_fifo_wrap_around_preserves_order);
    return UNITY_END();
}

22.7 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: In the Unity test framework, what function is guaranteed to run before each and every individual test case?

Explanation: setUp() resets environmental prerequisites and state variables immediately prior to executing every single test case, ensuring complete isolation between tests.

Q2: What is the primary architectural purpose of a Mock Object generated by CMock?

Explanation: Mocks decouple the Unit Under Test from real peripheral drivers and buses, allowing tests to run purely on PC development machines.

Q3: Why is host-based unit testing significantly faster than testing on physical target evaluation boards?

Explanation: Erasing and flashing microcontroller flash memory over SWD typically takes 5 to 30 seconds per iteration; compiling and running on an x86/ARM64 host takes under 50 milliseconds.

Q4: What assertion macro should be used to verify that an unattenuated floating-point calculation yields 3.1415 within a margin of 0.0001?

Explanation: Due to IEEE-754 floating-point rounding imprecision, floats should never be compared with exact equality (==); delta-tolerance assertions must always be used.

Q5: How can a unit test verify firmware behavior across a 1-hour timeout without stalling test execution for an hour?

Explanation: Decoupling firmware from real wall-clock hardware timers allows unit tests to inject arbitrary time leaps instantaneously.
