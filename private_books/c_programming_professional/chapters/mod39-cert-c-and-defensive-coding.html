Module 39: CERT C & Defensive Coding Practices

Master the SEI CERT C Secure Coding Standard. Deep dive into integer wrap-around vulnerabilities (INT30-C/INT32-C), string boundary truncation hazards (STR31-C), pointer sanitization post-free (MEM30-C), branchless overflow detection, and defensive contract programming in C.

⏱️ Duration: 55m
🎯 Standard: SEI CERT C Coding Standard / Common Weakness Enumeration (CWE)
⚡ Target: High-Security Networked & Embedded C Software

39.1 MISRA C vs. CERT C: Functional Safety vs. Security

Engineers frequently ask: "If our codebase is MISRA-compliant, is it secure?"

Not necessarily! MISRA C was designed primarily for Functional Safety (ensuring software does not fail randomly in closed automotive/avionics environments). CERT C was designed by Carnegie Mellon’s Software Engineering Institute explicitly for Cybersecurity (preventing active malicious adversaries from exploiting software vulnerabilities).

Safety vs. Security Standards Spectrum
MISRA C:2012 / 2023 ──▶ Focus: Reliability, determinism, banning risky C syntax.
                        Audience: Closed embedded ECUs, braking, steering, avionics.

CERT C Standard     ──▶ Focus: Defeating malicious exploits, buffer overflows, tainted data.
                        Audience: Connected devices, IoT, networking stacks, Linux services.

39.2 Top CERT C Vulnerabilities & Mitigations

1. INT30-C & INT32-C: Integer Overflow & Wrap-Around

In C, unsigned integer overflow wraps around modulo 2^N. Signed integer overflow is Undefined Behavior!

Exploitable Integer Wrap-Around: 
/* VULNERABLE: If num_items = 0x40000001 on 32-bit:
   num_items * sizeof(int) wraps to 4 bytes!
   malloc allocates 4 bytes, but loop writes 1 GB of data, corrupting heap! */
void *allocate_array(size_t num_items) {
    return malloc(num_items * sizeof(int));
}

Secure Multiplication Bounds Check (CERT INT30-C Compliant)

#include <stdint.h>
#include <stddef.h>

void *secure_allocate_array(size_t num_items, size_t elem_size) {
    if (elem_size == 0 || num_items == 0) return NULL;

    /* Check for overflow before multiplying */
    if (num_items > (SIZE_MAX / elem_size)) {
        return NULL; /* Overflow prevented! */
    }

    return malloc(num_items * elem_size);
}

2. STR31-C: String Copying & Truncation

Legacy C string functions (strcpy, strcat, sprintf) do not perform bounds checking and cause catastrophic stack buffer overflows.

Even strncpy is hazardous: if the source string exceeds the destination buffer length, strncpy does not null-terminate the destination! 

/* SECURE STRING COPY PATTERN */
void secure_copy(char *dest, size_t dest_size, const char *src) {
    if (!dest || dest_size == 0 || !src) return;
    snprintf(dest, dest_size, "%s", src);
    dest[dest_size - 1] = ''; /* Guaranteed null-termination */
}

3. MEM30-C: Dangling Pointers & Use-After-Free

When memory is freed, the pointer variable still holds the physical address of the deallocated memory. Accessing it is undefined behavior. 

/* DEFENSIVE POINTER SCRUBBING MACRO */
#define SAFE_FREE(ptr) do {     free(ptr);                  (ptr) = NULL;           } while(0)

39.3 Compiler Built-in Safe Arithmetic

Modern GCC and Clang provide hardware-accelerated integer overflow builtins that check CPU carry and overflow flags directly in a single assembly instruction: 

uint32_t a = 0xFFFFFFFF;
uint32_t b = 10;
uint32_t result;

/* Branchless, Hardware-Assisted Overflow Detection */
if (__builtin_add_overflow(a, b, &result)) {
    /* Overflow occurred! Handle defensively */
} else {
    /* Valid result */
}

39.4 Industrial Case Study: Automotive Remote Keyless Entry Exploit

The Rolling Code 16-Bit Wrap-Around Vehicle Theft Bug

Security researchers discovered that a popular line of vehicles could be unlocked by replaying intercepted RF key fob transmissions.

Vulnerability Analysis: The vehicle verified rolling codes using a 16-bit sequence counter. To prevent denial-of-service when buttons were pressed away from the car, the car accepted sequence numbers within a future window of 256 counts: 

/* Vulnerable Sequence Check */
if ((received_seq - stored_seq) < 256) {
    unlock_doors();
}

Due to implicit integer promotion to 32-bit signed integers, when received_seq = 0x0005 and stored_seq = 0xFFF0 (normal counter wrap-around), the expression evaluated as 5 - 65520 = -65515. Because -65515 < 256 is true, the car unlocked!

Worse: an adversary transmitting received_seq = 0 always produced a negative number, unlocking the vehicle instantly at any time!

The Fix: Explicit unsigned arithmetic masking adhering to CERT INT30-C.

39.5 Hands-On Lab: Writing a Secure Integer Arithmetic Library

In this lab, you will write a complete, MISRA and CERT compliant safe arithmetic library in C providing overflow-checked addition, subtraction, and multiplication.

Safe Math Library (safe_math.h & safe_math.c)

#include <stdint.h>
#include <stdbool.h>

bool safe_add_u32(uint32_t a, uint32_t b, uint32_t *out) {
    if (!out) return false;
    #if defined(__GNUC__) || defined(__clang__)
        return !__builtin_add_overflow(a, b, out);
    #else
        if (UINT32_MAX - a < b) return false;
        *out = a + b;
        return true;
    #endif
}

bool safe_mul_u32(uint32_t a, uint32_t b, uint32_t *out) {
    if (!out) return false;
    #if defined(__GNUC__) || defined(__clang__)
        return !__builtin_mul_overflow(a, b, out);
    #else
        if (a > 0 && b > (UINT32_MAX / a)) return false;
        *out = a * b;
        return true;
    #endif
}

39.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: According to ISO C standards, what is the consequence of signed integer overflow?

Explanation: Signed integer overflow is undefined behavior in ISO C; compilers assume overflow can never occur and may delete downstream bounds checks.

Q2: What CERT C rule mandates setting pointer variables to NULL immediately following free()?

Explanation: Setting pointers to NULL after freeing prevents dangling pointer dereferences and double-free vulnerabilities.

Q3: What dangerous behavior occurs with standard strncpy(dest, src, n) if strlen(src) >= n?

Explanation: strncpy fails to append a null terminator if the source length equals or exceeds n, leaving dest as an unterminated character array.

Q4: What GCC builtin performs hardware-checked integer addition and returns true on overflow?

Explanation: __builtin_add_overflow(a, b, &res) executes single-cycle arithmetic and tests the hardware overflow flag directly.

Q5: How can multiplication overflow be checked prior to executing a * b without builtins?

Explanation: Precondition checking using division (a > MAX / b) detects overflow before the arithmetic operation executes.
