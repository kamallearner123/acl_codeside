Module 33: Memory-Mapped I/O (MMIO) & Register Control

Master bare-metal peripheral manipulation on ARM Cortex-M processors. Deep dive into Advanced Microcontroller Bus Architecture (AHB/APB), memory barriers (DMB, DSB, ISB), atomic register modification via Bit Set/Reset Registers (BSRR), CMSIS register struct mappings, and optimizer traps with volatile.

⏱️ Duration: 65m
🎯 Standard: ARMv7-M Architecture / CMSIS-Core / C11
⚡ Target: ARM Cortex-M4 / STM32F4 Bare-Metal

33.1 ARM Cortex-M Bus Architecture & MMIO

Unlike x86 processors that feature dedicated I/O ports (in/out assembly instructions), ARM microcontrollers utilize Memory-Mapped I/O (MMIO). All on-chip peripherals (GPIO, Timers, UART, I2C, DMA) share the unified 4-gigabyte 32-bit linear address space alongside Flash ROM and SRAM.

ARM Cortex-M Internal Bus Matrix & Address Map
0xFFFFFFFF ┌────────────────────────────────────────────────────────┐
           │ System Control Space (NVIC, SysTick, MPU: 0xE000E000)  │ <-- Internal Core Bus
0xE0000000 ├────────────────────────────────────────────────────────┤
           │ External Peripherals / Devices (0xA0000000)            │
0x60000000 ├────────────────────────────────────────────────────────┤
           │ Peripherals Bus (APB1: 0x40000000, APB2: 0x40010000,   │
           │                  AHB1: 0x40020000 - GPIO, RCC, DMA)    │ <-- AHB/APB Bridges
0x40000000 ├────────────────────────────────────────────────────────┤
           │ SRAM (0x20000000 - 0x2001FFFF: 128 KB SRAM1/SRAM2)     │ <-- System Bus (S-Bus)
0x20000000 ├────────────────────────────────────────────────────────┤
           │ Flash ROM (0x08000000 - 0x0807FFFF: 512 KB Flash)      │ <-- I-Code & D-Code Bus
0x00000000 └────────────────────────────────────────────────────────┘

33.2 The Critical Role of the volatile Qualifier

In standard C, the optimizing compiler assumes that a memory location only changes if modified by explicit program statements. For hardware peripheral registers (such as an ADC data register or UART status register), the value can change asynchronously due to external physical events or silicon hardware logic!

The Deadlock Optimization Bug: If you omit volatile on a hardware register read: 
/* FATAL ERROR: Omission of volatile */
uint32_t *status_reg = (uint32_t *)0x40011000;
while ((*status_reg & 0x01) == 0) { /* Wait for hardware flag */ }
Under -O2 optimization, the compiler hoists the read outside the loop: 
ldr r2, [r3]       ; Read register once into register R2
.L2:
tst r2, #1         ; Test register R2
beq .L2            ; Infinite loop! CPU never reads hardware memory again!

Marking pointers as volatile uint32_t * forces the compiler to emit a physical load/store bus transaction on every single access, respecting sequence points.

33.3 Atomic GPIO Toggling via BSRR Registers

A common beginner mistake when toggling a GPIO pin is using read-modify-write on the output data register: 

/* Non-Atomic Read-Modify-Write (Race Hazard!) */
GPIOA->ODR |= (1 << 5); /* Read ODR, Modify in ALU, Write back to ODR */

If a high-priority interrupt preempts execution between the Read and the Write instructions and modifies another pin on GPIOA, the mainline code will overwrite and destroy the interrupt’s pin state upon resuming!

The Silicon Solution: Bit Set/Reset Register (BSRR). Writing a 1 to the lower 16 bits atomically sets the pin; writing a 1 to the upper 16 bits atomically resets the pin. Writes of 0 have no effect. Zero read-modify-write! Zero interrupt disabling needed! 

/* Atomic 1-cycle Pin Manipulation */
GPIOA->BSRR = (1U << 5);       /* Atomically SET Pin 5 high */
GPIOA->BSRR = (1U << (5 + 16)); /* Atomically RESET Pin 5 low */

33.4 Memory Barriers: DMB, DSB, and ISB

Modern out-of-order execution pipelines and write buffers can reorder memory transactions. Cortex-M provides dedicated architectural barriers:

  • DMB (Data Memory Barrier): Ensures that all explicit memory accesses before the barrier complete before any memory accesses after the barrier. Critical for lock-free ring buffers and DMA transfers.
  • DSB (Data Synchronization Barrier): Halts instruction execution until all outstanding memory bus operations have physically finished. Mandatory after configuring clock registers or disabling interrupts before entering sleep (WFI).
  • ISB (Instruction Synchronization Barrier): Flushes the CPU instruction pipeline, forcing instructions to be refetched from cache/flash. Mandatory after reconfiguring the Memory Protection Unit (MPU) or modifying vector table base addresses (VTOR).

33.5 Industrial Case Study: The Medical Infusion Pump Motor Stalling Bug

The Disappearing Motor Pulse Under Compiler Optimization

An infusion pump stepper motor driver missed 10% of motor steps when the firmware was compiled with -O2 release flags, though it operated flawlessly under -O0 debug builds.

Investigation: The pulse generation routine generated a 2-microsecond high pulse by writing directly to GPIO: 

/* Defective Pulse Generation */
GPIO_TypeDef *gpio = (GPIO_TypeDef *)0x40020000;
gpio->ODR |= (1 << 2); // Motor step HIGH
delay_us(2);
gpio->ODR &= ~(1 << 2); // Motor step LOW

Because the vendor header file mistakenly omitted volatile on the ODR member in a custom HAL typedef, the compiler optimizer merged the two stores and eliminated the high pulse completely as dead code!

Resolution: The typedef was corrected to enforce __IO uint32_t ODR; (where __IO expands to volatile in CMSIS), and pin toggling was refactored to use the atomic BSRR register with a compiler memory barrier.

33.6 Hands-On Lab: Writing a Register-Accurate Bare-Metal GPIO Driver

In this laboratory, you will write a complete, MISRA-compliant bare-metal C driver for the STM32F4 GPIO port from scratch, defining CMSIS register structs, configuring clock gating, and toggling an LED using BSRR.

Complete Bare-Metal Driver (gpio_driver.c)

#include <stdint.h>

/* Base Addresses from STM32F4 Reference Manual */
#define RCC_BASE        (0x40023800UL)
#define GPIOA_BASE      (0x40020000UL)

/* RCC Register Map */
typedef struct {
    volatile uint32_t CR;
    volatile uint32_t PLLCFGR;
    volatile uint32_t CFGR;
    volatile uint32_t CIR;
    volatile uint32_t AHB1RSTR;
    volatile uint32_t AHB2RSTR;
    volatile uint32_t AHB3RSTR;
    uint32_t          RESERVED0;
    volatile uint32_t APB1RSTR;
    volatile uint32_t APB2RSTR;
    uint32_t          RESERVED1[2];
    volatile uint32_t AHB1ENR; /* GPIOA clock enable bit 0 */
} RCC_TypeDef;

/* GPIO Register Map */
typedef struct {
    volatile uint32_t MODER;   /* Mode register */
    volatile uint32_t OTYPER;  /* Output type register */
    volatile uint32_t OSPEEDR; /* Output speed register */
    volatile uint32_t PUPDR;   /* Pull-up/pull-down register */
    volatile uint32_t IDR;     /* Input data register */
    volatile uint32_t ODR;     /* Output data register */
    volatile uint32_t BSRR;    /* Bit set/reset register (Atomic) */
    volatile uint32_t LCKR;    /* Configuration lock register */
    volatile uint32_t AFR[2];  /* Alternate function registers */
} GPIO_TypeDef;

#define RCC   ((RCC_TypeDef *)RCC_BASE)
#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)

void led_init(void) {
    /* 1. Enable Clock to GPIOA (Bit 0 of AHB1ENR) */
    RCC->AHB1ENR |= (1U << 0);

    /* Memory barrier ensuring clock is active before touching GPIO registers */
    __asm__ volatile("dsb" ::: "memory");

    /* 2. Configure Pin PA5 as General Purpose Output (Mode 01) */
    GPIOA->MODER &= ~(3U << (5 * 2)); // Clear mode bits 10 and 11
    GPIOA->MODER |=  (1U << (5 * 2)); // Set mode to 01 (Output)

    /* 3. Configure Push-Pull Output (OTYPER bit 5 = 0) */
    GPIOA->OTYPER &= ~(1U << 5);

    /* 4. Configure High Speed (OSPEEDR bits = 10) */
    GPIOA->OSPEEDR |= (2U << (5 * 2));
}

void led_set(void) {
    /* Atomically set PA5 high */
    GPIOA->BSRR = (1U << 5);
}

void led_clear(void) {
    /* Atomically reset PA5 low (Bit 5 + 16 = 21) */
    GPIOA->BSRR = (1U << 21);
}

33.7 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why is writing to the Bit Set/Reset Register (BSRR) preferred over modifying the Output Data Register (ODR)?

Explanation: BSRR allows setting or clearing specific pins atomically via a single 32-bit write, avoiding the hazard where an interrupt preempts a read-modify-write on ODR.

Q2: What happens if you omit the volatile qualifier when defining pointers to hardware registers?

Explanation: volatile informs the compiler that the value may change outside program control, preventing the optimizer from eliding memory reads or caching values.

Q3: Which ARM architectural barrier instruction flushes the instruction pipeline and forces refetching?

Explanation: ISB flushes the processor pipeline, ensuring that subsequent instructions are fetched afresh following MPU, cache, or memory mapping reconfigurations.

Q4: What bus bridge on the STM32 connects high-speed CPU peripherals (such as DMA and GPIO) to the system crossbar?

Explanation: AHB connects high-bandwidth peripherals (GPIO, DMA, Flash memory, Ethernet) directly to the multi-layer bus matrix at full CPU clock speeds.

Q5: What is the primary risk of using C bitfields (e.g. struct { uint32_t pin0:1; }) for memory-mapped hardware registers?

Explanation: Bitfield layout in memory is implementation-defined by ISO C; moreover, updating a bitfield requires multi-cycle read-modify-write instructions that introduce race conditions on hardware registers.
