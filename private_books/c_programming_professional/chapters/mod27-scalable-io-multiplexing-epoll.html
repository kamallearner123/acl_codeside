Module 27: Scalable I/O Multiplexing (epoll)

Master high-concurrency event-driven network I/O in C. Deep dive into the limits of select and poll (the C10K problem), Linux epoll kernel architecture (Red-Black tree and ready-list wait queues), Edge-Triggered (EPOLLET) vs Level-Triggered (EPOLLLT) mechanics, and non-blocking socket drains.

⏱️ Duration: 60m
🎯 Standard: Linux epoll(7) / Non-Blocking POSIX Sockets
⚡ Target: High-Concurrency Linux Network Daemons

27.1 The C10K Problem & The Death of select/poll

In early Unix network programming, handling multiple concurrent network connections relied on select(2) or poll(2).

Algorithmic Scaling: select/poll vs epoll
1. select() / poll() - O(N) Linear Scanning:
   User Space ──(Passes 10,000 FDs array)──▶ Kernel
                                               │ Iterates across all 10,000 FDs linearly
                                               ▼
   User Space ◀──(Returns 10,000 FDs array)── Kernel
   (User must iterate 10,000 FDs in user space to find the 2 active sockets!)

2. epoll - O(1) Ready-List Traversal:
   User Space ──(epoll_wait)──▶ Kernel
                                  │ Reads only the active 'rdllist' (populated by ISRs)
                                  ▼
   User Space ◀──(Returns ONLY the 2 active FDs!)── Kernel
Dimension select(2) poll(2) epoll(7)
Computational Complexity O(N) O(N) O(1) (proportional only to active events)
Max File Descriptors Hardcoded 1024 (FD_SETSIZE) Limited by process FD limit Unlimited (Millions of sockets)
User-Kernel Copies Copies full bitmask every syscall Copies full array every syscall Zero (State maintained in kernel RB-Tree)

27.2 Linux epoll Kernel Architecture

When you invoke epoll_create1(EPOLL_CLOEXEC), the Linux kernel allocates an internal struct eventpoll holding two central data structures:

  1. Interest List (Red-Black Tree - rbr): Stores all monitored file descriptors keyed by FD integer. Allows O(log N) insertion, modification, and deletion via epoll_ctl().
  2. Ready List (Doubly-Linked List - rdllist): Contains only those file descriptors that currently possess active I/O events. When incoming Ethernet packets arrive, the network driver's hardware ISR fires, and the kernel network stack places the socket onto the ready list. epoll_wait() simply extracts entries from this list in O(1) time.

27.3 Edge-Triggered (EPOLLET) vs Level-Triggered (EPOLLLT)

Understanding the difference between Level-Triggered (the default) and Edge-Triggered mode is mandatory for writing bug-free epoll servers:

  • Level-Triggered (EPOLLLT): epoll_wait() continuously returns the file descriptor as long as unread data remains in the kernel socket buffer. If you read only 10 bytes out of 100 bytes, the next call to epoll_wait() immediately wakes up again.
  • Edge-Triggered (EPOLLET): epoll_wait() returns the file descriptor only when a state transition occurs (e.g. from empty buffer to having data). If you do not drain the socket completely, epoll will never notify you again for the remaining data, causing permanent connection lockup!
Golden Rule of Edge-Triggered epoll: When using EPOLLET, sockets must be non-blocking (O_NONBLOCK), and reads must be wrapped in a while loop that drains data continuously until read() returns -1 with errno == EAGAIN or errno == EWOULDBLOCK!

27.4 Industrial Case Study: The Edge-Triggered Telemetry Stall

The Smart Factory Gateway Deadlock

An industrial IoT edge gateway connected to 2,000 manufacturing sensors started dropping sensor packets during high-load manufacturing shifts. Connections remained open, but no new telemetry was ingested.

Root Cause: The developer configured epoll with EPOLLET (Edge-Triggered) for maximum performance, but read data using a single read() call with a 1,024-byte buffer: 

/* Defective Edge-Triggered Handler */
if (events[i].events & EPOLLIN) {
    ssize_t bytes = read(events[i].data.fd, buffer, sizeof(buffer));
    process_telemetry(buffer, bytes);
    /* BUG: If the sensor transmitted 1,500 bytes, 476 bytes remained in kernel buffer!
       Because epoll is Edge-Triggered, it never re-notified for the remaining 476 bytes!
       The socket stalled forever awaiting another edge transition! */
}

The Fix: The read handler was rewritten to execute inside an EAGAIN drain loop, ensuring all buffered bytes were consumed before returning to epoll_wait().

27.5 Hands-On Lab: Scalable Non-Blocking epoll TCP Echo Server

In this lab, you will construct a production-ready, non-blocking TCP server in C using epoll_create1(), epoll_ctl(), and epoll_wait() capable of serving thousands of simultaneous clients.

Complete Compilable Server (epoll_server.c)

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/epoll.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define MAX_EVENTS 64
#define BUFFER_SIZE 512
#define PORT 8080

static int make_socket_non_blocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags == -1) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

int main(void) {
    int server_fd = socket(AF_INET, SOCK_STREAM, 0);
    int opt = 1;
    setsockopt(server_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_addr.s_addr = INADDR_ANY;
    address.sin_port = htons(PORT);

    bind(server_fd, (struct sockaddr *)&address, sizeof(address));
    listen(server_fd, SOMAXCONN);
    make_socket_non_blocking(server_fd);

    int epoll_fd = epoll_create1(EPOLL_CLOEXEC);
    struct epoll_event ev, events[MAX_EVENTS];

    ev.events = EPOLLIN;
    ev.data.fd = server_fd;
    epoll_ctl(epoll_fd, EPOLL_CTL_ADD, server_fd, &ev);

    printf("[SERVER] Listening on port %d with epoll...
", PORT);

    while (1) {
        int nfds = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == server_fd) {
                /* New incoming connection */
                struct sockaddr_in client_addr;
                socklen_t client_len = sizeof(client_addr);
                int client_fd = accept(server_fd, (struct sockaddr *)&client_addr, &client_len);
                make_socket_non_blocking(client_fd);

                ev.events = EPOLLIN | EPOLLET; /* Edge-Triggered */
                ev.data.fd = client_fd;
                epoll_ctl(epoll_fd, EPOLL_CTL_ADD, client_fd, &ev);
                printf("[ACCEPT] Client connected: FD %d
", client_fd);
            } else {
                /* Data available from client (Drain until EAGAIN) */
                int fd = events[i].data.fd;
                char buf[BUFFER_SIZE];
                while (1) {
                    ssize_t count = read(fd, buf, sizeof(buf));
                    if (count > 0) {
                        write(fd, buf, (size_t)count); // Echo back
                    } else if (count == 0) {
                        /* Client disconnected */
                        printf("[CLOSE] Client disconnected: FD %d
", fd);
                        epoll_ctl(epoll_fd, EPOLL_CTL_DEL, fd, NULL);
                        close(fd);
                        break;
                    } else {
                        if (errno == EAGAIN || errno == EWOULDBLOCK) {
                            /* Fully drained! */
                            break;
                        }
                        perror("read error");
                        epoll_ctl(epoll_fd, EPOLL_CTL_DEL, fd, NULL);
                        close(fd);
                        break;
                    }
                }
            }
        }
    }
    close(server_fd);
    return 0;
}

27.6 Knowledge Verification & Self-Study Quiz

Self-Assessment Check

Q1: Why does epoll_wait() achieve O(1) performance while poll() degrades at O(N)?

Explanation: poll() must iterate through the entire array of file descriptors to check for readiness; epoll returns only descriptors that have already transitioned onto the kernel ready list.

Q2: What error code from read() signifies that a non-blocking socket has been completely drained under Edge-Triggered (EPOLLET) mode?

Explanation: In non-blocking sockets, EAGAIN / EWOULDBLOCK indicates that no more data is currently available in the kernel buffer and subsequent reads would block.

Q3: What internal kernel data structure does epoll use to store the registered interest list of file descriptors?

Explanation: The interest list is stored in a Red-Black Tree, enabling efficient O(log N) additions, removals, and modifications of monitored file descriptors.

Q4: What flag ensures that epoll automatically disables a file descriptor after delivering a single notification event?

Explanation: EPOLLONESHOT tells epoll to disable event reporting for that descriptor until re-armed with epoll_ctl(..., EPOLL_CTL_MOD, ...), preventing multithreaded race conditions on the same socket.

Q5: When should epoll_create1(EPOLL_CLOEXEC) be preferred over legacy epoll_create()?

Explanation: epoll_create1(EPOLL_CLOEXEC) avoids the race condition between creation and setting FD_CLOEXEC via fcntl in multithreaded programs.
