## 5.1 What the Programmer's Model Is

The programmer's model is the part of the CPU visible to software: registers, operating modes, privilege levels, stacks, exceptions and the memory map. It is the contract between hardware and firmware.

## 5.2 Operating Modes and Privilege

| State | Meaning |
|---|---|
| Thread mode | Normal application code |
| Handler mode | Running an exception or interrupt handler (always privileged) |
| Privileged | Full access to all resources |
| Unprivileged | Restricted access, enforced with the MPU |

Thread mode privilege is selected by `CONTROL[0]` (nPRIV). Handler mode is always privileged.

## 5.3 Two Stacks

- **MSP**: main stack pointer, used after reset and by handlers.
- **PSP**: process stack pointer, selected by `CONTROL[1]` (SPSEL) in thread mode, used by RTOS tasks.

```asm Switching a task to the PSP
    LDR  R0, =task_stack_top
    MSR  PSP, R0
    MOV  R0, #2
    MSR  CONTROL, R0       @ SPSEL=1: thread mode uses PSP
    ISB                    @ flush pipeline after CONTROL change
```

## 5.4 Execution State

Cortex-M executes **Thumb state only**. There is no ARM state. Branching to an address with bit 0 clear raises a fault: the lowest bit of function addresses must be 1.

## 5.5 Special Registers

| Register | Purpose |
|---|---|
| PRIMASK | Masks all configurable exceptions |
| FAULTMASK | Masks all except NMI |
| BASEPRI | Masks exceptions below a priority level (M3 and above) |
| CONTROL | Selects privilege and stack |

## 5.6 Memory Model

- Little-endian by default.
- Unaligned access supported for many loads and stores on M3 and above, not on M0.
- Strongly ordered, device and normal memory types and the need for barriers (`DMB`, `DSB`, `ISB`).
