## 26.1 What the MPU Does

The Memory Protection Unit divides the address space into regions and assigns each **access permissions** and **memory attributes**. It does not translate addresses (no virtual memory). On violation it raises a MemManage fault.

| Core | MPU regions |
|---|---|
| M0+ (optional) | 8 |
| M3, M4 (optional) | 8 |
| M7 | 8 or 16 |
| M33 | 8 or 16 per security state |

## 26.2 Uses

- Catch NULL pointer dereferences (region 0 at address 0, no access).
- Detect stack overflow with a no-access guard region.
- Mark code regions execute-only or read-only.
- Isolate RTOS tasks from each other and from the kernel.
- Set cache attributes for DMA buffers (M7).

## 26.3 Region Registers (Armv7-M)

| Register | Purpose |
|---|---|
| MPU_TYPE | Number of regions |
| MPU_CTRL | Enable, enable in handlers, default map |
| MPU_RNR | Region number to program |
| MPU_RBAR | Base address |
| MPU_RASR | Size, enable, access permissions, XN, TEX/C/B/S |

Region size is a power of two (32 bytes up to 4 GB) and the base must be aligned to its size.

## 26.4 Example: Guard Region at the Bottom of the Stack

```c Protect 32 bytes under the stack
void mpu_guard(uint32_t addr) {                 /* addr aligned to 32 */
    MPU->RNR  = 0;
    MPU->RBAR = addr;                           /* region 0 base */
    MPU->RASR = (4u << 1)                       /* SIZE = 4 -> 2^(4+1) = 32 bytes */
              | (0u << 24)                      /* AP = no access */
              | (1u << 28)                      /* XN */
              | 1u;                             /* enable region */
    MPU->CTRL = MPU_CTRL_ENABLE_Msk | MPU_CTRL_PRIVDEFENA_Msk;
    __DSB(); __ISB();
}
```

`PRIVDEFENA` keeps the default memory map for privileged code outside configured regions.

## 26.5 Access Permissions

| AP | Privileged | Unprivileged |
|---|---|---|
| 000 | No access | No access |
| 001 | Read/write | No access |
| 010 | Read/write | Read only |
| 011 | Read/write | Read/write |
| 101 | Read only | No access |
| 110 | Read only | Read only |

## 26.6 Handling the Fault

Enable `MEMFAULTENA`, then read `MMFSR` and `MMFAR` in the handler to find the offending address and instruction. A reasonable response is to kill the offending task and continue.
