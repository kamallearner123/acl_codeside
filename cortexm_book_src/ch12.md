## 12.1 SRAM Basics

SRAM is volatile, fast and used for variables, stack, heap and sometimes code. It has no wait states at core speed on most small MCUs. Contents are undefined at power-up.

## 12.2 What Lives in SRAM

| Section | Content | Initialised by |
|---|---|---|
| `.data` | Initialised globals | Startup code copies from flash |
| `.bss` | Zero-initialised globals | Startup code zeroes it |
| Heap | `malloc` area | Grows upward |
| Stack | Locals, return addresses | Grows downward |

```text Typical SRAM layout (low to high)
0x20000000  .data
            .bss
            heap  ---->
                   <---- stack
0x20020000  end of SRAM (initial SP)
```

## 12.3 Multiple RAM Blocks

Many chips have several RAMs with different properties.

| RAM | Example | Notes |
|---|---|---|
| Main SRAM | STM32F446 SRAM1/2 at 0x20000000 | DMA capable |
| CCM | STM32F4 0x10000000 | Core-only, no DMA, no bus contention |
| TCM | Cortex-M7 DTCM/ITCM | Zero-wait, deterministic |
| Backup SRAM | 4 KB retained on VBAT | Survives power loss with battery |

## 12.4 Bus Contention

CPU and DMA share the same SRAM through the bus matrix. If both access one block, one waits. Place DMA buffers in a different RAM block than hot CPU data to improve throughput.

## 12.5 Retention and Low Power

In deep sleep SRAM may be retained or lost depending on the mode. Check the reference manual for **which RAM is retained** in each low-power mode.

## 12.6 Checking Usage

```bash Report the size
arm-none-eabi-size firmware.elf
   text    data     bss     dec     hex filename
  24580     128    3120   27828    6cb4 firmware.elf
```

SRAM used by globals = `data + bss`. Add worst-case stack and heap to get the true footprint.
