## 21.1 What a Fault Is

A fault is an exception triggered by an error: bad memory access, illegal instruction, bus error. On M3 and above faults have separate handlers and status registers; on M0 only HardFault exists.

## 21.2 Fault Types

| Fault | Typical cause |
|---|---|
| MemManage | MPU violation, XN access |
| BusFault | Invalid address, bus error on a peripheral or memory |
| UsageFault | Undefined instruction, unaligned LDM, divide by zero, invalid EXC_RETURN or state |
| HardFault | Escalation of the above if the handler is disabled or fails, vector read errors, SVC problems |

## 21.3 Status Registers (SCB)

| Register | Address | Purpose |
|---|---|---|
| CFSR | 0xE000ED28 | MMFSR, BFSR, UFSR combined |
| HFSR | 0xE000ED2C | HardFault status |
| MMFAR | 0xE000ED34 | Faulting address, valid if MMARVALID |
| BFAR | 0xE000ED38 | Bus fault address, valid if BFARVALID |
| SHCSR | 0xE000ED24 | Enable fault handlers |

Common bits: `IACCVIOL`, `DACCVIOL` (MemManage), `PRECISERR`, `IMPRECISERR` (BusFault), `UNDEFINSTR`, `INVSTATE`, `INVPC`, `UNALIGNED`, `DIVBYZERO` (UsageFault).

## 21.4 Enabling Separate Handlers

```c Turn on the finer faults
SCB->SHCSR |= SCB_SHCSR_MEMFAULTENA_Msk | SCB_SHCSR_BUSFAULTENA_Msk | SCB_SHCSR_USGFAULTENA_Msk;
SCB->CCR   |= SCB_CCR_DIV_0_TRP_Msk | SCB_CCR_UNALIGN_TRP_Msk;   /* trap divide by zero and unaligned */
```

## 21.5 A HardFault Handler That Tells You Something

```c Extract the stacked frame
__attribute__((naked)) void HardFault_Handler(void) {
    __asm volatile("TST LR, #4\n ITE EQ\n MRSEQ R0, MSP\n MRSNE R0, PSP\n B hardfault_c\n");
}
void hardfault_c(uint32_t *s) {
    volatile uint32_t pc = s[6], lr = s[5];
    volatile uint32_t cfsr = SCB->CFSR, bfar = SCB->BFAR;
    (void)pc; (void)lr; (void)cfsr; (void)bfar;
    __BKPT(0);
}
```

Look up the stacked `pc` with `arm-none-eabi-addr2line -e firmware.elf 0x08001234` to get the source line.

## 21.6 Imprecise Bus Faults

A write to a bad address may be buffered. The fault happens after the instruction has retired, so the stacked PC does not point at the culprit. Disable the write buffer for debugging (`ACTLR.DISDEFWBUF`) to make it precise.

## 21.7 Typical Causes

| Symptom | Likely cause |
|---|---|
| Fault right after enabling interrupt | Missing handler or bad vector table |
| Fault using floating point | FPU not enabled in CPACR |
| Random fault after weeks | Stack overflow, heap corruption |
| Fault on peripheral access | Peripheral clock not enabled |
| INVSTATE | Branched to an address with bit 0 clear |
