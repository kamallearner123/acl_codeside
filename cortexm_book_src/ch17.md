## 17.1 What Is an Interrupt?

An interrupt is a hardware signal that makes the CPU pause its current code, run a handler (ISR), and then resume. It replaces wasteful polling and gives fast reaction to events.

## 17.2 What Happens on an Interrupt

```text Hardware sequence
1. Peripheral raises its IRQ line, NVIC marks it pending.
2. If priority is high enough, the core finishes the current instruction (long LDM/STM may be abandoned).
3. Core stacks R0-R3, R12, LR, PC, xPSR on the active stack.
4. Core fetches the handler address from the vector table.
5. LR = EXC_RETURN, IPSR = exception number, mode = Handler.
6. ISR runs.
7. ISR returns with BX LR (EXC_RETURN) -> hardware unstacks and resumes.
```

Entry takes 12 cycles on M3 and M4, then the ISR starts.

## 17.3 Writing an ISR

```c An ISR is an ordinary function
volatile uint32_t ticks;

void TIM3_IRQHandler(void) {
    if (TIM3->SR & TIM_SR_UIF) {
        TIM3->SR = ~TIM_SR_UIF;       /* clear flag first */
        ticks++;
    }
}
```

The name must match the vector table entry. The core's AAPCS-compatible stacking is why no special attribute is needed on Cortex-M.

## 17.4 Rules for Good ISRs

1. Keep them short; set a flag or push to a queue.
2. Clear the peripheral flag, or the interrupt re-triggers forever.
3. Declare shared variables `volatile` and protect multi-word data.
4. Never block, delay or call non-reentrant library functions such as `printf`.
5. Choose priorities deliberately.

## 17.5 Interrupt Latency Factors

| Factor | Effect |
|---|---|
| Core entry | 12 cycles |
| Higher-priority ISR running | Waits |
| Interrupts masked | Waits until unmasked |
| Slow flash with wait states | Adds cycles to fetch the handler |
| Multi-cycle instruction in progress | Up to a few cycles |

> [tip] Measure it | Toggle a GPIO at the first line of the ISR and trigger from an external edge; the logic analyzer gives true latency.

## 17.6 Sleep and Wake-up

`WFI` stops the core until any enabled interrupt. `SLEEPONEXIT` returns to sleep after an ISR ends, useful for fully interrupt-driven low-power designs.
