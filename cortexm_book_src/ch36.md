## 36.1 The Pipeline from C to Machine Code

```text Tool chain
main.c --preprocessor--> main.i --compiler--> main.s --assembler--> main.o
main.o + startup.o + libs --linker (linker script)--> firmware.elf
firmware.elf --objcopy--> firmware.bin / firmware.hex --> flash
```

## 36.2 Look at the Assembly

```c Source
int sum(int a, int b) { return a + b; }
int counter;
void tick(void) { counter++; }
```

```asm Compiled with -O2 for Cortex-M4
sum:
    ADD  R0, R0, R1       @ args in R0, R1; result in R0
    BX   LR
tick:
    LDR  R3, =counter     @ literal pool: address of counter
    LDR  R2, [R3]
    ADDS R2, R2, #1
    STR  R2, [R3]
    BX   LR
```

## 36.3 Optimisation Levels

| Flag | Effect | Use |
|---|---|---|
| `-O0` | No optimisation, easy debugging | Early development |
| `-Og` | Debug-friendly optimisation | Daily debugging |
| `-O1`, `-O2` | Balanced speed | Production |
| `-O3` | Aggressive, bigger | Hot paths |
| `-Os` | Smallest size | Flash-limited parts |
| `-flto` | Link-time optimisation across files | Final builds |

Optimisation exposes bugs such as missing `volatile`, data races and undefined behaviour.

## 36.4 What the Compiler Assumes

- Variables not marked `volatile` can be cached in registers.
- Signed overflow is undefined; the compiler may delete checks that rely on it.
- Aliasing rules allow reordering of accesses through different pointer types.
- Dead stores and empty loops may be removed.

```c A classic bug
int ready;                       /* missing volatile */
void ISR(void) { ready = 1; }
void wait(void) { while (!ready) { } }   /* may compile to an infinite loop at -O2 */
```

## 36.5 Inspecting Binaries

```bash Tools
arm-none-eabi-size firmware.elf              # text, data, bss
arm-none-eabi-objdump -d -S firmware.elf     # disassembly with source
arm-none-eabi-nm --size-sort -S firmware.elf # biggest symbols
arm-none-eabi-readelf -S firmware.elf        # sections and addresses
arm-none-eabi-addr2line -e firmware.elf 0x080012a4
```

## 36.6 Calling Conventions Revisited

Arguments in R0-R3, extra arguments on the stack, return in R0 (R0:R1 for 64-bit), R4-R11 callee-saved. Structs larger than 4 bytes are passed by reference or copied to the stack. This is the AAPCS from chapter 7.

## 36.7 From Machine Code to the Pipeline

The assembler encodes `ADD R0, R0, R1` as the 16-bit Thumb word `0x4408`; the CPU fetches it from flash through the I-Code bus, decodes it, reads two registers, adds them, and writes R0 back, all in one cycle in steady state. Every concept in this book, from the memory map to the interrupt controller, exists to make that process fast, deterministic and debuggable.
