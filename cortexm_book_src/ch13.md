## 13.1 What the Stack Is

The stack is a region of memory used for function call frames: return addresses, saved registers, local variables and exception frames. The CPU supports it with the SP register and `PUSH` and `POP`.

## 13.2 Full Descending Stack

Cortex-M uses a **full descending** stack: SP points at the last used word, `PUSH` decrements first, and the stack grows from high addresses to low.

```text Stack growth
high  0x20020000  <- initial SP (top)
      [ saved R4  ]
      [ saved LR  ]  <- SP after PUSH {R4, LR}
low
```

## 13.3 A Function Frame

```asm Prologue and epilogue
func:
    PUSH {R4, R5, LR}       @ save callee-saved regs and return address
    SUB  SP, SP, #16        @ room for locals
    ...
    ADD  SP, SP, #16
    POP  {R4, R5, PC}       @ restore and return
```

## 13.4 Exception Stacking

On an exception the core automatically pushes eight words: R0-R3, R12, LR, PC and xPSR. This **exception frame** is why an ISR can be an ordinary C function. On M4F with FPU lazy stacking it may also reserve space for S0-S15 and FPSCR.

| Offset | Word |
|---|---|
| SP+0 | R0 |
| SP+4 | R1 |
| SP+8 | R2 |
| SP+12 | R3 |
| SP+16 | R12 |
| SP+20 | LR |
| SP+24 | Return address (PC) |
| SP+28 | xPSR |

## 13.5 Sizing the Stack

Worst case = deepest call chain locals + saved registers + largest ISR nesting frames. Methods:

- `-fstack-usage` for per-function use, then trace the call graph.
- **Stack painting**: fill with 0xA5A5A5A5 at boot, later find the high-water mark.
- A guard region with the MPU or a canary word at the bottom.

## 13.6 Stack Overflow Symptoms

Silent corruption of globals, random HardFaults, or strange behaviour that changes with compiler options. Use the MPU or flip-link style layout so overflow faults immediately.

> [tip] Beware big locals | `char buf[1024]` inside a function consumes 1 KB of stack each call. Make large buffers static or place them in a dedicated section.
