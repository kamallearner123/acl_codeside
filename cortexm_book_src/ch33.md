## 33.1 What CMSIS Is

The **Cortex Microcontroller Software Interface Standard** is Arm's vendor-independent software layer. It defines common names and functions so code that touches the core is portable across vendors.

## 33.2 CMSIS Components

| Component | Content |
|---|---|
| CMSIS-Core | Core register access, NVIC, SysTick, intrinsics, startup structure |
| CMSIS-DSP | Optimised maths and filters (FFT, FIR, matrix) |
| CMSIS-NN | Neural-network kernels |
| CMSIS-RTOS2 | RTOS API (FreeRTOS, RTX, Zephyr wrappers) |
| CMSIS-Driver | Generic peripheral driver APIs (UART, SPI, I2C) |
| CMSIS-Pack | Device description and software packaging |
| CMSIS-SVD | XML description of all peripheral registers |

## 33.3 CMSIS-Core in Practice

```c What you get from the device header
#include "stm32f4xx.h"           /* includes core_cm4.h */

SystemCoreClockUpdate();
NVIC_SetPriority(TIM2_IRQn, 3);
NVIC_EnableIRQ(TIM2_IRQn);
__disable_irq();                 /* CPSID i */
__WFI();                         /* WFI */
__NOP();
uint32_t p = __get_PRIMASK();
SysTick_Config(SystemCoreClock / 1000);
```

CMSIS wraps special instructions as **intrinsics** so you need no inline assembly.

## 33.4 Device Header Conventions

Vendors provide a header with peripherals as structs:

```c Naming
TIM2->PSC = 83;
TIM2->ARR = 999;
TIM2->CR1 |= TIM_CR1_CEN;          /* bit mask macros end in _Msk and _Pos */
USART2->BRR = 0x1D4C;
```

`_Pos` is the bit position and `_Msk` the mask: `(x << X_Pos) & X_Msk`.

## 33.5 CMSIS-DSP Example

```c Using the FFT
#include "arm_math.h"
arm_rfft_fast_instance_f32 S;
arm_rfft_fast_init_f32(&S, 256);
arm_rfft_fast_f32(&S, input, output, 0);
arm_cmplx_mag_f32(output, mags, 128);
```

Kernels use SIMD and the FPU on M4 and M7 for large speedups.

## 33.6 CMSIS vs HAL vs LL

| Layer | Level | Portability |
|---|---|---|
| CMSIS-Core | Core, NVIC, SysTick | All Cortex-M |
| Vendor device header | Peripheral registers | One vendor family |
| LL drivers | Thin register helpers | One vendor |
| HAL | High-level APIs | One vendor family |

A good codebase keeps hardware access behind an interface so only a small BSP depends on the vendor.
