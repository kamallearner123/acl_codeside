## 3.1 Design Goals of the Cortex-M Family

Every Cortex-M core shares the same principles: Thumb-only instructions, a nested vectored interrupt controller, a standard memory map, low power and a common debug interface. Code and skills transfer between cores and vendors.

## 3.2 Family Overview

| Core | Architecture | Pipeline | Typical features |
|---|---|---|---|
| M0 / M0+ | Armv6-M | 3 / 2 stage | Smallest, lowest power, 32 interrupts max |
| M3 | Armv7-M | 3 stage | Full Thumb-2, hardware divide, bit-banding |
| M4 | Armv7E-M | 3 stage | M3 plus DSP instructions and optional FPU |
| M7 | Armv7E-M | 6 stage superscalar | Caches, TCM, double-precision FPU option |
| M23 | Armv8-M Base | 2 stage | M0+ plus TrustZone |
| M33 | Armv8-M Main | 3 stage | M4-class plus TrustZone |

## 3.3 The Shared Programmer's View

- 16 registers (R0-R15) and a program status register.
- Two stack pointers (MSP and PSP) on most cores.
- Thread mode and Handler mode, privileged and unprivileged levels.
- One fixed memory map with Code, SRAM, Peripheral and System regions.
- A built-in SysTick timer and NVIC.

## 3.4 Choosing a Core

| Need | Choice |
|---|---|
| Lowest power, simple control | M0+ |
| General embedded, integer maths | M3 |
| Sensor fusion, motor control, audio | M4F |
| High-performance, graphics, DSP | M7 |
| Secure IoT (TrustZone) | M33 |

> [tip] Software portability | Because the architecture is shared, a bare-metal driver written for M3 usually runs on M4 with a rebuild. Differences appear mostly in instructions available and optional units.
