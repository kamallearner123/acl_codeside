## 30.1 Why Debug Hardware Is in the Core

A Cortex-M debug unit lets a host halt the CPU, read and write memory, set breakpoints and trace execution **without running any code on the target**. It is part of the CoreSight architecture.

## 30.2 CoreSight Components

| Block | Role |
|---|---|
| DAP (Debug Access Port) | Gateway from the debug probe to the system |
| DP / AP | Debug port and access ports (AHB-AP for memory) |
| FPB | Flash Patch and Breakpoint unit: hardware breakpoints (2-8) |
| DWT | Data Watchpoint and Trace: watchpoints, cycle counter, PC sampling |
| ITM | Instrumentation Trace Macrocell: printf over SWO |
| ETM | Embedded Trace Macrocell: full instruction trace (M3 and above, optional) |
| TPIU | Trace port interface unit, sends trace off chip |

## 30.3 Hardware Breakpoints and Watchpoints

- FPB gives a limited number of **hardware** breakpoints (typically 6 on M4). More require software breakpoints that rewrite flash.
- DWT watchpoints trigger on a read or write of an address: ideal for finding who corrupts a variable.

## 30.4 Debug Halting

`DHCSR` (0xE000EDF0) controls halting and single stepping. Setting `C_DEBUGEN` and `C_HALT` stops the core. `DEMCR` (0xE000EDFC) enables trace and vector-catch (halt on reset or fault).

```c Enable the DWT cycle counter
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
uint32_t t0 = DWT->CYCCNT;
work();
uint32_t cycles = DWT->CYCCNT - t0;
```

## 30.5 printf over SWO

```c ITM_SendChar via SWO
int _write(int fd, char *ptr, int len) {
    for (int i = 0; i < len; i++) ITM_SendChar(ptr[i]);
    return len;
}
```

The host reads SWO through the probe at no UART cost; the debugger shows it in a console.

## 30.6 Debug vs Low Power

In sleep modes the debug clocks may stop and the probe disconnects. Vendors provide a setting (such as `DBGMCU_CR` on STM32) to keep clocks running during sleep while debugging.

## 30.7 Production Considerations

Disable or lock debug access in released products (RDP, debug authentication) to protect firmware and reduce attack surface.
