## 14.1 What the Heap Is

The heap is memory managed at run time with `malloc` and `free`. Unlike the stack, blocks can live beyond the function that created them. On bare-metal there is no OS: the C library implements the heap on top of `_sbrk()`.

## 14.2 How newlib Gets Memory

```c _sbrk: extend the heap
extern char _end;                 /* symbol from the linker script */
static char *heap_end = &_end;

void *_sbrk(int incr) {
    char *prev = heap_end;
    if (heap_end + incr > (char *)&_estack - _Min_Stack_Size) {
        errno = ENOMEM;
        return (void *)-1;
    }
    heap_end += incr;
    return prev;
}
```

The heap starts after `.bss` and must stop before the reserved stack area.

## 14.3 Why Embedded Systems Avoid the Heap

| Problem | Consequence |
|---|---|
| Fragmentation | Allocation fails despite enough total free memory |
| Non-determinism | `malloc` time varies |
| Leaks | Slow death over weeks of uptime |
| Hard to test | Failures depend on allocation history |
| Safety standards | MISRA and many certifications forbid dynamic allocation |

## 14.4 Alternatives

| Alternative | Idea |
|---|---|
| Static allocation | Fixed global arrays sized at build time |
| Memory pools | Fixed-size blocks, O(1) alloc and free, no fragmentation |
| Arena allocator | Allocate forward, free all at once |
| RTOS heaps | FreeRTOS `heap_4`, deterministic variants |

```c A simple fixed-block pool
#define BLOCKS 16
static uint8_t pool[BLOCKS][64];
static uint8_t used[BLOCKS];

void *pool_alloc(void) {
    for (int i = 0; i < BLOCKS; i++)
        if (!used[i]) { used[i] = 1; return pool[i]; }
    return NULL;                         /* always check */
}
void pool_free(void *p) {
    used[((uint8_t (*)[64])p - pool)] = 0;
}
```

## 14.5 If You Must Use malloc

- Allocate only during initialisation and never free.
- Check every return value for NULL.
- Protect with a critical section if called from more than one context (newlib needs `__malloc_lock`).
- Monitor `mallinfo()` during testing.
