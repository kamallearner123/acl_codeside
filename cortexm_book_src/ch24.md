## 24.1 What the Linker Script Does

The compiler produces object files with **sections** (`.text`, `.data`, `.bss`). The linker script tells the linker **where in the memory map** each section goes, and creates symbols the startup code needs.

## 24.2 The MEMORY Block

```ld Describe the chip
MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
}
```

## 24.3 The SECTIONS Block

```ld Place the sections
ENTRY(Reset_Handler)
_estack = ORIGIN(RAM) + LENGTH(RAM);

SECTIONS
{
  .isr_vector : { KEEP(*(.isr_vector)) } > FLASH
  .text       : { *(.text*) *(.rodata*) . = ALIGN(4); _etext = .; } > FLASH

  _sidata = LOADADDR(.data);
  .data : { _sdata = .; *(.data*) . = ALIGN(4); _edata = .; } > RAM AT > FLASH

  .bss  : { _sbss = .; *(.bss*) *(COMMON) . = ALIGN(4); _ebss = .; } > RAM

  ._user_heap_stack : {
    . = ALIGN(8);
    _end = .;
    . = . + 0x400;      /* minimum heap */
    . = . + 0x800;      /* minimum stack */
  } > RAM
}
```

## 24.4 Load Address vs Run Address

`.data` has two addresses. It is **stored** in flash (`AT > FLASH`) but **runs** in RAM. The startup code copies from `_sidata` to `_sdata`. Mixing these up is the classic reason globals start with garbage.

## 24.5 Symbols Shared with C

```c Using linker symbols
extern uint32_t _sdata, _edata, _sidata;
size_t data_size = (size_t)&_edata - (size_t)&_sdata;   /* use the address, not the value */
```

Linker symbols have **addresses** and no storage; always take `&symbol`.

## 24.6 Useful Techniques

- Put code in RAM: `__attribute__((section(".ramfunc")))` with a matching section and copy.
- Put a version string at a fixed flash address for the bootloader to read.
- Reserve the last flash sector for settings with a separate memory region.
- Check the map file (`-Wl,-Map=firmware.map`) for sizes and discarded sections.
- `-Wl,--gc-sections` with `-ffunction-sections` removes unused code.
