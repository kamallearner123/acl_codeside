## 11.1 What Flash Holds

Flash is non-volatile memory that stores the vector table, code and read-only data (`.text`, `.rodata`) and the initial values of variables (`.data` load image). It survives power loss.

## 11.2 How Flash Works

| Property | Behaviour |
|---|---|
| Erase | Sets bits to 1, done per **sector** or page |
| Program | Clears bits to 0, per word or half-word |
| Endurance | 10,000 to 100,000 erase cycles |
| Read | Fast, but slower than the CPU clock at high speed |

You cannot write 1 over a 0 without erasing the whole sector first.

## 11.3 Wait States and Accelerators

At 180 MHz the STM32F4 flash needs 5 wait states. To hide that, ST adds an **ART accelerator**: a prefetch buffer plus instruction and data caches. Always set the flash latency to match the clock **before** increasing frequency.

| Core clock | Wait states (3.3 V, F446) |
|---|---|
| up to 30 MHz | 0 |
| up to 60 MHz | 1 |
| up to 90 MHz | 2 |
| up to 180 MHz | 5 to 6 |

## 11.4 Sectors on STM32F446

| Sector | Size | Address |
|---|---|---|
| 0 to 3 | 16 KB each | 0x08000000 |
| 4 | 64 KB | 0x08010000 |
| 5 to 7 | 128 KB each | 0x08020000 |

Uneven sectors mean a bootloader usually uses the small ones and the application the large ones.

## 11.5 Programming Flash from Code

```c Unlock, erase, program (HAL)
HAL_FLASH_Unlock();
FLASH_EraseInitTypeDef e = { .TypeErase = FLASH_TYPEERASE_SECTORS,
                             .Sector = FLASH_SECTOR_7, .NbSectors = 1,
                             .VoltageRange = FLASH_VOLTAGE_RANGE_3 };
uint32_t err;
HAL_FLASHEx_Erase(&e, &err);
HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD, 0x08060000, 0xDEADBEEF);
HAL_FLASH_Lock();
```

> [warn] Code stalls during erase | On many chips the CPU stalls while flash erases if it executes from the same bank. Time-critical code must run from RAM or another bank.

## 11.6 Protection and Option Bytes

Read protection (RDP) levels, write protection per sector and boot configuration live in **option bytes**. RDP level 2 is irreversible.
